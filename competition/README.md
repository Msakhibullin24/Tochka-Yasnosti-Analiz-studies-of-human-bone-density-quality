# Osseo AI — конкурсный сервис DXA

Сервис принимает DICOM позвоночника и бедра, вычисляет качество и типы нарушений,
выдаёт CSV/XLSX, визуальные серии и DICOM SR. Основной React-интерфейс находится в `../src/CompetitionWorkspace.tsx`.
CLI, API и валидация используют общий модуль итогового решения `dxaqc/decision.py`.
План завершения проекта: [этапы, метрики и условия сдачи](../docs/DXA_QC_END_TO_END_PLAN_2026_09_24_RU.md).
Актуальная сверка с ТЗ и разъяснениями: [статус требований на 25.09.2026](../docs/SOURCE_MATERIALS_CONSISTENCY_AUDIT_2026_09_25_RU.md).
Текущий разбор точности и приоритеты доработки: [метрики и ошибки на 25.09.2026](../docs/DXA_QC_ACCURACY_NEXT_STEPS_2026_09_25_RU.md).
Метрики основного QC: [`../docs/DXA_QC_PROGRESS_2026_09_24_RU.md`](../docs/DXA_QC_PROGRESS_2026_09_24_RU.md).
Независимые модели версии 1.9.3: [`docs/INDEPENDENT_MODELS.md`](docs/INDEPENDENT_MODELS.md).
Текущая рабочая сборка **1.11.5**, решение **v5**: бинарный сигнал больше не превращается
в класс 0 из-за отсутствия типа. Актуальные числа и ограничения —
[метрики рабочей сборки](../docs/PROJECT_METRICS_2026_09_29_RU.md).
[Описание исследования и динамики](../docs/AUTOMATIC_STUDY_DESCRIPTION_RU.md) собирается
из результатов модели и сохранённой экспертной версии; сравнение двух DICOM
требует подтверждения пациента и дат по документам.
[Паспорт 1.11.0](../docs/CURRENT_RELEASE.json) и
[доработки по ТЗ](../docs/TZ_ALIGNMENT_2026_09_26_RU.md) сохранены как история.
Исторические отчёты 1.9.x остаются архивом экспериментов.
Внешние AP DXA данные, benchmark масок и приоритет функций: [`../docs/EXTERNAL_DXA_DATASETS_AND_FEATURES_2026_09_24_RU.md`](../docs/EXTERNAL_DXA_DATASETS_AND_FEATURES_2026_09_24_RU.md).

## Запуск

Из любой рабочей папки: `./run.sh build`, `./run.sh serve 8090` (если текущая папка — `competition`).
Скрипт сам выбирает корень репозитория как build context. Прямой аналог из корня:
`docker build -f competition/Dockerfile -t osseo-dxaqc:1.11.5 .`.
Офлайн-инференс: `./run.sh batch /absolute/input /absolute/output`.

Требования: Docker; для сборки — сеть, для работы — нет. CPU-инференс, GPU не требуется.
Ориентировочная конфигурация: 4 ядра / 4 ГБ RAM; место под образ, исходные пакеты и результаты.
Рекомендуется 8 ядер / 8 ГБ и запас диска по объёму архива. Ограничения размеров:
20 ГБ распаковки суммарно по вложенным ZIP, 200 000 членов архивов, вложенность ограничена.
Фактическое потребление ресурсов на целевом стенде нужно замерить при приёмке.

Для локальной разработки и тестов установите окружения командой `make setup` из корня.
Python-окружения создаются и синхронизируются через `uv`, frontend — через `pnpm`.

## Вход и выход

Вход CLI: папка, DICOM-файл или ZIP с исследованиями. Веб-загрузка: один ZIP либо несколько DICOM.
Неподдерживаемые сопроводительные форматы пропускаются, ошибки чтения DICOM/распаковки отражаются
в отчёте. Пустой вход имеет строку `NO_DICOM_IMAGES`, отменённые файлы — `CANCELLED`.

Первые восемь колонок неизменны: `path_to_study`, `study_uid`, `image_uid`, `anatomical_region`,
`quality_class`, `violation_type`, `processing_status`, `time_of_processing`.
`quality_class=0` — нарушений не выявлено, `1` — нарушение; при `Failure` класс,
вероятность и тип остаются пустыми. Отказ обработки не считается нарушением качества.
`quality_prob` — score нарушения [0;1], калибровка вероятностей не подтверждена.
CLI по умолчанию пишет в `results.csv/xlsx` восемь полей плюс `quality_prob`.
`--extended-columns` включает подробный CSV/XLSX; `--strict-columns` сохраняется как явный выбор строгого режима.
В обоих режимах `results_extended.csv` содержит диагностику, `submission.csv/xlsx` — таблицу для сдачи,
`submission_validation.json` — строгую проверку V2. В API `results.csv/xlsx` остаются расширенными.
Положительная строка без типа не проходит строгую проверку. В решении v5 бинарный сигнал сохраняется как `quality_class=1`, даже если тип не установлен. Выдумывать официальный тип или превращать этот сигнал в норму нельзя; незавершённая типизация явно отклоняется строгим валидатором. Наличие файла для сдачи само по себе не означает его готовность.

Рабочая сборка 1.11.5 включает профиль `tz-delivery-1.11.5` и вторичный обученный пересмотр
таких ответов. Он может определить тип или отменить тревогу; эффект на чувствительность
и F1 описан в основном README. Проекция позвоночника проверяется перед QC.
При низкой уверенности в стороне бедра проверка допускается только если
выбор модели совпал с однозначной DICOM-меткой `ImageLaterality`/`Laterality`;
источник записывается в `laterality_basis` расширенного отчёта.
Путь `path_to_study` определяется по ближайшей от корня папке, содержащей
только один известный `StudyInstanceUID`; копии в разных ветках сохраняют
свои пути. Для плоского набора с несколькими исследованиями используется путь файла.
Исходная ROI с явным назначением `ROI_SCAN_COVERAGE` и известным масштабом участвует
в проверке отступов; для ROI шейки правила охвата не применяются.

CLI: `--acceptance report` проверяет только выполнение обработки,
`--acceptance submission` требует валидной таблицы и отсутствия Failure,
`--acceptance complete` также требует полного покрытия обязательных проверок.
Отклонение приёмки возвращает код 3 и сохраняет результаты. `run.sh batch`
использует `submission`. Самостоятельный запуск Python с поставляемым профилем:

```sh
DXAQC_WORKFLOW_PROFILE="$PWD/competition/models/workflow_1_11_5/profile.json" \
PYTHONPATH=competition competition/.venv/bin/python -m dxaqc.cli \
  --input /absolute/input.zip --output /absolute/new-output --acceptance complete
```

Расширенный отчёт включает сторону, внутренние коды, score и пороги критериев, измерения,
масштаб X/Y и его источник, причину решения, ошибки, стабильный внутри пакета `row_id` и путь визуализации.
Для случаев `binary_only_review` команда `make review-release-errors` создаёт локальную очередь и папку `blind/`
с уникальными изображениями и двумя пустыми бланками для независимой экспертной проверки. Связь изображений
с DICOM-путями и исходными метками хранится отдельно от `blind/`; заполненные бланки сверяет
`competition/reconcile_reviews.py`. Этот этап не меняет предсказания или обучающие метки автоматически.
С `RELEASE_REVIEW_INCLUDE_LABEL_CONFLICTS=1` та же команда добавляет случаи, где итоговый класс
противоречит полному набору критерийных меток. Архив `blind-review-packet.zip` содержит только
изображения и пустые бланки; сводка с исходными метками остаётся вне архива.
Для набора организатора масштаб фиксирован: X=0,6 мм, Y=1,05 мм; в коде и DICOM
`PixelSpacing` порядок компонентов — Y, затем X. Если физический масштаб неизвестен,
отчёт указывает источник fallback; такую оценку нельзя считать измеренной в масштабе организатора.
Новые экспертные версии принимают только официальные критерии области. Металл
остаётся причиной дополнительной проверки, а не отдельным официальным типом.
Историческое сопоставление `hip_metal_implant` сохранено только для чтения прежних
версий; новая версия требует выбора официального типа с подтверждением специалиста.

Официальные области: «Поясничный отдел позвоночника», «Проксимальный отдел бедра».
Несколько типов разделяются `;`. Машинные файлы не изменяются после проверки специалистом.

`Failure` — технический отказ, не медицинское заключение. В новых отчётах
`quality_class`, `quality_prob` и `violation_type` пустые. Старые отчёты сохраняются
без изменения; исторический класс 1 у Failure валидатор отмечает как устаревшее
кодирование, не как предсказание качества. Контракт отказных строк не задан куратором.

`requirements.json` отражает незавершённые обязательные проверки отдельно от формата
таблицы. `timing.json` включает подготовку, запись таблиц и ZIP; валидатор принимает
`--timing /path/timing.json` для консервативной проверки лимита 180 секунд.

Кэш учитывает нормализованные пиксели и физический масштаб. Производные серии создаются
для каждого исходного изображения, включая точные пиксельные копии с другим SOPInstanceUID.

## API

| Маршрут | Назначение |
|---|---|
| `GET /health` | Жив ли HTTP-сервис |
| `GET /api/v1/ready` | Загрузка модели/энкодера, запись в рабочую папку, свободное место |
| `GET /api/v1/catalog` | Имена и допустимые типы критериев |
| `POST /api/v1/batch?wait=true` | Multipart `files`: создать пакет и при необходимости дождаться окончания |
| `POST /api/v1/batch/path` | JSON `input_path` внутри разрешённого корня |
| `GET /api/v1/jobs?limit=50&offset=0` | Сохранённая история, постранично |
| `GET /api/v1/jobs/{id}` | Статус и прогресс |
| `POST /api/v1/jobs/{id}/cancel` | Отмена на границе файлов; готовые строки сохраняются |
| `GET /api/v1/jobs/{id}/rows` | Машинные строки |
| `GET /api/v1/jobs/{id}/{artifact}` | `results.csv/xlsx`, `submission.csv/xlsx`, `requirements.json`, `timing.json`, `additional_series.zip`, `summary.json` |
| `GET /api/v1/jobs/{id}/images/{row_id}` | Геометрия и параметры исходного изображения |
| `GET /api/v1/jobs/{id}/images/{row_id}/original.png` | Нормализованный preview без наложений |
| `GET/POST /api/v1/jobs/{id}/images/{row_id}/reviews` | История / новая экспертная версия |
| `GET /api/v1/jobs/{id}/reviewed.csv` | Последние экспертные версии, кроме черновиков |
| `GET /api/v1/jobs/{id}/reviews.json` | Все экспертные версии вместе с исходным ответом ИИ |
| `GET /api/v1/jobs/{id}/report.html` | Отчёт для просмотра и печати |
| `POST /api/v1/analyze` | Один DICOM → JSON |
| `POST /api/v1/compare` | Сравнение двух визитов; экспериментальные допуски |

Схемы запросов — в `/docs`. Редакция содержит `expected_revision`, автора, статус, класс,
нарушения, комментарий и геометрию. Координаты нормализованы по `(width-1,height-1)` исходного preview.
Устаревшая версия → HTTP 409. Для нового изображения `expected_revision=0`.
Статусы редакции: `draft`, `confirmed`, `not_evaluable`. Неоценимость требует причины.
Автор — введённое имя в локальном однопользовательском режиме, не аутентифицированная электронная подпись.

## Модель, данные и ограничения

Замороженный ResNet18 + компактные геометрические признаки; ансамбли RF/LogReg и итоговые правила.
Левое бедро зеркалится для анализа, точки возвращаются в координаты исходного preview.
Анизотропная геометрия измеряется на физически изотропной сетке; CNN получает прежнее изображение.
Неизвестный масштаб помечается допущением, точность эвристических ориентиров на реальной анатомии
клинически не подтверждена. ROI-редактор не является доказанным автоматическим контролем разметки.

Рабочий bundle не заменён при реорганизации продукта. Историческая CV (3 повтора):
spine AUC 0.814/F1 0.657, hip 0.776/0.519, overall 0.793/0.583.
Новый протокол отдельно сохраняется в `reports/decision_v2_validation.json` и OOF CSV;
его нельзя смешивать с историческими цифрами. Порог каждого типа теперь выбирается во внутренней CV,
после чего применяются те же правила, что в инференсе. Роутер оценивается отдельно.
На 100 исследованиях доверительные интервалы широкие; эксперта для дополнительной разметки пока нет.

## Проверки

`./run.sh test` — тесты в контейнере без сети. Для локальной проверки из корня:
`DXAQC_DEBUG_SET='/path/Для теста' competition/.venv/bin/python -m pytest -q competition/tests`.
`make verify` также проверяет React и исследовательский backend.

Основные ошибки: `NO_PIXEL_DATA`, `PIXEL_DECODE_ERROR`, `EMPTY_IMAGE`, `UNSUPPORTED_IMAGE_SIZE`,
`ARCHIVE_INPUT_ERROR`, `ARCHIVE_MEMBER_ERROR`, `UNSAFE_ARCHIVE_MEMBER`, `BATCH_INPUT_ERROR`.
При перезапуске прерванный пакет помечается `failed` с доступным CSV; повтор требует новой загрузки.
История и подтверждённые правки сохраняются. С 1.9 исходные DICOM/ZIP сохраняются в архиве задания для скачивания и повторного анализа; временная папка загрузки удаляется. Это локальное хранилище, не PACS.
