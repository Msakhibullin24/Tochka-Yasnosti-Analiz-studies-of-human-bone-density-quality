# Руководство по развёртыванию

## Требования
Linux/UNIX, Docker 24+. GPU и доступ в интернет на этапе работы **не нужны**. Интернет нужен только при
сборке образа (pip-пакеты); для закрытого контура образ переносится файлом:

```sh
./run.sh build
docker save osseo-dxaqc:1.0.0 | gzip > osseo-dxaqc-1.0.0.tar.gz     # на машине с сетью
docker load < osseo-dxaqc-1.0.0.tar.gz                              # в закрытом контуре
```

## Режимы
* **Пакетный (для финального тестирования):** `./run.sh batch /mnt/test /mnt/out` — контейнер стартует с
  `--network none`, входная папка монтируется только на чтение, процесс работает от непривилегированного пользователя.
* **Сервис:** `./run.sh serve 8000` — API и веб-интерфейс, порт публикуется только на `127.0.0.1`.
  Для доступа из сети ЛПУ поставьте перед ним reverse-proxy с TLS и аутентификацией.

## Переменные окружения
| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DXAQC_DATA_DIR` | `/work` | рабочая папка заданий API |
| `DXAQC_INPUT_ROOT` | `/data` | единственный корень, разрешённый для `POST /api/v1/batch/path` |
| `DXAQC_MAX_UPLOAD_MB` | `8192` | лимит загрузки |
| `OMP_NUM_THREADS` | `8` | потоки CPU |

## Производительность и ресурсы
≈0.1 с на изображение, порядка 1 ГБ RAM. Стенд 44 CPU / 256 ГБ / H200 используется на единицы процентов;
1000 исследований обрабатываются за минуты. Задания API выполняются строго последовательно одним
рабочим потоком — это гарантирует воспроизводимость и отсутствие конкуренции за CPU.

## Контроль целостности
При сборке проверяется sha256 весов энкодера и загружается модель; образ с битой моделью не соберётся.
`GET /health` используется в `HEALTHCHECK`.

## Безопасность
Нет исходящих соединений; распаковка архивов защищена от path traversal, симлинков и zip-бомб; пути из API
ограничены `DXAQC_INPUT_ROOT`; персональные теги DICOM не читаются и не попадают в отчёты и логи.
