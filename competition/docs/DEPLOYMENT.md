# Развёртывание и сохранность данных

## Контейнер

Из корня репозитория:

```sh
./competition/run.sh build
DXAQC_DATA=/absolute/osseo-data ./competition/run.sh serve 8090
```

Открыть http://127.0.0.1:8090. React и API обслуживаются одним процессом сервиса.
Сборка использует Node-stage и Python-stage. Для работы GPU и интернет не нужны.
`./competition/run.sh batch /input.zip /output` принудительно использует `--network none`.

Сервис рассчитан на один worker-процесс на каталог данных: файловая блокировка не даёт
двум экземплярам независимо восстанавливать/обрабатывать одну очередь. Не увеличивать
`uvicorn --workers` без изменения модели владения очередью. HTTP-ожидание `wait=true` не блокирует event loop.

## Данные

В `DXAQC_DATA/dxaqc-jobs/`: `jobs.sqlite3`, блокировка worker и папки заданий.
Структура задания: `out/results.*`, `out/images/` (preview и геометрия), `out/additional_series/` и ZIP.
SQL хранит историю заданий и неизменяемые экспертные редакции. Автоудаления последних N заданий нет.
С 1.9 исходные DICOM/ZIP сохраняются в source.zip задания; удаляется только временная папка загрузки. Предыдущие задания могут содержать только результаты и preview.
Объём диска нужно контролировать. Не удалять отдельные строки SQLite вручную.

Завершённые результаты переживают перезапуск. Прерванные задания получают `failed` и отчёт с причиной;
для повторной обработки загрузить исходный пакет заново. Новая схема базы имеет `user_version=1`;
неизвестная более новая версия отклоняется, а не мигрируется вслепую.

## Резервное копирование

Остановить сервис. Для контейнерной установки выполнять backup/restore в контейнере,
чтобы пути в базе оставались путями runtime (`/work`), а не путями хостовой машины:

```sh
mkdir -p /absolute/backups /absolute/restored
docker run --rm --network none --user "$(id -u):$(id -g)" \
  -v /absolute/osseo-data:/work -v /absolute/backups:/backup \
  osseo-dxaqc:1.9.1 python -m dxaqc.maintenance backup \
  --root /work/dxaqc-jobs --archive /backup/osseo.zip
docker run --rm --network none --user "$(id -u):$(id -g)" \
  -v /absolute/restored:/work -v /absolute/backups:/backup:ro \
  osseo-dxaqc:1.9.1 python -m dxaqc.maintenance restore \
  --root /work/dxaqc-jobs --archive /backup/osseo.zip
```

Для установки непосредственно в Python использовать тот же модуль через
`PYTHONPATH=competition backend/.venv/bin/python -m dxaqc.maintenance`; корень должен совпадать
с путём данных в среде, где будет запущен сервис.

Backup блокирует работающий экземпляр через его lease. Restore допускается только в пустую папку,
проверяет пути ZIP и целостность SQLite, переносит пути артефактов на новый корень.
Затем запустить `DXAQC_DATA=/absolute/restored ./competition/run.sh serve 8090`.
Копию с медицинскими изображениями хранить в том же доверенном контуре, что и рабочие данные.

## Диагностика

`/health` — жив ли HTTP; `/api/v1/ready` — живой worker очереди, загрузка весов, доступ к БД, возможность записи и свободный диск.
Docker HEALTHCHECK использует readiness. Ошибка модели не заменяется демонстрационным ответом.
Результат отдельного изображения может быть `Failure` при завершённом пакете — смотреть сводку и CSV.

Порт по умолчанию опубликован только на loopback. Для многопользовательского сетевого режима нужны
аутентификация и контроль доступа; введённое имя эксперта в текущем UI не удостоверяет личность.


## Проверенная конфигурация 1.5.0

| Ресурс | Минимально проверенная конфигурация | Рекомендуемый старт для локальной работы |
|---|---|---|
| CPU | x86-64, лимит Docker 4 CPU на Intel i7-1265U | 8 CPU |
| RAM | лимит контейнера 4 ГиБ | 8 ГиБ |
| GPU | Не используется | Не требуется |
| Диск | 10 ГиБ свободно для готового образа и небольшого пакета | 40 ГиБ свободно, увеличивать по архивам и истории |

Это минимально испытанный профиль, не доказанный аппаратный минимум. Диск для сборки
с кешами, больших архивов, истории и резервных копий рассчитывается отдельно: образ + вход +
распаковка + результаты + резерв. Лимит распаковки ZIP 20 ГиБ сам по себе не резервирует место.
Готовый образ занимает 1 520 322 653 байта; результаты одного проверенного архива — около
184 МБ. Пик RSS процесса batch — 510 566 400 байт (около 487 МиБ); RSS не включает весь
контейнерный page cache и не является рекомендацией ограничить RAM до 512 МБ.

Два запуска с `--network none --cpus 4 --memory 4g`: 499 DICOM / 100 исследований,
499 успешных в каждом, предсказания совпадают. Время всей обработки 181,230 / 226,022 с,
максимум по одному исследованию 3,902 / 10,406 с. Полное wall time контейнера
184,744 / 229,143 с. Параллельная нагрузка хоста присутствовала; это не изолированный
бенчмарк. Финальный стенд организатора с H200 не проверялся.

Полный протокол с хешами образов, входа и результатов:
`competition/reports/release_1_5_checks.json`. Бенчмарк выполнен до добавления проверки
worker в HTTP readiness; batch-код и веса одинаковы. Финальный образ дополнительно прошёл
контейнерные тесты и публичный batch smoke. Для проверки именно байтов поставки сверять
image ID, а не только изменяемый тег.

Выходной каталог batch должен быть новым или не содержать служебных артефактов результата.
Повторный запуск в занятый каталог возвращает `OUTPUT_CONFLICT` и код 2, сохраняя старые
результаты. Для сравнения использовать два отдельных каталога. CLI также запрещает вывод
в исходный каталог или его подпапку при видимой ему общей файловой иерархии; при Docker
не монтировать выход внутрь входа на хосте.


### Хранение исходников с 1.9

Новые API-задания хранят `source.zip` и `source.sha256` рядом с каталогом out.
Архив содержит исходные байты, включая возможные персональные теги; размещайте
локальное хранилище с теми же правами доступа, что и исходные исследования.
Это часть рабочего сценария повторного анализа; автоматического удаления архива нет.
Резервное копирование всего корня заданий включает архивы. При планировании диска
нужно учитывать исходные архивы каждого запуска и производные изображения.
Повторный анализ создаёт собственную копию исходника, независимую от родительского
задания, и lineage.json с идентификатором родителя. Старые задания не мигрируют
несуществующие исходные DICOM из PNG.
