# Проекция, ориентиры и исходная ROI — реализация 1.6

## Что работает

- Исходная ROI автоматически читается из DICOM Overlay с `OverlayType=R`.
  Учитываются origin, отдельные компоненты и отверстия. Тип `G` не считается ROI.
- GSPS с SOP Class `1.2.840.10008.5.1.4.1.1.11.1` в том же входном пакете
  связывается с исходными изображениями по ссылкам UID; согласованная GSPS не получает
  строку изображения в CSV. Потерянная ссылка/неподдерживаемый объект остаётся явным отказом.
  Поддерживаются замкнутые `POLYLINE`, `GraphicDimensions=2`, единицы `PIXEL`,
  слои `ROI` или `ROI_*`. Другие графические объекты не интерпретируются как области измерения.
- GSPS-координаты от угла пикселя переводятся в координаты центров пикселей;
  поворот отображения GSPS не меняет исходную геометрию в единицах `PIXEL`.
  Единицы `DISPLAY`/`MATRIX`, frame-specific аннотации, RTSTRUCT, SEG,
  приватные форматы и распознавание нарисованной разметки из пикселей пока не поддерживаются.
- Повторное изображение с теми же пикселями не наследует ROI другого SOPInstanceUID.
- Для бедра рассчитываются отступы исходной ROI, отношения её контуров к кандидатам
  анатомических ориентиров. Поддерживаются отверстия, без их заполнения.
  Отступы не объявляются подтверждёнными при масштабе аппарата по умолчанию.
- На снимках выделяются кандидаты подвздошных краёв, ненумерованных тел позвонков,
  большого/малого вертела, седалищной кости, шейки бедра. Все точки возвращаются
  в исходной ориентации, включая левое бедро. Это геометрические детекторы-кандидаты.
- Проекция оценивается по пикселям: наличие двусторонних структур позвоночника
  или сочетания ориентиров бедра даёт гипотезу `frontal`. В остальных случаях `unknown`.
  Это не обученный и валидированный классификатор AP/lateral; AP от PA он не различает.
  Явная боковая ViewPosition по-прежнему отклоняется чтением DICOM.
- В рабочем месте показаны кандидаты, исходная ROI, причины недоступности и результат
  геометрической проверки. Добавление кандидатов в черновик выполняется явно,
  существующие точки врача не заменяются. Кандидат не становится экспертным эталоном.

## Контракт результатов

В расширенных CSV/XLSX добавлены `projection_assessment`, `anatomy_assessment`,
`source_roi_assessment`, `anatomical_checks_complete`, `image_width`, `image_height`.
Первые восемь полей и `--strict-columns` сохранены. В detail JSON и single-image API
доступен объект `assessment`. Машинные веса и прежние quality_class/score не менялись.
`anatomical_checks_complete=false`: новая проверка не делает полный анатомический вердикт.
Строка с quality_class=0 не означает подтверждения всех анатомических требований ТЗ.

Состояния ROI: `absent` — нет поддерживаемой исходной разметки, `extracted` — прочитана,
`partial` — часть прочитана с ограничениями, `unavailable` — обнаруженное представление
не поддержано или повреждено. Эти состояния описывают чтение, не клиническую правильность.
`margin_status=pass` относится только к геометрическим отступам; назначение ROI
(шейка, всё бедро, отдельные позвонки) нельзя угадывать по произвольной форме.

## Как проверить локализацию на независимом эталоне

```sh
PYTHONPATH=competition python -m dxaqc.validate_anatomy \
  --results /absolute/results.csv --template --output /absolute/reference-template.json
PYTHONPATH=competition python -m dxaqc.validate_anatomy \
  --results /absolute/results.csv --reference /absolute/reviewed-reference.json \
  --tolerance-mm 5 --output /absolute/localization-metrics.json
```

Первый вызов создаёт задания без копирования предсказаний в эталон. Для каждой точки
нужно независимо отметить видимость и координаты в исходном изображении, указать
реальную проекцию, подтверждение, автора и источник. Второй вызов отклоняет незаполненные
шаблоны, неоднозначные UID и неверные координаты. Считает пропуски, ложные точки на
невидимых ориентирах, медиану и P95 расстояния в мм, число попаданий в заданный допуск,
долю размеченных случаев, ошибки и отказы определения проекции. Масштаб по умолчанию
не допускает миллиметровой оценки. Допуск 5 мм — параметр анализа, не медицинский норматив.
Указание имени автора не удостоверяет личность и не доказывает независимость разметки.

## Почему полное ТЗ ещё нельзя объявить закрытым

В исходном архиве 499 DICOM: ViewPosition присутствует, но пуст; ROI/GSPS/RTSTRUCT и
приватных аннотаций нет. Инвентаризация: `reports/anatomy_input_audit_1_6.json`.
Независимого эталона номеров позвонков, ориентиров и альтернативных проекций нет.

Th12 намеренно не присваивается первой найденной структуре: обрезка кадра не задаёт номер
позвонка. Реализовано выделение ненумерованных кандидатов, **локализация Th12 не завершена**.
Проверенной анатомической локализации и анатомического вердикта исходной ROI также пока нет.
Их нельзя получить добавлением флага «проверено» или обучением на собственных неподтверждённых
подсказках. Необходимы независимо проверенные ориентиры и проекции, затем отложенная оценка.

Стандарт чтения: [DICOM PS3.3 C.9.2](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.9.2.html),
[DICOM PS3.3 C.10.5](https://dicom.nema.org/medical/dicom/2024a/output/chtml/part03/sect_C.10.5.html).
Это реализация указанного подмножества, не сертификат полной DICOM-совместимости.
