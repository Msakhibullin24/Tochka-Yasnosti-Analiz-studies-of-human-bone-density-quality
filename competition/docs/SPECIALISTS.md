# Специализированные модели: установка, обучение и проверка

Реализация от 2026-09-22. Основной QC работает; новые нейросетевые кандидаты
подключаются в экспериментальном режиме и не меняют итоговый класс или правки врача.
Готовый детектор Th12/L1–L4 и целевой детектор имплантов этой поставкой не заявляются.

## Что скачивается

`make specialists` загружает 6 снимков исходных репозиториев, 7 внешних checkpoint
и 18 таблиц NHANES. Полный список, версии, размеры и SHA-256 находятся в
[`specialist_sources.json`](../../docs/competition/specialist_sources.json).

| Источник | Локальное состояние и назначение |
|---|---|
| DXA-to-3D | Код и 139 МБ весов; строгая загрузка архитектуры проверена, выход `[1, 1254]`. Порядок кривых и исходный preprocessing не подтверждены; не используется для нумерации позвонков |
| timm | Код; ConvNeXt-V2 Tiny и EfficientNet-B4 с общим предобучением, строгая загрузка проверена |
| ASL | Исходники; masked ASL и BCE реализованы в нашем обучении и проверены тестами |
| TorchCAM / pytorch-grad-cam | Оба репозитория; для рабочего Grad-CAM используется пакет `grad-cam` |
| YOLO26x | Ultralytics 8.4.40, `yolo26x.pt` и `yolo26x-seg.pt`; оба проходят CPU-инференс. 80 COCO-классов, целевых DXA-классов нет |
| NHANES | 18 XPT-файлов whole-body, spine, femur для доступных циклов. Это таблицы, не изображения |

Исходники сохраняются в `data/specialists/sources/`, архивы — в `archives/`,
веса — в `weights/`, XPT — в `datasets/nhanes/`. Каталог исключён из Git и Docker-контекста.
Ссылки внутри архивов не извлекаются; список пропущенных ссылок отражается в receipt.
Повреждённые или изменённые локальные файлы не перезаписываются автоматически.

Скачивание не означает разрешение на распространение весов: в каталоге отдельно
зафиксированы лицензии исходников.
Для YOLO необходимо учитывать AGPL-3.0. Эти исходники и внешние веса не добавляются
автоматически в основной контейнер. MIT-уведомление для реконструированной архитектуры
DXA-to-3D сохранено в `docs/competition/DXA_TO_3D_LICENSE.txt`.

## Подготовка окружения

Нужны `uv` и Python 3.11. По умолчанию используется существующий `backend/.venv/bin/python`;
другой интерпретатор задаётся `OSSEO_PYTHON=/path/to/python3.11`.

```sh
make specialists
make specialists-verify
```

Первая команда создаёт отдельное окружение `data/specialists/venv` из
`competition/requirements-specialists-lock.txt`. Рабочее окружение backend не меняется.
Пакеты устанавливаются из lock-файла; скачанные снимки библиотечных репозиториев
служат зафиксированным материалом для исследования, а не подменяют установленные пакеты.
Профиль рассчитан на CPU; на проверенной машине CUDA недоступна.
Агрегированные результаты первоначального запуска (до замены YOLOv8 на YOLO26x) сохранены в
[`specialist_execution_2026_09_22.json`](../../docs/competition/specialist_execution_2026_09_22.json).

Вторая команда проверяет все артефакты без сети. Отчёты:

- `data/specialists/assets-status.json`: целостность и ограничения источников;
- `data/specialists/checkpoint-checks.json`: совместимость архитектур, не точность;
- `data/specialists/nhanes-inventory.json`: строки и уникальные участники каждой таблицы.

## YOLO26x: детекция и сегментация

По запросу проекта YOLOv8n заменена на [YOLO26x](https://docs.ultralytics.com/models/yolo26/)
в каталоге загрузки и проверках. Скачаны официальные `yolo26x.pt` (118 667 365 байт)
и `yolo26x-seg.pt` (142 129 861 байт) из релиза assets v8.4.0.
SHA-256 закреплены в каталоге. Окружение использует `ultralytics==8.4.40`,
совместимость с текущим `torch==2.1.2+cpu` проверена.

Обе модели прошли инференс на трёх локальных DICOM при `imgsz=640`, CPU, 4 потока,
с запрещёнными сетевыми подключениями. Также прошли проверки всех пяти архитектур
и 13 тестов исследовательской ветки и загрузчика. Это проверка выполнения;
точность обнаружения имплантов или артефактов на DXA не оценивалась.
Отчёт: [`yolo26x_execution_2026_09_22.json`](../../docs/competition/yolo26x_execution_2026_09_22.json).

Модели имеют 80 общих COCO-классов. Для целевого обучения нужны DXA-изображения
с bbox/mask-разметкой и независимая проверка по исследованиям. Общие предсказания
YOLO не передаются в медицинский вердикт. Старые локальные файлы YOLOv8 могут
оставаться на диске, но не входят в активный каталог и не загружаются проверками.

## Обучение бинарной и многометочной модели

Вход — существующий CSV `competition/labels/image_labels.csv`: бинарные 0/1,
пустые значения для неизвестных меток. Неприменимые к области метки исключаются из loss.
Используется полный кадр с сохранением пропорций и исходной ориентации.

```sh
HF_HUB_OFFLINE=1 data/specialists/venv/bin/python competition/train_specialist.py \
  --dataset '/path/to/Исследования' \
  --weights data/specialists/weights/convnextv2_tiny.safetensors \
  --output data/specialists/runs/convnextv2-bce-v1
```

Для ASL добавить `--loss asl` и выбрать другую папку результата. Для EfficientNet:
`--backbone tf_efficientnet_b4 --weights data/specialists/weights/efficientnet_b4.safetensors`.
Существующие эксперименты не перезаписываются. На этой машине три эксперимента уже выполнены.

Сейчас обучается линейная бинарная/multilabel голова над замороженным encoder.
Полное дообучение backbone не реализовано этим скриптом. Никакой целевой разметки
для новых классов motion/implant скрипт не создаёт.

Фиксированное разбиение по исследованиям: 149 изображений / 60 исследований train,
54 / 21 validation, 46 / 19 test. Пороги выбираются только на validation.
Это внутренняя проверка с известной областью; принадлежность нескольких исследований
одному пациенту отдельно не подтверждена. Автоматический роутер оценивается отдельно.
Если в training или validation нет двух классов для критерия, его статус `undetermined`.

На этом разбиении ConvNeXt+BCE: ROC-AUC 0,642, F1 0,390;
ConvNeXt+ASL: 0,642 / 0,400; EfficientNet+BCE: 0,569 / 0,372.
Тест содержит только 10 положительных бинарных случаев. Для ряда отдельных критериев
положительных примеров нет или очень мало. Эти результаты не доказывают улучшение
относительно основного продукта: его опубликованные метрики получены по другому протоколу.
Кандидат по умолчанию — первый BCE baseline, не победитель отбора по test.

Выход: `model.ts` (TorchScript), `head.safetensors`, `model.json` с контрактом,
контрольными суммами и метриками, `predictions.json` с разбиением и score.
Полный TorchScript содержит encoder и голову, поэтому `timm` не нужен для инференса в приложении.

## Запуск в продукте

```sh
make dev-specialists
# Другой кандидат:
make dev-specialists SPECIALIST_MODEL=data/specialists/runs/convnextv2-asl-v1
```

Интерфейс: http://127.0.0.1:5173. Backend: http://127.0.0.1:8001.
В карточке нового задания появляется «Экспериментальная оценка качества».
Предыдущие задания нужно обработать заново: их сохранённые результаты не переписываются.
`/api/v1/ready` сообщает, какая дополнительная модель загружена.

Переменная `DXAQC_SPECIALIST_PATH` задаёт папку модели при старте backend.
Неверный checksum/контракт препятствует запуску этой конфигурации; ошибка дополнительного
инференса после запуска сохраняется как `unavailable` без изменения основного решения.
Результаты доступны в detail JSON и колонке `specialist_qc` расширенного CSV/XLSX.
Строгие конкурсные колонки не меняются.

Контейнер с read-only подключением подготовленного кандидата:

```sh
docker compose -f docker-compose.yml -f docker-compose.specialists.yml up --build
```

Сначала выполнить обучение: монтирование пустой папки не создаёт модель.
Для отключения вернуться к `make dev` либо обычному compose без дополнительного файла.

## Отдельный вывод и Grad-CAM

```sh
HF_HUB_OFFLINE=1 data/specialists/venv/bin/python competition/predict_specialist.py \
  --model data/specialists/runs/convnextv2-bce-v1 \
  --input '/path/to/image.dcm' --region spine \
  --output data/specialists/predictions/example \
  --cam quality --weights data/specialists/weights/convnextv2_tiny.safetensors
```

Создаются `prediction.json`, `cam.npy` и `cam.png` в координатах исходного снимка.
Карта объясняет выбранный выход дополнительной модели, а не итоговое правило основного QC.
Она не считается bbox или маской дефекта. CAM доступен через CLI; интерактивное наложение
CAM в веб-просмотрщике пока не реализовано.

## Что ещё необходимо для полной исходной задачи

1. Целевые фронтальные DXA с проверенными номерами/границами Th12–L5, подвздошными
   гребнями и другими нужными ориентирами. DXA-to-3D не закрывает этот контракт.
2. Bbox/mask-разметка объектов на целевых DXA и точный внешний датасет имплантов.
   Ссылка на главную Roboflow Universe не определяет ни набор, ни его версию.
3. Экспертные классы движения, артефактов и пригодности конкретной ROI; XPT NHANES
   не заменяют изображения и такую разметку.
4. Разделение по пациентам, более представительный тест, проверка разных аппаратов,
   затем решение о замене основного классификатора. Клиническая приёмка не завершена.

## Проверки

`make verify` проверяет frontend, оба backend и сборку. Новые тесты покрывают
целостность загрузок, безопасное извлечение, masked loss, непересекающиеся study split,
загрузку TorchScript, неприменимые/неизвестные критерии, сохранение дополнительной
оценки и неизменность основного решения. Реальные checkpoint проверяются отдельно
через `make specialists`, поскольку обычный CI не скачивает внешние веса.
Тест полного обучения и экспорта выполняется в отдельном окружении подготовки моделей;
в базовом окружении он пропускается из-за отсутствия необязательного `safetensors`.
Контейнер `osseo-specialists:dev` проверен без сети, с 4 CPU и 4 ГиБ:
3/3 DICOM обработаны, строгая таблица прошла проверку; весь пакет занял 17,84 с.
Это smoke-проверка на трёх файлах, не измерение клинической точности или нагрузки.

## Обучить QC и открыть все метрики

```sh
make train-specialists INPUT='/path/to/Исследования' OUTPUT=data/specialists/experiments/new-run
make metrics-specialists METRICS_DIR=data/specialists/experiments/new-run/report
```

Отчёт открывается по `http://127.0.0.1:8092`. Команда обучает головы трёх моделей:
ConvNeXt-V2 BCE, ConvNeXt-V2 ASL, EfficientNet-B4 BCE, по 50 эпох.
Backbone заморожен. Каждый запуск сохраняет loss train/validation по эпохам,
TorchScript-модель, веса головы и предсказания. Выходная папка должна быть новой.

В HTML доступны ROC/PR-кривые, матрицы ошибок и таблицы test. JSON/CSV содержат
метрики train/validation/test, precision, recall, specificity, accuracy,
balanced accuracy, F1, ROC AUC и average precision (AP, не трапецеидальная PR AUC).
95% интервалы в JSON рассчитаны 1000 bootstrap-повторами по исследованиям.
Неопределённые метрики остаются `null`; неизвестные и неприменимые метки исключены.
Число bootstrap-повторов, где метрика определена, сохранено отдельно.

Выполнены запуски `data/specialists/runs/*-v2`, отчёт —
`data/specialists/reports/qc-v2/index.html`. Разделение не изменялось:
149/54/46 изображений, 60/21/19 исследований. Выбор модели по этим повторно
просмотренным test-результатам потребует нового независимого набора для подтверждения.

## Целевое обучение YOLO26x

Нужны проверенные человеком DXA-аннотации объектов, а не CSV оценок качества.
Найденный HipRay содержит маски бедренных/тазовых костей на рентгенограммах;
он не является DXA-разметкой имплантов. Его маски не использованы как такой эталон.

`competition/train_detector.py` принимает manifest JSON:

```json
{
  "modality": "DXA",
  "task": "detect",
  "names": ["implant", "removable_artifact"],
  "samples": [
    {"image": "images/a.dcm", "label": "labels/a.txt", "study": "group-001", "split": "train", "reviewed": true},
    {"image": "images/b.dcm", "label": "labels/b.txt", "study": "group-002", "split": "val", "reviewed": true},
    {"image": "images/c.dcm", "label": "labels/c.txt", "study": "group-003", "split": "test", "reviewed": true}
  ]
}
```

Это схема, не готовый обучающий набор. TXT для detect содержит строки
`class_id center_x center_y width height` с координатами [0,1]. Для `task=segment`
нужны полигоны YOLO: `class_id x1 y1 x2 y2 x3 y3 ...` в исходной геометрии изображения.
Пустой TXT допустим только для проверенного отрицательного снимка. Отсутствующий TXT
не превращается в отрицательную метку. Все исследования разделяются между train/val/test;
декодированные дубликаты запрещены. Если известен общий пациент, используйте один
`study`-идентификатор для всех его исследований. Пути относительны к корню датасета.

```sh
data/specialists/venv/bin/python competition/train_detector.py \
  --manifest /path/to/manifest.json --dataset /path/to/dataset \
  --output data/specialists/runs/yolo26x-dxa-v1 --check-only

data/specialists/venv/bin/python competition/train_detector.py \
  --manifest /path/to/manifest.json --dataset /path/to/dataset \
  --output data/specialists/runs/yolo26x-dxa-v1 --epochs 50 --size 640 --device cpu
```

Из каталога автоматически выбираются YOLO26x detect или segment и проверяется SHA-256.
Обучение сохраняет `training/results.csv`, loss/PR/confusion-графики, `best.pt`,
`metrics.json` (aggregate и per-class для val/test), `data-audit.json`, `status.json`.
Best checkpoint выбирается по validation; test оценивается после обучения.
Проверка разметки не заменяет её содержательную медицинскую проверку.
Изображения для обучения копируются локально; эта папка может содержать данные пациента.

Полный реальный цикл YOLO можно проверить отдельно на синтетической тестовой фикстуре:

```sh
DXAQC_TEST_YOLO_TRAIN=1 data/specialists/venv/bin/python -m pytest -q \
  competition/tests/test_training_reports.py
```

Эта проверка не обучает DXA-детектор и не входит в отчёт клинических метрик.
Без целевой разметки обучение и оценка имплантов/артефактов остаются невыполненными.

При проверке обучения обнаружена ошибка segmentation loss в Ultralytics 8.4.0.
Пакет обновлён до 8.4.40 с исправлением; веса assets v8.4.0 остаются прежними.
Исторический отчёт миграции YOLO отражает первоначальный инференс на 8.4.0.

Итог выполненного обучения и проверок: [training_execution_2026_09_22.json](../../docs/competition/training_execution_2026_09_22.json).

## Региональное дообучение и единое сравнение

```sh
make advance-specialists INPUT='/path/to/Исследования' OUTPUT=data/specialists/experiments/new-upgrade
make dev-specialists SPECIALIST_MODEL=data/specialists/experiments/new-upgrade/suite
```

Команда создаёт пакет экспертной разметки, обучает общий head-only baseline и
отдельные ConvNeXt-V2 для позвоночника и бедра, упаковывает suite и строит парный
benchmark. У региональных моделей дообучаются последний stage, финальная нормализация
и классификационная голова. Остальная сеть заморожена; её карты признаков вычисляются
один раз. Эпоха выбирается по validation loss, пороги — по validation F1. По умолчанию
12 эпох, CPU. Это дообучение части backbone, а не обучение всей сети с нуля.

Доступен дополнительный эксперимент `--views full-center`: полный кадр + центральные
70% нормализованного входа с общим encoder. Эта вторая область не является результатом
анатомической локализации. Полный кадр сохраняется для проверки охвата.

`benchmark_specialists.py` заново обучает гибрид только на той же train-части,
включая роутер, и оценивает реальный `Analyzer` на DICOM. Старый bundle, обученный на
всём наборе, не используется для оценки. CNN выбирается по предсказанной роутером
области. Вес смешивания выбирается из фиксированных 0/0.25/0.5/0.75/1 по validation AP;
порог ансамбля — по validation F1. В этом сравнении у гибрида нет синтетических
добавок; результаты не тождественны опубликованной ранее полной CV.

Выполненный benchmark: `data/specialists/benchmarks/paired-v3/metrics.json`.
На общих 46 test-снимках: hybrid refit AUC 0.869 / F1 0.432; общий frozen CNN
0.642 / 0.390; региональные fine-tuned CNN 0.639 / 0.462; выбранный на validation
ансамбль 0.833 / 0.462. Это не доказательство статистически значимого улучшения:
test уже просматривался, содержит лишь 10 нарушений. Основной bundle не заменён.

`regional-suite-v3` содержит две TorchScript-модели и проверяемые SHA-256 метаданных.
Роутер выбирает одну региональную модель. Для Grad-CAM отдельного fine-tuned кандидата
загружаются его `encoder.safetensors` и `head.safetensors`, а результат сверяется с
TorchScript. CAM для двух видов пока не поддержан и явно отклоняется.

## Авторские модели: единый статус и исследовательский запуск

`GET /api/v1/specialists` возвращает проверку файлов по SHA-256 и отдельно готовность
задачи. В интерфейсе доступен раздел «Модели и данные проекта». В контейнер входит
каталог, но внешние многомегабайтные веса автоматически в образ не добавляются.
Для проверки смонтированных весов задайте `DXAQC_SPECIALIST_ASSETS`.

Каталог дополнен `yolo26x-pose.pt` и уже имевшимся checkpoint модели
`hawaii-ai/dxa-pointplacement` на 105 ориентиров. Последний хранится также в
`backend/models/checkpoint.pth`; его существующий MMPose runtime работает в backend
окружении. Используются веса hawaii-ai/dxa-pointplacement.
Всего в каталоге 9 архивов исходников, 7 файлов весов и 18 XPT-таблиц.

```sh
data/specialists/venv/bin/python competition/analyze_specialists.py \
  --input /path/to/spine.dcm --protocol spine \
  --qc data/specialists/runs/regional-suite-v3 \
  --output data/specialists/predictions/new-case
```

Поддержаны `spine`, `hip_left`, `hip_right`, `whole-body-air-ratio`. Отчёт явно
разделяет обученный QC, общие COCO-объекты и неприменимые модели. Для whole-body
доступны 105 исследовательских ориентиров и необработанный вектор DXA-to-3D;
его порядок кривых/preprocessing не подтверждены, поэтому он не превращается
в номера Th12/L1–L4, углы или клиническую 3D-реконструкцию. Протокол whole-body
должен быть установлен отдельно; передавать туда локальный снимок поясницы нельзя.

Human-Skeletal-Form и VerteNet удалены из активного каталога и кода анализа:
авторские веса недоступны. Их загрузка больше не входит в `make specialists`.
Ранее сохранённые отчёты отражают состояние до удаления.

## Разметка и обучение анатомии

Подготовлен приватный пакет `data/specialists/annotations/review-v1` на 249 снимков:
исходная геометрия PNG, пустые COCO-задачи для объектов и ориентиров, два независимых
CSV-бланка. В позвоночнике предусмотрены центр и четыре угла Th12–L5; в бедре —
восемь именованных ориентиров. Видимость точки должна быть размечена экспертом;
модель не должна «достраивать» невидимую анатомию как достоверную.

```sh
data/specialists/venv/bin/python competition/reconcile_reviews.py \
  --packet /path/to/packet --review-a /path/to/reviewer-A.csv \
  --review-b /path/to/reviewer-B.csv --output /path/to/new-reconciliation.json
```

Сверка сохраняет согласованные оценки и расхождения. Незавершённые бланки остаются
pending, несогласованные случаи требуют adjudication. Исходные оценки организатора
никогда не перезаписываются. Выгруженный пакет сейчас содержит 249 pending-снимков;
экспертная проверка не была выполнена автоматически.

После завершения COCO-разметки нужен CSV-реестр `image_id,reviewer_id,reviewed`,
где `reviewed=true` подтверждает проверку каждого изображения, включая отрицательные.

```sh
data/specialists/venv/bin/python competition/import_annotations.py \
  --packet /path/to/packet --coco /path/to/completed.coco.json \
  --ledger /path/to/review-ledger.csv --task pose --output /path/to/new-pose-dataset

data/specialists/venv/bin/python competition/train_detector.py \
  --dataset /path/to/new-pose-dataset --manifest /path/to/new-pose-dataset/manifest.json \
  --output data/specialists/runs/anatomy-v1 --epochs 50
```

Импорт поддерживает detect/segment/pose, проверяет SHA изображений, размеры,
координаты, классы, видимость, подтверждение разметки и разделение исследований.
Несвязные полигоны и RLE не объединяются молча. Для pose автоматически выбирается
YOLO26x Pose с новым количеством именованных точек; flip-аугментации отключены.
Общие COCO pose-веса — инициализация, не готовая DXA-анатомия. Полный технический
цикл pose проверен на синтетической фикстуре. Целевые веса и анатомические метрики
появятся только после экспертной разметки и реального обучения.

Текущий обзор результатов: `http://127.0.0.1:8093`; приложение региональной версии:
`http://127.0.0.1:5175`. Они работают локально, пока запущены соответствующие процессы.
