# Подход, данные, эксперименты, ограничения (материал для презентации)

> Исторические эксперименты ниже относятся к указанным артефактам и прежнему протоколу.
> Актуальное соответствие ТЗ: `../../docs/FINAL_TZ_AUDIT_2026_09_20_RU.md`; сквозные метрики: `../reports/pipeline_audit_1_5.json`.
> Геометрические признаки не являются подтверждённой локализацией Th12, вертелов или ROI; калибровка score не подтверждена.

## 1. Клиническая логика
Сервис использует критерии методических рекомендаций как таксономию классификации. Геометрические
признаки объединяются с эмбеддингами; доступные измерения показаны в интерфейсе. Не каждое срабатывание
имеет подтверждённую анатомическую локализацию.

| Критерий ТЗ | Что измеряется | AUC одного лучшего измерения¹ → AUC ансамбля на групповой CV² |
|---|---|---|
| Укладка позвоночника (гребни подвздошных костей, ½ Th12) | доля кости в латеральных зонах нижних 20 % кадра, высота гребня в мм | 0.92 → 0.86 |
| Ось позвоночника ≤ 5° | трекинг центра позвоночного столба (динамическое программирование) → робастная прямая → угол; кривизна отделяет сколиоз | 0.84 → 0.80 (точность угла на синтетике < 1°, проверяется тестом) |
| Артефакты | white top-hat вне столба (косточки белья, клипсы), насыщенные пятна (металл) | 0.92 → 0.90 |
| Позиционирование/ротация бедра | ось диафиза, выступ малого вертела над хордой «диафиз→шейка», вогнутость медиального контура | 0.76 → 0.73 |
| Область интереса бедра (3 см / 2 см) | отступы в **мм** над большим вертелом, под седалищной костью, латерально; высота кадра | 0.94 → 0.94 |

¹ одномерный AUC на всех данных, без обучения (`reports/experiments/geometry_univariate_auc.txt`; для «обратных» признаков 1−AUC).
² out-of-fold, `reports/validation_metrics.json`. Для редких классов (6–10 позитивов) ансамбль на CV закономерно ниже одномерной оценки.

## 2. Таксономия и несколько нарушений
Мультилейбл: 3 типа для позвоночника, 2 (+ правило металлоконструкции) для бедра. Каждый тип — отдельный
скор; итог = noisy-OR типов, усреднённый с двумя «прямыми» моделями класса (они ловят случаи,
когда эксперт поставил 1 без отметки критерия: «сколиоз, неверная разметка»). Текущий итоговый класс и типы определяет общий `decision.py`, учитывающий пороги и геометрические ограничения.

## 3. Данные: что нашли при аудите (и почему это важно для честных метрик)
* 499 DICOM = 252 уникальных изображения: **247 файлов — точные пиксельные копии** с другими SOPInstanceUID.
  Случайное разбиение по файлам дало бы утечку и завышенные метрики. У нас дедупликация по sha256 пикселей
  и разбиение по исследованиям.
* В DICOM нет ни области, ни стороны, ни привязки к колонкам Excel → мы разметили область/сторону всех 252
  изображений и проверили согласованность (в каждом исследовании ровно одно изображение каждой области;
  набор областей совпал с заполненными колонками Excel в 98/100 исследований, 2 расхождения — эндопротезы без метки).
* Нет PixelSpacing → нашли масштаб в `ExposedArea`: 0.607 мм/пикс (разброс < 1 %).
* 337 файлов с UID, не проходящими валидацию DICOM → сохраняем как есть.
* Несогласованности разметки (строки 8, 13, 37 Excel) не исправляли — храним исходные метки.
* PatientID обезличен одинаково у всех → независимость пациентов между исследованиями проверить нельзя (ограничение).
* Дисбаланс: 29 % нарушений; редкие типы 6–7 позитивов → `class_weight=balanced`, компактные наборы признаков
  (6–11) на тип, без аугментаций, меняющих метку.

## 5. Почему метрикам можно верить
1. Разбиение по исследованиям, копии и парные области не пересекают границу фолда.
2. Порог F1 для каждого фолда выбран на внутренней CV обучающей части.
3. Гиперпараметры зафиксированы до оценки, перебора на CV не было.
4. Негативный контроль (`leakage_check.py`, `reports/leakage_check.json`): метки переставляются между
   исследованиями целыми блоками (внутриисследовательская корреляция сохраняется) → AUC 0.48 / 0.47.
5. Детерминизм: два полных прогона (папка и ZIP) дали идентичные вердикты и score (`reports/full_batch_summary.json`, тест `test_results_are_reproducible...`).
6. Что остаётся оптимистичным (и мы это пишем): признаки проектировались с просмотром всего набора;
   F1 по отдельным типам — с порогом на объединённых OOF. Доверительные интервалы широкие (AUC 0.70–0.85):
   100 исследований — это мало, и на закрытом тесте возможен разброс в этих пределах.

6а. Внешняя проверка на другом аппарате (Hologic, открытый набор Ramathibodi, в обучении не участвует):
   область — 100 %, измерения переносятся слабо (AUC 0.58–0.72 при n=20; другая подача изображения, нанесённые ROI).
   Организатор подтвердил, что аппарат в данных один, но для внедрения в другие ЛПУ потребуется дообучение.

## 6. Анализ ошибок
* 12 из 45 ложных срабатываний и часть пропусков — исследования с комментарием эксперта «сколиоз» /
  «требует внимания»: граница «анатомия vs ошибка укладки» неоднозначна даже для экспертов.
* Главный источник пропусков — ротация бедра (18 из 36): оценка малого вертела по 2D-проекции тонкая;
  здесь поможет точечная разметка 4–6 ориентиров на 300–500 снимках (инструмент разметки в проекте есть).
* Артефакты позвоночника ловятся лучше всего (пропущен 1 из 17).

## 7. Скорость и требования
Полный прогон 499 файлов: см. `reports/full_batch_summary.json` (100 % Success, доли секунды на изображение,
единицы секунд на исследование при лимите 180 с). GPU не нужен; пакетный режим работает с `--network none`.

## 8. План пилота
1. Тихий режим в 1–2 кабинетах денситометрии: сервис пишет SR в PACS, лаборант видит подсказку до ухода пациента.
2. Сбор расхождений «ИИ vs врач» → дообучение (`train.py`, 15 минут на CPU), расширение на Hologic.
3. Метрики пилота: доля повторных исследований, время врача на контроль качества, согласие κ с экспертом.
4. Далее: точечные ориентиры → автоматическое предложение ROI с подтверждением специалистом.
