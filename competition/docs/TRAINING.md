# Обучение и дообучение

```sh
python train.py --dataset "/path/НД_для_обучения/Исследования" --synthetic rotate   # боевая конфигурация, ≈8 мин на 12 CPU
python train.py --dataset ... --synthetic rotate --skip-cv                           # только финальная модель
python leakage_check.py --dataset ...                                                # негативный контроль протокола
```
В контейнере: `docker run --rm -v /path/Исследования:/data/in:ro -v $PWD/models:/app/models osseo-dxaqc:1.0.0 python train.py --dataset /data/in`.

## Данные
`labels/image_labels.csv` — результат аудита: 499 DICOM → 252 уникальных изображения (247 файлов — точные
пиксельные копии) → для каждого определена область и сторона (проверено визуально, согласовано с Excel:
в каждом исследовании ровно по одному изображению каждой области) → присоединены метки из `разметка.xlsx`
по ключу папки. 249 изображений с метками; 3 (эндопротезы, метка пустая) не используются.

Перед экспериментом можно сохранить воспроизводимый аудит текущих декодированных пикселей:

```sh
PYTHONPATH=competition python competition/source_integrity.py \
  --source "organiser=competition/labels/image_labels.csv=/absolute/Исследования" \
  --output data/specialists/audits/organiser_source_integrity.json
```

В нём есть хеши текущих пикселей и групп исследований, но нет доказательства независимости пациентов.
Файл содержит относительные пути к исходным снимкам и хранится локально в исключённом из Git `data/`.
После аудита можно зафиксировать проверяемый снимок кода, весов и измерений:

```sh
PYTHONPATH=competition python competition/release_snapshot.py \
  --source-audit data/specialists/audits/organiser_source_integrity.json \
  --output docs/competition/my_release_snapshot.json
PYTHONPATH=competition python competition/release_snapshot.py \
  --source-audit data/specialists/audits/organiser_source_integrity.json \
  --output docs/competition/my_release_snapshot.json --verify
```

Снимок проверяет текущий baseline 1.9.2 и отдельный shadow-портфель 1.9.3. При изменении
весов или кода нужен новый файл, а не тихая перезапись старого. Для проверки на другом ПК
нужно перенести локальный файл аудита; Git содержит только агрегированный снимок без путей к снимкам.

Чтобы дообучить на новых данных, используйте отдельный `--extra` CSV. Перед обучением
`train.py` заново декодирует все размеченные источники и отвергает пиксельные копии между
наборами или исследованиями, изменившиеся размеры и пропавшие файлы. Исторический
`pixel_sha256` из CSV не совпадает с текущей нормализацией; проверка использует текущие пиксели.

## Новые датасеты (которые вы скачаете)
```sh
python ingest.py --name mydata --root /path/to/downloaded \
  --reference-root /path/to/organiser/Исследования [--pixel-mm 0.6]
```
1. `ingest.py` заново читает размеченные DICOM организатора из `--reference-root`, затем DICOM/PNG/JPG нового
   набора. Точные копии текущих декодированных пикселей отклоняются до формирования кандидатов; без
   исходного корня организатора импорт теперь не запускается. Результат —
   `labels/candidates_mydata.csv` + контактные листы.
   Колонки меток в шаблоне **пустые**: `suggested_*` — лишь подсказки модели для эксперта, метки не выдумываются.
2. Эксперт заполняет `region`, `quality_class` и критерии (0/1; неизвестно — пусто) → `labels/mydata.csv`.
3. Обучение: `python train.py --dataset <organiser> --synthetic rotate --extra mydata=labels/mydata.csv=/path/to/downloaded
   --report-name exp_with_mydata --no-save-model` — сначала как эксперимент.
4. **Метрики всегда считаются только на снимках организатора**, дополнительные данные участвуют лишь в обучении.
   Точные пиксельные копии не допускаются даже при прямом запуске `train.py --extra`.
   Кэш признаков привязан к текущим декодированным пикселям, поэтому изменение DICOM не переиспользует старые признаки.
   Однако связь разных исследований с одним пациентом не доказана, поэтому оценки остаются внутренними.
   Берите датасет в боевую модель, только если AUC вырос во всех парных повторах (`quality_auc_per_repeat`)
   и ни один критерий не просел; иначе он вредит (другой аппарат, другая подача изображения).
5. Наборы без меток качества (рентгенограммы, сегментации) классификатору напрямую не помогают — ими можно
   улучшать только измерения (ориентиры), и это отдельная работа с отдельной проверкой.

Проверено на реальном внешнем наборе Ramathibodi (Hologic): `ingest.py` → 60 файлов, 40 уникальных, области
определены; `external_validation.py` → `reports/external_ramathibodi.json`.

## Протокол валидации (защита от утечек)
* единица разбиения — папка исследования: позвоночник и оба бедра одного исследования, а также все пиксельные
  копии всегда в одном фолде. Во всех 100 исследованиях DICOM `PatientID` одинаковый после обезличивания;
  по этим данным доказать независимость пациентов нельзя;
* `StratifiedGroupKFold(5)` × 3 повтора с разными сидами;
* порог решения для каждого внешнего фолда выбирается по **внутренним** out-of-fold предсказаниям обучающей
  части → F1 в отчёте не подогнан под оцениваемые данные;
* 95 % ДИ — кластерный бутстрап по исследованиям (2000 выборок);
* обычные аугментации не применяются: поворот меняет целевой угол, кроп — охват, отражение — сторону;
* единственное исключение — синтетические повороты качественных снимков позвоночника с **известной по
  построению** меткой оси; они идут в обучение только вместе с родительским снимком и учат только критерий оси
  (остальные метки для них «неизвестно» — иначе чёрные углы портят критерий укладки: проверено экспериментом);
* гиперпараметры фиксированы заранее (без перебора на CV), сид 17.

Артефакты: `models/bundle.joblib`, `reports/validation_metrics.json`, `reports/oof_predictions.csv`.


## Сквозной аудит роутера и качества (1.5)

Из корня репозитория, в среде с установленными конкурсными зависимостями:

```sh
PYTHONPATH=competition python competition/train.py --dataset /absolute/Исследования \
  --synthetic rotate --repeats 1 --pipeline-cv --report-name pipeline_audit_1_5 --no-save-model
```

Внешние разбиения по исследованиям общие для роутера и моделей качества. Пороги выбираются
на внутренних разбиениях обучающей части. Отложенные исходные DICOM проходят через рабочий
`Analyzer`, включая предсказанную область, отражение левого бедра, геометрию и итоговые правила.
Режим записывает JSON и OOF CSV, не меняет поставляемые веса. Один повтор из пяти фолдов —
зафиксированный объём этого аудита; старые три повтора региональных моделей не подменяют его.
Отчёт содержит бинарные метрики и точность роутера. Для типов нарушений см. отдельный
`decision_v2_validation.json`; его протокол отличается. Доверительные интервалы отражают
внутреннюю выборку, а не переносимость на другую клинику. Равенство SHA кода в отчёте
проверяется относительно версии, фактически использованной при запуске.


## Калибровка V2 (1.8)

Для GE Healthcare / Lunar Prodigy Advance при отсутствии явных PixelSpacing или
ImagerPixelSpacing используется пара Y=1,05 мм, X=0,6 мм из разъяснений организатора.
ExposedArea не заменяет эту пару. Явные теги имеют приоритет; расхождение с V2
отмечается предупреждением. Для других аппаратов V2 автоматически не применяется.

Измерения основных и синтетических снимков проходят через measure_image.
Повороты синтетики выполняются в физических координатах, затем возвращаются в
исходную сетку пикселей; образцы с нечисловым углом или углом ≤5° отбрасываются.
Это инженерная проверка синтетики, не независимая анатомическая разметка.
Кэш признаков учитывает исходники чтения и геометрии. Старые веса несовместимы
с новой калибровкой и должны быть переобучены. Новый bundle хранит calibration_version.

Повтор воспроизведения из корня:

```sh
PYTHONPATH=competition python competition/train.py --dataset /absolute/Исследования \
  --synthetic rotate --repeats 1 --report-name calibration_v2_training
PYTHONPATH=competition python competition/train.py --dataset /absolute/Исследования \
  --synthetic rotate --repeats 1 --pipeline-cv --no-save-model --report-name calibration_v2_pipeline
```

Первый отчёт оценивает качество при известной области, второй — сквозной Analyzer
на общих внешних фолдах. Не смешивать эти протоколы и не выдавать внутреннюю CV
за независимую проверку поставляемого bundle на новой клинике.
