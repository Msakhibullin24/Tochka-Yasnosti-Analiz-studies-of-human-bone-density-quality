# Обучение и дообучение

```sh
python train.py --dataset "/path/НД_для_обучения/Исследования" --synthetic rotate   # боевая конфигурация, ≈8 мин на 12 CPU
python train.py --dataset ... --synthetic rotate --skip-cv                           # только финальная модель
python leakage_check.py --dataset ...                                                # негативный контроль протокола
```
В контейнере: `docker run --rm -v /path/Исследования:/data/in:ro -v $PWD/models:/app/models osseo-dxaqc:1.0.0 python train.py --dataset /data/in`.

## Данные
`labels/image_labels.csv` — результат аудита: 499 DICOM → 252 уникальных изображения (247 файлов — точные
пиксельные копии) → для каждого определена область и сторона (проверено визуально, согласовано с Excel:
в каждом исследовании ровно по одному изображению каждой области) → присоединены метки из `разметка.xlsx`
по ключу папки. 249 изображений с метками; 3 (эндопротезы, метка пустая) не используются.

Чтобы дообучить на новых данных: добавьте строки в `image_labels.csv` (sha256 пикселей не обязателен —
достаточно `first_source_path`, `study_key`, `region` и меток) и перезапустите `train.py`.

## Новые датасеты (которые вы скачаете)
```sh
python ingest.py --name mydata --root /path/to/downloaded [--pixel-mm 0.6]
```
1. `ingest.py` читает DICOM/PNG/JPG, выбрасывает пиксельные копии и всё, что уже есть в обучающих метках
   (защита от утечки), определяет область и пишет `labels/candidates_mydata.csv` + контактные листы.
   Колонки меток в шаблоне **пустые**: `suggested_*` — лишь подсказки модели для эксперта, метки не выдумываются.
2. Эксперт заполняет `region`, `quality_class` и критерии (0/1; неизвестно — пусто) → `labels/mydata.csv`.
3. Обучение: `python train.py --dataset <organiser> --synthetic rotate --extra mydata=labels/mydata.csv=/path/to/downloaded
   --report-name exp_with_mydata --no-save-model` — сначала как эксперимент.
4. **Метрики всегда считаются только на снимках организатора**, дополнительные данные участвуют лишь в обучении.
   Поэтому прогоны «с» и «без» нового датасета сравнимы напрямую, и внешний набор не может «нарисовать» качество.
   Берите датасет в боевую модель, только если AUC вырос во всех парных повторах (`quality_auc_per_repeat`)
   и ни один критерий не просел; иначе он вредит (другой аппарат, другая подача изображения).
5. Наборы без меток качества (рентгенограммы, сегментации) классификатору напрямую не помогают — ими можно
   улучшать только измерения (ориентиры), и это отдельная работа с отдельной проверкой.

Проверено на реальном внешнем наборе Ramathibodi (Hologic): `ingest.py` → 60 файлов, 40 уникальных, области
определены; `external_validation.py` → `reports/external_ramathibodi.json`.

## Протокол валидации (защита от утечек)
* единица разбиения — папка исследования: позвоночник и оба бедра одного пациента, а также все пиксельные
  копии всегда в одном фолде (PatientID обезличен, надёжнее ключа нет — ограничение зафиксировано);
* `StratifiedGroupKFold(5)` × 3 повтора с разными сидами;
* порог решения для каждого внешнего фолда выбирается по **внутренним** out-of-fold предсказаниям обучающей
  части → F1 в отчёте не подогнан под оцениваемые данные;
* 95 % ДИ — кластерный бутстрап по исследованиям (2000 выборок);
* обычные аугментации не применяются: поворот меняет целевой угол, кроп — охват, отражение — сторону;
* единственное исключение — синтетические повороты качественных снимков позвоночника с **известной по
  построению** меткой оси; они идут в обучение только вместе с родительским снимком и учат только критерий оси
  (остальные метки для них «неизвестно» — иначе чёрные углы портят критерий укладки: проверено экспериментом);
* гиперпараметры фиксированы заранее (без перебора на CV), сид 17.

Артефакты: `models/bundle.joblib`, `reports/validation_metrics.json`, `reports/oof_predictions.csv`.
