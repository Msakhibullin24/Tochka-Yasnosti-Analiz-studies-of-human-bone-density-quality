# Следующий месяц работы: качество DXA, без PACS

## Что говорят имеющиеся данные

Воспроизводимый срез `reports/hip_criterion_audit_2026_09_21.json` использует
150 размеченных снимков бедра из одного уже просмотренного OOF-повтора.
Для критерия «укладка/ротация» — 36 позитивов, 19 TP, 17 FN, 16 FP, 98 TN.
Доступность кандидата большого вертела — 17/36 позитивов и 80/114 негативов;
это **не точность** координат. Лучший из проверенных одиночных признаков —
абсолютный наклон диафиза (описательный AUC 0,775). Текущий признак
`lesser_troch_protrusion_mm` даёт AUC 0,493: его название не делает его
корректным анатомическим измерением. Число миллиметров здесь — выступ над
вычисленной хордой, а не клиническая ширина профиля малого вертела.

Вывод: новый порог по этому признаку или автоматическое правило по недавно
восстановленной точке большого вертела сейчас не оправданы. Наклон диафиза
уже входит в модель; простое повторное добавление признака ничего не решит.
Главная неизвестность — почему маска и анатомические кандидаты ненадёжны
именно на трудных снимках и какие нарушения объединяет общая метка укладки.

## Порядок работы

1. **Разметить технические причины 33 ошибок бедра и сопоставимые верные
   случаи.** Отмечать только наблюдаемые категории: обрезка кости, слияние с
   тазом, ошибка стороны/масштаба, плохой контраст, отсутствие ориентиров,
   расхождение измерения с видимым контуром. Не выдавать эту разметку за
   врачебное заключение. Для каждого случая сохранить изображение с точками,
   исходную метку, score и версию алгоритма.
2. **Сделать измерения устойчивыми.** Проверить контур при небольших
   изменениях яркости, шума и разрешения, которые не меняют анатомию.
   Отдельно оценить левое/правое бедро и отсутствие масштаба. Для нового
   признака малого вертела определить явные условия, когда он недоступен;
   нельзя подменять отсутствие измерения нулём. Сегментацию HipRay и точки
   MTDDH использовать только как кандидаты из другой модальности, пока не
   доказан перенос на целевые DXA.
   Первый стресс-тест выполнен: `HIP_STABILITY_2026_09_21.md`. Наиболее
   проблемны кандидат шейки и расчётный выступ малого вертела; найден также
   единичный крупный срыв измерения оси диафиза. Поиск шейки ограничен
   компонентой бедра, но независимая точность по-прежнему неизвестна.
3. **Проверить гипотезу на парных фолдах.** Сравнить текущий гибрид, вариант
   только с исправленной геометрией и вариант с детектором-кандидатом на
   одинаковых разбиениях по исследованиям. Пороги выбирать внутри обучающей
   части. Показать отдельно общий F1/ROC-AUC/PR-AUC, чувствительность и
   специфичность, FN/FP укладки бедра, число случаев с недоступными
   ориентирами, интервалы по исследованиям. В рабочую модель переносить
   только воспроизводимое улучшение без роста критических пропусков.
4. **Закрывать остальные пункты ТЗ тем же принципом.** Для позвоночника —
   кандидаты Th12 и гребней плюс честный статус «не локализовано»; для
   проекции — распознавание или явное «не определена»; для входной ROI —
   поддерживаемый формат, извлечение, геометрия в мм и проверка связи с
   анатомией. При отсутствии независимой разметки не объявлять эти проверки
   клинически валидированными.
5. **Зафиксировать финальный релиз.** После выбора модели заморозить веса,
   пороги и тестовый протокол; прогнать полный путь DICOM → решение →
   объяснение → CSV/XLSX/SC/SR, повторяемость, лимит времени и отказные
   сценарии. Отдельно репетировать демонстрацию на новых снимках, не
   использованных для подбора порогов.

## Что считать результатом к сдаче

Функциональные проверки должны иметь явный статус: `pass`, `fail` или
`undetermined`, причину и видимое основание. Конкурсные метрики должны
относиться к одному закреплённому протоколу; кандидатные ориентиры и
внутренний аудит нельзя представлять как клиническую точность. Без врача и
закрытой выборки остаётся предел доказательности, который надо показать
жюри честно. Интерфейс и экспорт уже существуют; новые экраны и PACS не
имеют приоритета перед сокращением пропусков и закрытием требований ТЗ.

Повторить численный срез:

```sh
python -m experiments.hip_criterion_audit \
  --oof reports/scope_gate_1_9_pipeline_oof.csv \
  --labels labels/image_labels.csv \
  --dataset /path/to/Исследования \
  --output /path/to/report.json --repeat 0
```
