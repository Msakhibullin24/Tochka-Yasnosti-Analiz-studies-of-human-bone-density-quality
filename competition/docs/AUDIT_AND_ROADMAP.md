# Аудит решения и план развития (18.09.2026)

Принцип: каждое улучшение принимается только парным экспериментом на тех же фолдах
(`quality_auc_per_repeat`), оценка — только на реальных снимках организатора. Правило приёма, зафиксированное
заранее: итоговый AUC вырос во всех повторах **и** ни один критерий не просел больше чем на 0.03.

## 1. Аудит по критериям жюри

| Критерий ТЗ | Состояние | Главный риск / что добрать |
|---|---|---|
| 8.1 Подход | таксономия = закрытый список организатора; дедупликация 247 копий; разбиение по исследованиям; негативный контроль утечки | нет независимости пациентов (PatientID обезличен) — ограничение названо |
| 8.2 Техника | устойчивое чтение DICOM, 33 теста, враждебные архивы, детерминизм, полный lock зависимостей | **Docker-образ ни разу не собирался** (запрет на загрузки) — риск №1 всей сдачи |
| 8.3 Соответствие | 8 колонок ТЗ + согласованный `quality_prob`; области и метки — точные строки куратора; пакет, API, UI, SC, SR | «автокоррекция разметки с подтверждением» не реализована (доп. функционал) |
| 8.4 Метрики | AUC ≈ 0.79–0.80, F1 ≈ 0.58; 95 % ДИ; по областям и типам | потолок = 100 исследований и шум меток; слабое место — ротация бедра (пропущено 18 из 36) |
| 8.5 Питч | `APPROACH.md` — готовый сценарий | нет слайдов и отрепетированного демо |

## 2. Что проверено экспериментами в этой итерации

| Гипотеза | Результат (позвоночник, AUC класса качества) | Решение |
|---|---|---|
| Синтетические повороты 7–12° учат критерий оси | 0.785 → 0.802, рост во всех 3 повторах | **принято** |
| То же + синтетическая обрезка гребней (метки только целевого критерия) | 0.802 → 0.807, рост не во всех повторах; критерий укладки 0.86 → 0.81 | отклонено (`exp_synthetic_both_v2.json`) |
| Артефакт важен только в зоне L1–L4 | наоборот: сигнал в **верхних 15 % кадра** (косточки белья): одномерный AUC 0.93 против 0.91, для класса качества 0.75 против 0.66 | гипотеза опровергнута, найден признак |
| Признаки top-hat верхней зоны в критерии артефактов | 0.802 → 0.814, рост во всех 3 повторах; F1 артефактов 0.74 → 0.79; ничего не просело | **принято** (`exp_before_top_artifact.json` vs `validation_metrics.json`) |
| Скор контралатерального бедра как контекст | +0.01, шум | отклонено |
| Внешний набор Hologic (Ramathibodi) в обучение | другая подача снимка, измерения переносятся на AUC 0.58–0.72 | только внешняя проверка |
| Триаж «авто-принять / на просмотр» | при чувствительности ≥ 95 % авто-принять можно лишь 17–26 % снимков (NPV 0.93–0.96) | пока не продуктовая фича: станет осмысленной при AUC ≥ 0.9 |

Оговорка о честности: признаки верхней зоны найдены при просмотре ошибок на всём наборе, т. е. оценка чуть
оптимистична (как и для остальных признаков — это указано в `APPROACH.md`). Защита — парная проверка и ДИ.

## 3. Новые функции, добавленные сейчас

1. **Анализ в динамике** (`dxaqc/dynamics.py`, `POST /api/v1/compare`). Два визита → проверка сопоставимости
   укладки по измерениям (наклон оси, центрирование, протяжённость скана; для бедра — угол диафиза, выступ
   малого вертела = ротация, отступы, сторона) → `comparable / review / not_comparable` с причинами. Если оператор
   вводит МПК, изменение сравнивается с LSC (2.77 × CV, методрекомендации 4.3) и объявляется значимым **только
   при сопоставимых снимках**. МПК из пикселей не вычисляется никогда.
   Статус: логика покрыта тестами; допуски — инженерные значения по критериям ТЗ, **клинически не валидированы**:
   в данных организатора нет повторных исследований одного пациента (проверено поиском близкой анатомии).
   Для валидации нужны 30+ пар «исходное–повторное».
2. **Список меток на перепроверку** (`review_candidates.py` → `reports/label_review.csv` + лист). Уверенные
   расхождения честных OOF-предсказаний с экспертом. При 249 снимках каждая спорная метка стоит заметной доли AUC;
   типичные находки — «норма» при видимых косточках белья и сколиоз. Метки автоматически не меняются.
3. **Приём новых датасетов** (`ingest.py`, `train.py --extra`) — см. `TRAINING.md`.

## 4. План: что поднимет результат (по убыванию отдачи)

| # | Действие | Ожидаемый эффект | Цена |
|---|---|---|---|
| 1 | Собрать и прогнать Docker-образ на чистой машине (`./run.sh build && ./run.sh test && ./run.sh batch`) | снимает единственный риск «у организатора не запустилось» | 30 мин, нужна сеть |
| 2 | Отдать эксперту `label_review.csv` (30 снимков) и уточнить у куратора правило «сколиоз ≠ нарушение оси» | прямой рост AUC/F1: шум меток — главный потолок | 1–2 часа эксперта |
| 3 | Разметка 6 ориентиров на 150 снимках бедра (вершина большого вертела, малый вертел, ось шейки, ось диафиза, низ седалищной кости) → точные измерения вместо контурных эвристик | ротация бедра — 36 из 41 нарушения бедра; сейчас AUC 0.73 | 3–4 часа разметки + день кода |
| 4 | Больше размеченных исследований того же аппарата (запросить у организатора / партнёрской клиники) | самый сильный рычаг; сужает ДИ | зависит от доступа |
| 5 | Калибровка вероятностей (Platt во вложенной CV) + отчёт Brier/ECE | AUC не меняет; стабилизирует порог F1 и делает `quality_prob` интерпретируемым | полдня |
| 6 | Тест устойчивости к яркости/шуму/масштабу (стабильность вердикта) | аргумент для 8.2, находит хрупкие признаки | полдня |

## 6. Что сознательно НЕ делаем
* Большие нейросети end-to-end на 249 снимках — линейная проба CNN уже показывает потолок (AUC 0.5 по оси).
* Дообучение на наборах без меток качества укладки или с другой подачей изображения.
* Любые «демо-данные» в интерфейсе: старый React-интерфейс (`src/data.ts`) содержит выдуманных пациентов и в сдачу
  входить не должен, пока не подключён к API `dxaqc`.
