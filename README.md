# Osseo AI — контроль качества DXA

Основной продукт — локальное рабочее место для проверки DICOM позвоночника и бедра в
`competition/`. React-интерфейс, FastAPI и базовые release-веса поставляются одним
контейнером. Старый total-body/Hologic-workbench сохранён отдельно для исследований.
PACS в текущий объём разработки не входит.

## Рабочий процесс

1. Загрузить DICOM-файлы либо один ZIP.
2. Посмотреть результат пакета и причины ошибок обработки.
3. Открыть исходное изображение без наложений, включить ориентиры, проверить критерии и измерения.
4. Исправить координаты ориентиров/ROI, сохранить черновик или подтвердить решение специалиста.
5. Скачать машинные CSV/XLSX/DICOM-серии либо отдельный экспертный CSV, историю правок и отчёт для печати.
6. Открыть автоматически составленное описание находок по исследованию или сравнить два визита в разделе «Анализ в динамике двух DXA»; оба текста можно скачать.

Пакеты и экспертные версии сохраняются после перезапуска. Машинный результат не переписывается
экспертной правкой. Конкурентное сохранение устаревшей версии отклоняется.

## Запуск

```sh
./competition/run.sh build
./competition/run.sh serve 8090
```

Открыть http://127.0.0.1:8090. По умолчанию данные сохраняются в `competition/out/`.
Другую папку задаёт `DXAQC_DATA=/absolute/path ./competition/run.sh serve 8090`.
Для переноса текущей сборки без сети: `docker save osseo-dxaqc:1.11.6 -o osseo-dxaqc.tar`, затем `docker load -i osseo-dxaqc.tar`.

Альтернатива: `make docker-up` — интерфейс http://127.0.0.1:8080, данные `data/runtime/`.

Пакетный режим без сети:

```sh
./competition/run.sh batch /absolute/input.zip /absolute/output
```

Разработка: `uv` и Python 3.11; Node.js 22.14+ и `pnpm`. Выполните `make setup`, затем
`make dev`. Интерфейс http://127.0.0.1:5173, API http://127.0.0.1:8001.
`make verify` проверяет оба backend, интерфейс и сборку.

Generated-кэши и результаты запусков не являются исходниками. Посмотреть границы каталогов,
команды и безопасную очистку можно в [карте проекта](docs/PROJECT_MAP_RU.md); очистка выполняется
через `make clean-generated` (сначала dry-run) или `make clean-generated APPLY=1`.

## Область доказанности

Текущая техническая сборка **1.11.6**, профиль **tz-delivery-1.11.6**.
[Паспорт выпуска](docs/CURRENT_RELEASE.json),
[полная сверка ТЗ и результаты обновления](docs/TZ_AUDIT_AND_METRIC_UPGRADE_2026_10_03_RU.md).
Веса включены в образ, запуск не требует локального `data/`.
В 1.11.6 устранён повторный расчёт признаков левого бедра; медицинские веса и
решения сохранены. Исправлена упаковка исследовательских инструментов и ресурсов
анатомической разметки; усилена проверка кандидатов по всем доступным QC-метрикам.

**ТЗ закрыто частично.** Th12, края подвздошных костей, нумерация L1–L4,
проекция бедра, отдельные подтипы ротации и анатомическая корректность исходной
ROI не имеют завершённой независимой проверки. `requirements_complete=false`
сохраняется. Положительный QC не является клиническим диагнозом; модель не
вычисляет BMD по картинке. `Failure` означает отказ обработки с пустыми классом
и вероятностью и учитывается отдельно от медицинского нарушения.

Исторический внутренний OOF после строгого ограничения оси: 249 изображений,
100 исследований, F1 **0,592**, ROC-AUC **0,790**, чувствительность **0,616**,
специфичность **0,807**, macro-F1 типов **0,482**. Это post-hoc оценка ранее
изученной выборки; независимость пациентов и клиническая переносимость не
подтверждены. Пропущены 28 из 73 положительных случаев, в том числе 9 из 10
нарушений оси. [Полные показатели и 95% интервалы](docs/competition/quality_axis_guard_internal_oof_2026_10_03.json).
Новые исследовательские кандидаты не дали совместного улучшения и не заменяют
рабочие медицинские веса.

В каждом пакете есть `requirements.json` и `timing.json`, учитывающий подготовку,
таблицы и упаковку SC/SR. Валидность конкурсного CSV проверяется отдельно от
полноты анатомических требований. `./competition/run.sh batch INPUT OUTPUT complete`
сохраняет отчёты и возвращает код 3 при незакрытых обязательных проверках;
по умолчанию используется `submission`. Для независимой проверки полноты
использовать `results_extended.csv` с манифестом входа, а строгие колонки проверять
по `submission.csv` или строгому `results.csv`.

Масштаб организатора без `PixelSpacing`: Y=1,05 мм, X=0,6 мм согласно разъяснениям
V2. Источник масштаба сохраняется в отчёте. У других аппаратов нужен отдельный
контроль калибровки и качества. Замер на целевом H200 ещё не выполнен.

Исторический паспорт 1.11.0 сохранён в `docs/RELEASE_1_11_0.json`; прежние отчёты
и показатели иных моделей остаются архивными. [Автоматические описания](docs/AUTOMATIC_STUDY_DESCRIPTION_RU.md).

## Подготовка GPU-ПК и следующий цикл качества

[Полный план](docs/GPU_FULL_PROJECT_UPGRADE_PLAN_2026_10_03_RU.md) содержит порядок
MedSigLIP-448 → DINOv3-B/L → частичное дообучение → экспертная анатомия,
условия перехода к H+/7B и приёмку каждого оставшегося пункта ТЗ.
Исполняемый комплект: `competition/gpu_research/` — отдельное CUDA-окружение,
загрузка/хеши моделей, frozen nested QC, multi-label fine-tuning, dense mask heads
на подтверждённых контурах и проверяемый перенос данных.

```sh
bash competition/gpu_research/bootstrap.sh
.venv-gpu/bin/python competition/gpu_research/suite.py --stage frozen \
  --models medsiglip dinov3-b --download \
  --dataset /absolute/Исследования --output data/gpu-runs/frozen-v1
```

Данные и большие веса не переносятся через Git. Инструкция отдельного переноса
есть в плане. Новые инструменты исследовательские: GPU-прогоны и прирост качества
ещё не измерены, кандидаты не заменяют медицинские веса автоматически.

## Обучение и метрики специализированных моделей

```sh
make train-specialists INPUT='/path/to/Исследования' OUTPUT=data/specialists/experiments/new-run
make metrics-specialists METRICS_DIR=data/specialists/experiments/new-run/report
```

Отчёт доступен на `http://127.0.0.1:8092`: loss по эпохам, ROC/PR, матрицы ошибок,
метрики JSON/CSV. Обучаются QC-головы над замороженными ConvNeXt-V2 / EfficientNet-B4.
Для обучения YOLO26x нужны проверенные DXA bbox/mask-аннотации; формат и команды —
в [инструкции обучения](competition/docs/SPECIALISTS.md).

Региональное дообучение, парное сравнение с гибридом и пакет экспертной разметки:
`make advance-specialists INPUT=... OUTPUT=...`. Подробности и ограничения авторских моделей —
в [инструкции специализированных моделей](competition/docs/SPECIALISTS.md).
