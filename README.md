# Osseo AI — контроль качества DXA

Основной продукт — локальное рабочее место для проверки DICOM позвоночника и бедра в
`competition/`. React-интерфейс, FastAPI и базовые release-веса поставляются одним
контейнером. Старый total-body/Hologic-workbench сохранён отдельно для исследований.
PACS в текущий объём разработки не входит.

## Рабочий процесс

1. Загрузить DICOM-файлы либо один ZIP.
2. Посмотреть результат пакета и причины ошибок обработки.
3. Открыть исходное изображение без наложений, включить ориентиры, проверить критерии и измерения.
4. Исправить координаты ориентиров/ROI, сохранить черновик или подтвердить решение специалиста.
5. Скачать машинные CSV/XLSX/DICOM-серии либо отдельный экспертный CSV, историю правок и отчёт для печати.
6. Открыть автоматически составленное описание находок по исследованию или сравнить два визита в разделе «Анализ в динамике двух DXA»; оба текста можно скачать.

Пакеты и экспертные версии сохраняются после перезапуска. Машинный результат не переписывается
экспертной правкой. Конкурентное сохранение устаревшей версии отклоняется.

## Запуск

```sh
./competition/run.sh build
./competition/run.sh serve 8090
```

Открыть http://127.0.0.1:8090. По умолчанию данные сохраняются в `competition/out/`.
Другую папку задаёт `DXAQC_DATA=/absolute/path ./competition/run.sh serve 8090`.
Для переноса текущей сборки без сети: `docker save osseo-dxaqc:1.11.5 -o osseo-dxaqc.tar`, затем `docker load -i osseo-dxaqc.tar`.

Альтернатива: `make docker-up` — интерфейс http://127.0.0.1:8080, данные `data/runtime/`.

Пакетный режим без сети:

```sh
./competition/run.sh batch /absolute/input.zip /absolute/output
```

Разработка: `uv` и Python 3.11; Node.js 22.14+ и `pnpm`. Выполните `make setup`, затем
`make dev`. Интерфейс http://127.0.0.1:5173, API http://127.0.0.1:8001.
`make verify` проверяет оба backend, интерфейс и сборку.

Generated-кэши и результаты запусков не являются исходниками. Посмотреть границы каталогов,
команды и безопасную очистку можно в [карте проекта](docs/PROJECT_MAP_RU.md); очистка выполняется
через `make clean-generated` (сначала dry-run) или `make clean-generated APPLY=1`.

## Область доказанности

Текущая рабочая сборка **1.11.5**, профиль **tz-delivery-1.11.5**. Полный
паспорт предыдущей поставки 1.11.0 сохранён в `docs/CURRENT_RELEASE.json`;
ограничения и проверки новой сборки перечислены в
`docs/DXA_ONLY_TZ_STATUS_2026_09_28_RU.md`. Контейнер
включает базовую модель v5, модели проекции и анатомических масок, а также обученный
пересмотр положительных ответов без типа. Все веса и профиль входят в образ;
файлы из локального `data/` для запуска не нужны. Проверка проекции выполняется
до классификации: боковая или неопределённая проекция позвоночника получает
`Failure` с причиной отказа. `Failure` — отказ обработки с пустыми классом и
вероятностью, а не медицинское нарушение.

Начиная с 1.11.2 неуверенная сторона бедра допускается к проверке только при согласии
наиболее вероятной стороны модели с однозначной меткой стороны в DICOM.
На внешних Hologic BMD это устранило три технических отказа: 60/60 обработаны,
но независимых меток качества для них нет. В 1.11.3 дополнительно исправлен
`path_to_study` в архивах с обёртками и копиями исследований. В 1.11.4
устранён обход порога оси 5° во вторичном пересмотре. В 1.11.5 добавлены
описания находок и динамики в интерфейс; API динамики больше не объявляет
изменение МПК значимым при неподтверждённой сопоставимости. Подробности —
в отчёте DXA выше. [Как устроены автоматические описания](docs/AUTOMATIC_STUDY_DESCRIPTION_RU.md).

Вторичная модель может определить тип либо пересмотреть тревогу как норму.
На ранее просмотренном внутреннем OOF F1 меняется с 0,580 до 0,601,
чувствительность — с 0,699 до 0,630, ROC-AUC — с 0,801 до 0,790,
macro-F1 типов — с 0,488 до 0,479 в исторической 1.11.3. После строгого
ограничения оси постфактум OOF F1 составляет 0,592, чувствительность 0,616.
Это явный компромисс качества, не новая
независимая валидация поставки. Основные анатомические проверки ещё не завершены.
План и проверенные изменения: [этапы закрытия ТЗ](docs/TZ_COMPLETION_PROGRESS_2026_09_27_RU.md).
Сводка всех измеренных показателей и их протоколов: [метрики DXA QC на 29.09.2026](docs/PROJECT_METRICS_2026_09_29_RU.md).

Пакетный скрипт возвращает код 3 при невалидной таблице или отказах обработки.
Для строгой приёмки всех требований CLI поддерживает `--acceptance complete`:
при неполном анатомическом покрытии отчёты сохраняются, а команда завершается
кодом 3. Валидная таблица и полное выполнение ТЗ проверяются отдельно.

Актуальные метрики, образ, два офлайн-прогона и границы соответствия приводятся в
[паспорте предыдущей поставки](docs/CURRENT_RELEASE.json) и
[отчёте доработок](docs/TZ_ALIGNMENT_2026_09_26_RU.md). Этот отчёт описывает прежнюю
поставку 1.10.0. Историческая оценка v4
(F1 0,577; ROC-AUC 0,801) не является метрикой текущего бинарного решения.
Поставляемые веса обучены на 100 исследованиях / 249 размеченных уникальных
изображениях организатора; независимой клинической валидации нет.

Каждый пакет содержит `requirements.json` с покрытием требований и `timing.json`
с временем полного пакета, включая подготовку, таблицы и упаковку серий.
Верхняя граница на исследование консервативно включает весь общий накладной расход.
Валидный CSV не подтверждает полноту анатомической проверки. Th12/L1–L4,
проекция и анатомическая корректность ROI пока требуют независимого эталона.

Редактор ROI и линейные измерения реализованы. Точный обученный локализатор, клиническая
проверка нанесённой разметки и доказанная переносимость на другие аппараты пока не заявляются.
Для снимков организатора без `PixelSpacing` используется согласованный масштаб Y=1,05 мм и X=0,6 мм.
У других аппаратов возможны `ExposedArea` или явно обозначенное допущение; источник масштаба
сохраняется в расширенном отчёте. Результаты требуют проверки специалистом. Модель не вычисляет BMD по картинке.

## Обучение и метрики специализированных моделей

```sh
make train-specialists INPUT='/path/to/Исследования' OUTPUT=data/specialists/experiments/new-run
make metrics-specialists METRICS_DIR=data/specialists/experiments/new-run/report
```

Отчёт доступен на `http://127.0.0.1:8092`: loss по эпохам, ROC/PR, матрицы ошибок,
метрики JSON/CSV. Обучаются QC-головы над замороженными ConvNeXt-V2 / EfficientNet-B4.
Для обучения YOLO26x нужны проверенные DXA bbox/mask-аннотации; формат и команды —
в [инструкции обучения](competition/docs/SPECIALISTS.md).

Региональное дообучение, парное сравнение с гибридом и пакет экспертной разметки:
`make advance-specialists INPUT=... OUTPUT=...`. Подробности и ограничения авторских моделей —
в [инструкции специализированных моделей](competition/docs/SPECIALISTS.md).
