# Перенос на RTX 5090 и подготовка обучения

## Статус

RTX 5090 находится на другой машине; доступа к ней в текущей сессии нет. На текущей машине проверен CPU forward/backward тест и выполнен вспомогательный study-level baseline; см. [результаты](EXTERNAL_DATASETS_VERIFIED_RU.md). GPU-инструкция подготовлена, но её выполнение на 5090 и скорость обучения пока не проверены. Полноценный train-loop конкурсного классификатора следует реализовать после подготовки подтверждённых меток; приведённая ниже команда не обучает модель качества.

## Окружение

Рабочая отправная конфигурация: Linux x86_64, Python 3.11, отдельный virtualenv, PyTorch 2.7.1 + torchvision 0.22.1 из CUDA 12.8 index. Это зафиксированный стартовый профиль, не утверждение о самой новой версии. Blackwell поддерживается с PyTorch 2.7, а официальная страница прошлых версий содержит указанную пару пакетов. [PyTorch 2.7](https://pytorch.org/blog/pytorch-2-7/), [команды установки](https://pytorch.org/get-started/previous-versions/).

RTX 5090 имеет 32 GB памяти по спецификации NVIDIA. Этого достаточно, чтобы исследовать предложенные компактные модели при разумном batch size, но конкретный batch и время должны определяться замерами. [Спецификация NVIDIA](https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5090/).

Не устанавливать новый Torch поверх `backend/.venv`: там старый MMPose/MMCV-контур. На GPU-машине из корня копии проекта:

```bash
nvidia-smi
uv venv .venv-5090 --python 3.11
uv pip install --python .venv-5090/bin/python torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128
uv pip install --python .venv-5090/bin/python -r backend/requirements-training.txt
mkdir -p data/training-environment
.venv-5090/bin/python backend/scripts/check_training_device.py --device cuda > data/training-environment/device-check.json
uv pip freeze --python .venv-5090/bin/python > data/training-environment/requirements-resolved.txt
nvidia-smi > data/training-environment/nvidia-smi.txt
```

При ошибке CUDA сначала проверить драйвер, видимость устройства, версии wheel/runtime; не обходить проверку принудительным объявлением устройства поддерживаемым. Успешный запуск должен сообщить название устройства, CUDA runtime, compute capability, проверку конечности loss/градиентов и результат шага оптимизатора. Это проверка вычислений, не бенчмарк качества модели. Установка зависимостей использует интернет, медицинские изображения этим командам не передаются.

Полный транзитивный lock пока не зафиксирован: `uv pip freeze` выше сохраняет фактически установленное окружение для последующего воспроизводимого образа. Финальный Docker base image и зависимости фиксируются после успешного GPU-прогона; текущая инструкция не является окончательным конкурсным контейнером.

## Что переносить

1. Репозиторий с кодом и документацией.
2. `data/competition-v1/` целиком: manifest, исходные связи, изображения и CSV. Это отдельный локальный набор, он не входит в Git.
3. Подтверждённую врачом копию review-таблицы, решения спорных случаев, версию labelbook и замороженные группы.
4. Исходные DICOM и XLSX — для полного повторения импорта и финального теста чтения. PNG сохраняют пиксели текущего релиза, но не заменяют тестирование входного DICOM-контракта.

Никакой передачи на удалённую машину здесь не выполнялось. Архив подготовки находится в `data/competition-preparation-v1.zip`; контрольные суммы — рядом. Упакованные данные не следует публиковать вместе с открытым кодом. Пакет не является инструментом полного обезличивания DICOM.

## Повторение подготовки на текущем CPU-окружении

Из корня проекта:

```bash
PYTHONPATH=backend backend/.venv/bin/python -m app.competition_data \
  --source '/home/robot/Downloads/Датасет/НД_для_обучения/Исследования' \
  --labels '/home/robot/Downloads/Датасет/НД_для_обучения/разметка.xlsx' \
  --output data/competition-v2
```

Новый каталог обязателен: скрипт отказывается перезаписывать старый. В GPU-окружении этот модуль не запускается без остальных backend-зависимостей: он использует существующий проектный helper. Для обучения подготовленные PNG/JSON/CSV можно читать независимо от старого backend.

## Начальный профиль будущего обучения

- Вход 320×320, letterbox, три одинаковых grayscale-канала для pretrained RGB encoder, без center crop.
- Encoder ResNet18 с локальными ImageNet-весами; источник, условия использования и SHA-256 записываются до запуска. Случайная инициализация — контрольный эксперимент, а не основной выбор для 252 изображений.
- Сначала заморозить encoder; затем отдельный эксперимент с размораживанием последнего блока и меньшим learning rate. При замороженном encoder зафиксировать и статистики BatchNorm.
- Головы: область/сторона, бинарное качество, применимые нарушения. Loss по отсутствующим и неприменимым меткам маскируется.
- Начальные гиперпараметры-гипотезы: AdamW, LR голов 1e-3, LR encoder 1e-5…1e-4, weight decay 1e-4. Максимум 50 эпох и patience 8 для внутренней валидации; уточнить по learning curves.
- Начать с batch 16, затем подобрать 32/64 по измеренной памяти; увеличение batch не считать улучшением качества.
- BF16 — после успешной проверки на GPU; FP32 — контроль воспроизводимости. На столь малом наборе `torch.compile` и распределённое обучение не нужны до профилирования.
- Seed 17 для первого сравнения; победившие конфигурации повторить с 29 и 43. Не выбирать seed по лучшей внешней метрике.
- Сохранять train/inner-val curves, лучший по внутренней проверке checkpoint, вероятность каждого внешнего изображения и агрегаты по исследованиям.

Порог, эпоха и калибровка выбираются внутри train-части внешнего фолда. До фиксации групп не запускать массовый поиск параметров. `candidate_folds.json` ещё не является финальным split.

## Готовность к настоящему запуску

Требуются: подтверждённые связи изображений и областей; решение по спорным/пропущенным меткам; проверка похожих исследований; финальная версия групп; отдельное GPU-окружение; реализованный train/eval-loop с проверкой отсутствия групповой утечки.
