# API конкурсного DXA QC 1.11.0

Основной сервис — `competition/dxaqc/api.py`. React и API поставляются одним
локальным контейнером. Исследовательский total-body API сохранён в
[историческом контракте](LEGACY_API.md).

## Пакетная обработка

`POST /api/v1/batch` принимает `multipart/form-data`, поле `files`: несколько
DICOM или один ZIP. Смешивать ZIP и отдельные DICOM нельзя. По умолчанию ответ
возвращает задание; `?wait=true` ожидает его завершения. Лимит загрузки по умолчанию
8 ГиБ, задаётся `DXAQC_MAX_UPLOAD_MB`.

`POST /api/v1/batch/path` принимает JSON `{"input_path":"/data/input"}`.
Путь должен находиться внутри `DXAQC_INPUT_ROOT` (по умолчанию `/data`).
Есть тот же параметр `wait`. Доступ к исходным файлам только локальный.

| Endpoint | Результат |
|---|---|
| `GET /health` | Доступность HTTP |
| `GET /api/v1/ready` | Веса, worker, БД, запись и место на диске |
| `GET /api/v1/catalog` | Области и критерии |
| `GET /api/v1/jobs` | История заданий |
| `GET /api/v1/jobs/{id}` | Статус, прогресс, summary |
| `GET /api/v1/jobs/{id}/rows` | Машинные строки |
| `GET /api/v1/jobs/{id}/worklist` | Строки с состоянием экспертной проверки |
| `POST /api/v1/jobs/{id}/cancel` | Отмена оставшейся обработки |
| `POST /api/v1/jobs/{id}/reprocess` | Новое задание из сохранённых исходников |
| `GET /api/v1/jobs/{id}/source.zip` | Сохранённые исходные DICOM |

## Артефакты

`GET /api/v1/jobs/{id}/{name}` разрешает только известные артефакты:
`results.csv`, `results.xlsx`, `results_extended.csv`, `submission.csv`,
`submission.xlsx`, `submission_validation.json`, `requirements.json`,
`timing.json`, `additional_series.zip`, `summary.json`.

`submission.csv/xlsx` содержит восемь полей §2.5 ТЗ и согласованный `quality_prob`.
В расширенном CSV дополнительно сохраняются основания, ориентиры, масштаб,
статусы проверок и ошибки. Отсутствие установленного типа при классе 1 явно
отмечается, строгий валидатор отклоняет незавершённую типизацию. Failure имеет
пустые класс, вероятность и тип; причины доступны в расширенном отчёте.

`requirements.json` отделяет незавершённые обязательные проверки от валидности
CSV. `timing.json` учитывает полный пакет и общие расходы; это локальный замер,
не результат проверки на официальной H200-ВМ.

Подробный [контракт исходной ROI](ROI_INPUT_CONTRACT_RU.md) отделяет локальные
соглашения о назначении зон от неизвестного контракта организатора.

## Изображение и экспертная версия

| Endpoint | Результат |
|---|---|
| `POST /api/v1/analyze` | Один файл (`file`) → модельный JSON и assessment |
| `GET /api/v1/jobs/{id}/images/{row_id}` | Исходная сетка, масштаб, geometry, assessment |
| `GET /api/v1/jobs/{id}/images/{row_id}/original.png` | Нормализованный preview без наложений |
| `POST /api/v1/jobs/{id}/images/{row_id}/geometry-evaluation` | Геометрические отступы полигонов |
| `GET/POST /api/v1/jobs/{id}/images/{row_id}/reviews` | История / новая версия специалиста |
| `GET /api/v1/jobs/{id}/reviewed.csv` | Отдельные решения специалиста |
| `GET /api/v1/jobs/{id}/reviews.json` | История правок |
| `GET /api/v1/jobs/{id}/review-package.zip` | Пакет экспертной проверки |
| `GET /api/v1/jobs/{id}/report.html` | Отчёт для просмотра и печати |

Сохранение использует `expected_revision`; устаревшая версия получает HTTP 409.
Правка специалиста не переписывает исходный машинный CSV. Для полного формата
экспертной версии см. `competition/dxaqc/review.py` и OpenAPI `/docs`.

Проекция, исходная ROI и обязательные проверки находятся в `assessment`.
Кандидат ориентира не является подтверждённой анатомией. Отрицательный класс
не подтверждает полноту контроля. Данный API не вычисляет BMD из картинки.

## Ошибки

Недопустимая загрузка — 422, превышение размера — 413, неизвестный локальный путь —
404, ошибка доступа к рабочему каталогу — 507, конфликт экспертной версии — 409.
Ошибочный DICOM внутри пакета получает строку Failure; остальные изображения
продолжают обрабатываться. Подробные причины содержатся в расширенном отчёте.

### Проверяемый профиль дополнительных моделей

Для текущего конвейера задайте абсолютный `DXAQC_WORKFLOW_PROFILE` перед стартом API. Код, базовая модель и все компоненты сверяются с SHA-256 профиля до загрузки. Идентификатор доступен в `/api/v1/ready`, ответе одиночного анализа и сводке пакетного задания. Если проверка не проходит, readiness сообщает ошибку. Отдельные переменные путей моделей остаются совместимым способом запуска без общего паспорта.

Анатомические кандидаты содержат точный `raster` (shape, origin, runs) отдельно от полигона предложения ROI. Общая проверка яркости бедра имеет область `heuristic_geometry_only`; она не подтверждает устойчивость нейросетевой маски. Состояние `undetermined` сохраняется для неподтверждённых критериев.

[Сборка, запуск и состояние ТЗ](RUNTIME_WORKFLOW_AND_TZ_STATE_2026_09_26_RU.md).

Поставка 1.11.0 включает профиль `tz-delivery-1.11.0` и полный комплект весов. Вторичный пересмотр может определить тип либо отменить тревогу; его снижение чувствительности отражено в MODEL_CARD. Проекция позвоночника проверяется до QC. Явная исходная ROI охвата с известным масштабом влияет на результат при нарушении отступов; ROI шейки требует отдельной анатомической проверки.

В новых результатах `assessment.source_roi.neck_geometry` содержит физические
измерения явной ROI шейки. В расширенном CSV они вложены в
`source_roi_assessment`. Поля угла могут быть null при отсутствии отдельной
оси шейки; `clinical_verdict=undetermined` не является успешной проверкой.
