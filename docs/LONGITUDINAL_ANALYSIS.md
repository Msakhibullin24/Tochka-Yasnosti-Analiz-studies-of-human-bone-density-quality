# Анализ денситометрии в динамике

## Что реализовано сейчас

В UI есть воспроизводимый демонстрационный модуль follow-up для трёх сценариев:

1. качественные и сопоставимые исследования — рассчитывается значимое изменение относительно LSC;
2. пограничная укладка или ROI — показывается числовой расчёт, но клиническая интерпретация блокируется до коррекции;
3. отклонённое по качеству исследование — сравнение запрещается и рекомендуется повторное сканирование.

Все BMD в демонстрационных кейсах предполагаемые. Они нужны для проверки продуктовой логики и не извлечены из DICOM Pixel Data. UI, JSON-экспорт и model card явно маркируют этот статус.

## Клиническая логика

ISCD рекомендует оценивать серийные измерения через precision assessment и least significant change конкретного учреждения. В follow-up отчёте указывают baseline/предыдущее исследование и ROI, абсолютное изменение BMD в g/cm², процентное изменение и LSC. Если изменение не достигает LSC, его не следует описывать как значимое. При смене системы количественное сравнение возможно только после cross-calibration; без неё новое измерение становится новой baseline.

Источники:

- [ISCD Official Adult Positions 2023](https://iscd.org/official-positions-2023/);
- [ISCD Best Practices for DXA measurement and reporting](https://iscd.org/wp-content/uploads/2021/08/Best-Practices-DXA-Article.pdf);
- [ISCD DXA Atlas: изменение размера lumbar ROI во времени](https://iscd.org/dxaatlas/change-of-size-of-lumbar-spine-region-of-interest-over-time/);
- [ISCD DXA Atlas: различия global hip ROI](https://iscd.org/dxaatlas/follow-up-differences-in-hip-global-region-of-interest/).

## Формулы и decision table

```text
absoluteChange = currentBmd - baselineBmd
percentChange  = absoluteChange / baselineBmd × 100

if comparisonStatus != comparable → not-comparable
else if percentChange >=  LSC → significant-gain
else if percentChange <= -LSC → significant-loss
else → stable
```

| Quality gate | ΔBMD относительно LSC | Выход |
| --- | --- | --- |
| Пройден | `Δ ≥ +LSC` | Значимый прирост |
| Пройден | `−LSC < Δ < +LSC` | Без значимых изменений |
| Пройден | `Δ ≤ −LSC` | Значимое снижение |
| Нужна коррекция | любое | Не интерпретируется до review |
| Критический gate не пройден | любое | Сравнение заблокировано |

Пороговые значения 5,3% для L1–L4, 5,0% для Total Hip и 6,9% для шейки бедра в демо — верхние границы минимально приемлемого LSC из best-practices ISCD, а не измеренная точность конкретной клиники.

## Обязательные входы продукционной версии

- стабильный псевдоним пациента и корректный pair matching;
- одинаковая анатомическая область и сторона;
- дата, аппарат, серийный номер, ПО и протокол;
- структурированные BMD и ROI по каждому сайту;
- версия алгоритма производителя или источник извлечения;
- facility/device/operator-specific LSC с датой действия;
- запись cross-calibration при смене аппарата;
- quality status и подтверждение/коррекция экспертом каждого исследования.

## Пять quality gates

1. **Protocol:** область, сторона и проекция совпадают.
2. **Device:** тот же аппарат или допустимая система того же технологического семейства.
3. **Cross-calibration:** есть валидная запись, если аппарат менялся.
4. **Positioning:** оси, ротация, охват и масштаб сопоставимы.
5. **ROI:** одинаковая нумерация и правила исключения позвонков, границы femoral neck/total hip и площадь ROI.

Критический сбой переводит пару в `not-comparable`. Исправимая ошибка ROI или пограничная укладка — в `review`, после ручного исправления выполняется пересчёт с сохранением audit trail.

## Что ещё требуется для реального продукта

1. Реестр LSC с версионированием, сроком действия и привязкой к аппарату/технологу.
2. Vendor-adapters для надёжного чтения BMD/ROI из SR, secondary capture и private tags; яркость пикселя не является BMD.
3. Patient-level timeline и автоматический выбор только допустимых baseline-кандидатов.
4. Регистрация изображений и измеримые признаки расхождения ROI/укладки.
5. Cross-calibration workflow и автоматический запрет сравнения при истёкшей записи.
6. Экспертное подтверждение, история правок и электронная подпись результата.
7. Независимая валидация отдельно по аппарату, клинике, протоколу и длительности интервала.
8. Мониторинг дрейфа BMD, доли `not-comparable`, повторных сканирований и ошибок pair matching.

## Критерии приёмки

- система никогда не соединяет исследования разных пациентов или сторон;
- отклонённое исследование не может породить clinical trend status;
- аппарат без cross-calibration не сравнивается количественно;
- любое изменение порога LSC версионируется и воспроизводится;
- все значения на графике доступны в таблице и JSON;
- эксперт видит исходные причины решения и может исправить ROI с аудитом;
- итог не называется диагнозом и не заменяет медицинское заключение.
