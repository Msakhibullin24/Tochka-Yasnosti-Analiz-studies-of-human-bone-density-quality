# Проверка ТЗ Минздрава и обновление проекта — 03.10.2026

**Проект не закрывает ТЗ полностью.** Реализован работоспособный локальный
сервис, но обязательные анатомические критерии и независимая точность ещё
не подтверждены. Техническая версия 1.11.6 сохраняет `requirements_complete=false`.
Повышение всех медицинских метрик одновременно в этом обновлении не достигнуто.

Проверены исходные материалы из `Вся информация по задаче МинЗдрав РФ`:
`4. ДепЗдрав.pdf`, разъяснения V2, методические рекомендации и предоставленные
DICOM. Папка обучения содержит 499 DICOM; отдельная тестовая папка — 3.
Экспертные бинарные метки есть для 249 уникальных изображений из 100 исследований.
Три тестовых DICOM не имеют ключа ответов. Их успешная обработка не измеряет точность.

## Соответствие требованиям

| Требование | Вывод по текущему коду и данным |
|---|---|
| DICOM, папка/ZIP, пакетная обработка, API | Реализованы. Есть построчные Failure и продолжение пакета, очередь и сохранение результатов. |
| Независимость от персональных полей | Роутинг основан на пикселях; используются технические поля масштаба и стороны. UID нужны для группировки/отчёта. Независимость реальных пациентов между исследованиями не доказана обезличенными полями. |
| Поясница/бедро и сторона для зеркальной геометрии | Реализованы; недостаточная уверенность ведёт к отказу, либо сторона подтверждается согласующимся техническим полем DICOM. |
| Проекция позвоночника | Есть модель и отказ до QC для неподдержанной/неопределённой проекции. Независимая клиническая точность не подтверждена. |
| Проекция бедра | Не закрыта: нет подтверждённого самостоятельного допуска AP/lateral/unknown на DXA. |
| Бинарный QC | Реализован; сохраняются пропуски и ложные тревоги. См. измерения ниже. |
| Официальные типы и несколько нарушений | Формат закрыт: 3 типа позвоночника, 2 типа бедра; `;`, пустая строка при норме, `quality_prob` в [0,1]. Точность типизации ограничена. |
| Позвоночник: половина Th12 и верхние края подвздошных костей | Не закрыто: кандидатная анатомия не является подтверждённым измерением видимости каждого ориентира. |
| Позвоночник: ось ≤5° | Порог соблюдается, включая вторичный пересмотр. Из 10 размеченных нарушений обнаружено лишь 1; нет независимых числовых углов для оценки MAE. |
| Позвоночник: инородные предметы | Есть обученный тип; внутренний F1 0,757. Точность локализации предмета отдельно не измерена. |
| Позвоночник: L1–L4, межпозвоночные границы, исходная ROI | Маски и предложения есть; подтверждённой автоматической нумерации и проверки исходной анатомической разметки нет. |
| Бедро: большой вертел, шейка, седалищная кость | Есть кандидаты; полнота визуализации каждого ориентира не валидирована. |
| Бедро: недостаточная/избыточная ротация | Совмещённая метка укладки/ротации классифицируется; отдельные подтипы и контур малого вертела не подтверждены. |
| Бедро: отступы 30/30/20 мм | Масштаб и измерения реализованы; клиническая точность ориентиров не подтверждена. Нельзя подменять охват сканирования прямоугольником ROI шейки. |
| Бедро: анатомическая корректность ROI шейки | Геометрические проверки и редактор есть; нет независимого DXA-эталона оси шейки, большого вертела и мягких тканей по сторонам ROI. |
| CSV/XLSX и структурированный результат | Проверены строгий формат и расширенный отчёт; полнота входа проверяется по расширенной таблице. |
| Дополнительные SC/SR и визуализация | Есть; проверены читаемость и ссылки на исходные изображения. Это не полная независимая DICOM-conformance проверка или испытание PACS. |
| ≤180 секунд на исследование | Проверяется полное время, включая общие расходы. Есть локальные замеры; испытание на целевом H200 не выполнено. |
| Контейнер, Unix-скрипт, офлайн, фиксированные зависимости | Образ собран, веса и профиль закреплены хешами, офлайн-прогоны выполнены с `--network none`. |
| Документация/презентация/паспорт | Исправлена привязка генератора к конкретному версионному профилю; исторические материалы 1.11.0 архивированы. |
| Независимая оценка с доверительными интервалами | Не закрыта. Пересчитаны интервалы внутреннего исторического OOF; новых пациентов или независимой разметки это не добавляет. |

Методические рекомендации отдельно требуют проверять межпозвоночные маркеры,
нумерацию позвонков и положение ROI шейки относительно её оси, большого вертела
и мягкой ткани. Успешный CSV и общая метка «укладка» не подтверждают эти проверки.

## Что изменено

1. **Устранён повторный ResNet18 inference для левого бедра.** Один вектор
   зеркального изображения теперь используется и основным QC, и вторичным
   пересмотром. С review-моделью число вызовов `embed` уменьшено с 3 до 2:
   один для роутинга, один для QC. Это 33% сокращение числа таких вызовов для
   левого бедра, а не заявленный процент ускорения всего пакета.
2. **Усилен отбор кандидатов.** Проверяются источник меток, полные идентичности,
   разбиение исследований, словарь типов по области, конечность вероятностей,
   физический порог оси, F1/чувствительность/специфичность по областям и типам,
   ROC-AUC, average precision, macro-F1 и Brier. Кандидат с ухудшением этих
   измеренных показателей не проходит экран. Экран остаётся внутренней
   исследовательской проверкой и не заменяет независимый тест.
3. **Добавлен воспроизводимый nested-эксперимент по всем пяти типам.** Проверены
   RF, LR на геометрии, LR на признаках изображения с двумя регуляризациями,
   объединённые признаки, ансамбль и адаптивный выбор. Скейлеры, импьютеры,
   выбор моделей и пороги обучаются без внешних тестовых исследований.
4. **Добавлена независимая проверка поставки.** `competition/audit_delivery.py`
   собирает список и хеши исходных `.dcm` из входной папки, проверяет полноту
   результата, строгий CSV, время, SC/SR и совпадение медицинских полей при повторе.
5. **Исправлены проблемы контейнерной проверки.** В образ добавлены недостающие
   общий загрузчик/каталоги и ресурсы слепого анатомического редактора. Исправлен
   импорт теста, зависевший от структуры полного checkout. Тестовый tmpfs
   допускает запуск временных тестовых исполняемых файлов.
6. **Строгая приёмка доступна из `run.sh`.** Четвёртый аргумент `complete`
   возвращает код 3 при незакрытой анатомии, сохраняя отчёты. По умолчанию
   остаётся `submission`; ошибочный режим отклоняется до создания результатов.
7. **Подготовлен свежий слепой анатомический пакет.** 252 уникальных изображения
   из обучающего экспорта, включая 3 без QC-меток; изображения и источники
   проверены, решения модели скрыты. Независимые экспертные ответы пока отсутствуют.
   Выделены 64 изображения для случайной анатомической проверки из 25 исследований
   и 55 изображений для разработки: 31 ложная тревога, 24 пропуска. Очереди
   разделены по исследованиям. Исправлена совместимость подготовки очередей
   с входом, начинающимся непосредственно с каталога исследования.

## Новые эксперименты

Все варианты ниже используют одинаковые внешние исследования и сохранённый
роутинг/измерение оси базы. Это условная оценка нового QC, не новое end-to-end
испытание роутера. Вариант «ансамбль» повторяет семейства классификаторов,
но меняет композицию на объединение типов, поэтому не является воспроизведением поставки.

| Вариант | F1 QC | Чувствительность | Специфичность | ROC-AUC | Macro-F1 типов |
|---|---:|---:|---:|---:|---:|
| База | 0,592 | 0,616 | 0,807 | 0,790 | 0,482 |
| Ансамбль с объединением типов | 0,577 | 0,562 | 0,841 | 0,803 | 0,488 |
| RF на геометрии | 0,575 | 0,575 | 0,824 | 0,792 | 0,511 |
| LR на геометрии | 0,482 | 0,548 | 0,699 | 0,755 | 0,443 |
| LR на признаках изображения, C=0,01 | 0,505 | 0,630 | 0,642 | 0,750 | 0,382 |
| LR на признаках изображения, C=0,1 | 0,517 | 0,630 | 0,665 | 0,744 | 0,366 |
| LR на объединённых признаках | 0,500 | 0,630 | 0,631 | 0,753 | 0,402 |
| Внутренний адаптивный выбор | 0,580 | 0,548 | 0,858 | 0,762 | 0,507 |

**Ни один из семи вариантов не принят в рабочее медицинское решение.** Есть
частные улучшения отдельных показателей, но нет совместного улучшения.
Повторное использование этой выборки для экспериментов ограничивает доказательность.
[Полный машинный отчёт](competition/metric_upgrade_2026_10_03.json).

Дополнительно проверен MedSigLIP: локальный encoder, динамический INT8 линейных
слоёв vision, размер 224 с интерполяцией позиционных embeddings. Это отдельный
кандидат, не исходная FP32-модель на 448. На 150 снимках бедра из 78 исследований
по совмещённой метке укладки/ротации F1 **0,407** против **0,518** у парной базы;
чувствительность **0,694** против **0,611**, специфичность **0,456** против **0,763**,
ROC-AUC **0,628** против **0,775**. Ложные тревоги выросли с 27 до 62.
Кандидат отклонён; парный 95% интервал ΔF1: **−0,228…+0,007**.
[Протокол, веса, хеши и построчный OOF](competition/medsiglip_int8_224_hip_probe_2026_10_03.json).
Его фолды отличаются от общей таблицы QC; сравнивать эти F1 напрямую нельзя.
Незавершённые FP32/448 и INT8/448 извлечения сохранены только как локальные кэши
и не имеют полной метрики. Результат INT8/224 ничего не доказывает о качестве FP32/448.

## Воспроизведение и следующий шаг

```sh
make verify
./competition/run.sh build
./competition/run.sh test
./competition/run.sh batch /absolute/input.zip /absolute/new-output complete

make metrics-upgrade INPUT='/absolute/Исследования' OUTPUT=data/new-metric-experiment
make screen-candidate CANDIDATE=data/new-metric-experiment/adaptive_oof.csv OUTPUT=data/new-screen.json

PYTHONPATH=competition competition/.venv/bin/python competition/audit_delivery.py \
  --input /absolute/extracted-dicom-folder --results /absolute/batch-output \
  --output /absolute/new-audit.json
```

Техническое улучшение допускает выпуск 1.11.6 без смены медицинских весов.
Для следующего повышения точности нужны подтверждённые DXA ориентиры/углы,
подтипы ротации, реальные операторские ROI и новый независимый набор.
Открытые данные иной модальности, синтетические дефекты и собственные маски
модели не заменяют этот эталон. Отдельно нужен замер целевого H200.
