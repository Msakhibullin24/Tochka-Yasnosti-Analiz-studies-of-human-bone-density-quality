## Критические расхождения

### 1. Физический масштаб неверен относительно разъяснения

Организатор задаёт Y = 1,05 мм/пиксель, X = 0,6 мм/пиксель и единый аппарат в наборах.
Все 499 входных DICOM имеют Manufacturer GE Healthcare / Lunar Prodigy Advance,
не содержат PixelSpacing, ImagerPixelSpacing и NominalScannedPixelSpacing.
ExposedArea присутствует во всех 499 файлах, но не даёт основания игнорировать
заданные организатором размеры пикселя.

В результатах 1.7: 280 файлов используют изотропную оценку из ExposedArea,
219 — device_default = 0,607 мм по обеим осям. Все 499 не соответствуют указанной
паре. `_pixel_mm` в `competition/dxaqc/dicom_io.py` выбирает эти источники;
`geometry.py` поддерживает раздельные X/Y, но не получает нужную пару.

При шаге 0,607 вертикальный отступ 30 мм соответствует примерно 49,42 пикселя;
при 1,05 — 28,57 пикселя. Изменятся физические углы, расстояния, площади,
геометрические признаки, положения некоторых кандидатов. Одного изменения
подписи в интерфейсе недостаточно.

Это также выявляет проблему обучающей аугментации: `train.py` вращает исходную
пиксельную сетку, а синтетические признаки получает прямым `measure_spine`,
без X/Y-преобразования из `measure_image`. При разных размерах пикселя физический
угол нельзя отождествлять с углом такого вращения. Нужно согласованно исправить
основное извлечение признаков, синтетику и её целевые метки; заново обучить модели
и выполнить тот же протокол оценки. Кэш основных признаков учитывает исходники
геометрии и DICOM-чтения, но этого недостаточно для корректности аугментации.

Метрики 1.7 сохраняются как воспроизводимый результат прежнего алгоритма.
Они **не подтверждают качество решения с масштабом V2**. Веса и рабочий сервис
в рамках данного аудита не заменены.

### 2. Точное имя нарушения оси не совпадает

В DOCX: `Не выравнена ось позвоночника`.
В `model.py` и выходе: `Не выровнена ось позвоночника`.
Разница может оказаться критичной для проверки по закрытому словарю.
В полном выводе 16 строк содержат старую форму. Остальные четыре официальных
значения совпадают. Нужно использовать буквальную форму документа в конкурсном
экспорте и проверять её независимым эталоном, а не тем же словарём реализации.
Исторические результаты нельзя молча переписывать.

### 3. Неопределённый тип не разрешён документом как полноценный результат

В 9 строках класс 1 с пустым типом. Разъяснение предусматривает пустое поле при
отсутствии нарушений; отдельного значения «не определён» не вводит. Прозрачное
отображение неопределённости полезно для врача, но не закрывает конкурсную
типизацию. Внутренний `valid=true` с предупреждениями нельзя выдавать за
соответствие всем требованиям организатора. Нужен отдельный строгий режим
конкурсной приёмки и улучшение типизации, без выдуманного назначения категории.

ориентиров этим документом не разъяснены.
