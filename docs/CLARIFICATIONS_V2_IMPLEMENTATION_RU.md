# Реализация разъяснений V2 — релиз 1.8.0

## Выполненные изменения

- В DICOM-чтении для GE Healthcare / Lunar Prodigy Advance без явных тегов масштаба
  применяется Y=1,05 мм, X=0,6 мм (`organiser_v2`). ExposedArea больше не заменяет
  заданную организатором калибровку. Для неизвестного аппарата профиль V2 не угадывается.
  PixelSpacing/ImagerPixelSpacing имеют приоритет; конфликт с профилем отмечается
  `EXPLICIT_SCALE_DIFFERS_FROM_ORGANISER_V2` в диагностике.
- Геометрия и ROI получают раздельные X/Y. Синтетическое вращение при обучении
  производится в физической системе и переводится обратно в пиксели. Признаки
  синтетики вычисляются тем же measure_image, что и рабочие признаки. Положительная
  метка оси не назначается, если измеренный угол нечисловой или ≤5°.
- Рабочая модель переобучена; исходная сохранена в `data/model-backups/1.7.0/`.
  В метаданных новых весов зафиксирован `calibration_version=lct-v2-xy-1`.
  Загрузчик отклоняет несовместимые веса вместо неявного применения новой геометрии.
- Текст оси соответствует буквальному словарю DOCX: «Не выравнена ось позвоночника».
- CLI по умолчанию создаёт строгий `results.csv/xlsx`; расширенная диагностика
  остаётся в `results_extended.csv`. `--extended-columns` позволяет сохранить прежний
  расширенный основной вывод; `--strict-columns` совместим с прежним вызовом.
- Во всех новых пакетах дополнительно создаются `submission.csv/xlsx` и
  `submission_validation.json`. В API основной results.csv сохраняет расширенный
  контракт для существующего интерфейса. Новые экспорты доступны отдельными ссылками.
- Режим `validate_results --competition` проверяет точные девять колонок и отклоняет
  положительный класс без типа. Рабочий валидатор сохраняет явную неопределённость
  как предупреждение. Это разные профили: `competition_v2` и `working_report`.
- Исторические задания, оригинальные машинные результаты и версии экспертных правок
  не переписываются. Интерфейс не предлагает отсутствующие новые экспорты для старых заданий.

## Границы результата

Исправление масштаба обязательно по разъяснению, но само по себе не гарантирует рост
качества классификации или точную анатомическую локализацию. Положительные случаи
без определённого типа не заменяются произвольным типом и не скрываются из приёмки.
Th12, проверенные альтернативные проекции, ориентиры бедра и анатомический вердикт
исходной ROI остаются отдельными незавершёнными задачами. PACS исключён пользователем.

## Воспроизведение

```sh
./competition/run.sh build
./competition/run.sh test
./competition/run.sh batch /absolute/input.zip /absolute/new-output
PYTHONPATH=competition python -m dxaqc.validate_results \
  --results /absolute/new-output/submission.csv --competition
python competition/audit_consistency.py \
  --results /absolute/new-output/results_extended.csv --output /absolute/audit.json
```

Код возврата строгого валидатора 1 означает ошибки контракта, включая неопределённый
тип положительного результата. Код возврата batch 0 означает завершённую обработку;
он не подменяет отдельную проверку готовности таблицы для сдачи.


## Результаты проверки

Полный исходный архив: 499/499 файлов, 100 исследований, 0 ошибок обработки.
Все 499 строк имеют `organiser_v2`, Y=1,05, X=0,6. Новое буквальное название оси
встречается в 2 строках; прежнего названия нет. Обработано за 86,495 с по summary,
максимум на исследование 1,499 с; пиковый RSS 493 047 808 байт. Ограничения запуска:
4 CPU, 4 GiB, сеть отключена. Это замер текущего хоста, не гарантия SLA.

**Конкурсная приёмка полного архива не пройдена:** 19 положительных строк без
установленного типа. Рабочий валидатор допускает их с предупреждением, строгий
конкурсный — отклоняет. Ни имя файла submission.csv, ни статус finished не означают
готовность к сдаче. Шесть счётчиков прежних программных противоречий равны нулю.

Повторный запуск без визуальных серий проверяет воспроизводимость предсказаний.
Полный прогон с SC/SR сохранён в `data/audits/calibration-v2-1-8/`, повтор —
`data/audits/calibration-v2-1-8-repeat/`. Проверены ссылки SC/SR на исходники и
независимый манифест входов. Предупреждения исходных DICOM UID сохраняются;
полная независимая DICOM-conformance проверка не заявляется.

83 серверных теста прошли с отладочными данными организатора. В контейнере —
82 прошли, 1 пропущен из-за отсутствующего внешнего набора; тот же тест включён
в 83 локальных. Публичный run.sh test/batch smoke успешен. UI: 43 теста, lint,
сборка успешны. В действующем API проверены 3 переименованных DICOM, правильные
X/Y в строках и detail, строгий экспорт из 9 колонок и ограничения во всех 3 SR.
История 4 предыдущих заданий сохранена. Резервная копия — `data/before-1.8.0.zip`;
предыдущий контейнер сохранён остановленным как `osseo-ai-before-1-8`.

Сравнение на одних и тех же пяти внешних фолдах по исследованиям, 249 изображений.

Исправление обязательного масштаба не должно скрывать снижение точности.

В сквозном OOF остаются 34 положительных случая без установленного типа.
Это другая выборка и другой режим оценки, чем 19 файлов в полном прогоне
поставляемых весов; эти числа нельзя напрямую сопоставлять.

метки не переписывались под новый расчёт. Следующие приоритеты — ось и типизация,
затем подтверждённые анатомические ориентиры/ROI. Перебор порогов по этим внешним
результатам ради улучшения отчёта не выполнялся.

Региональное обучение с известной областью даёт другой протокол (общий F1 0,500),
поэтому его цифры не заменяют приведённую сквозную оценку. Оба отчёта сохранены:
`calibration_v2_training.json`, `calibration_v2_pipeline.json`, соответствующие OOF,
`calibration_v2_comparison.json`. Это внутренняя CV, а не независимая клиническая
оценка поставленных весов. Пороговые показатели и локализация не валидированы врачом.
