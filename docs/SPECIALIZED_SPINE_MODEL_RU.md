# Специализированная локализация Th12 и L1–L4

Дата проверки: 2026-09-22. Новый локализатор не подключён. После первичного аудита
скачаны исходники и checkpoint DXA-to-3D, проверена строгая загрузка архитектуры
и CPU-расчёт `[1, 1254]`. Это ещё не проверка preprocessing, порядка кривых или
анатомической точности. [Реализованный запуск](../competition/docs/SPECIALISTS.md).

## Проверка DXA-to-3D

Проверен [DXA-to-3D](https://github.com/EmmanuelleB985/DXA-to-3D/tree/e14cd1d81f38f445a1f34983bddb9bad57b355fd),
commit `e14cd1d81f38f445a1f34983bddb9bad57b355fd`.

[Страница авторов](https://www.robots.ox.ac.uk/~vgg/research/dxa-to-3d/)
описывает восстановление формы позвоночника из AP DXA через регрессию шести
кривых: трёх корональных и трёх сагиттальных. Это основание рассматривать работу
для отдельного исследования формы позвоночника. Оно не доказывает возможность
выделять и нумеровать отдельные тела Th12, L1, L2, L3, L4.

Есть конкретное несоответствие опубликованного API исходникам:

- [inference.py](https://github.com/EmmanuelleB985/DXA-to-3D/blob/e14cd1d81f38f445a1f34983bddb9bad57b355fd/inference.py)
  импортирует `create_model` и ожидает словарь предсказаний кривых.
- [model.py](https://github.com/EmmanuelleB985/DXA-to-3D/blob/e14cd1d81f38f445a1f34983bddb9bad57b355fd/model.py)
  не определяет эту функцию; содержит `RegressionModel`,
  `RegressionModel_Transformer`, `model_vit`. Первые две возвращают тензор.
- Этот же модуль загружает сторонние предобученные модели при импорте.
  Такой путь нельзя напрямую включить в нашу автономную поставку.

Первичная проверка выполнена чтением исходников и разбором Python AST.
При последующей реализации файл весов успешно скачан; `competition/check_specialists.py`
восстанавливает архитектуру без побочных загрузок upstream-модуля и строго загружает
checkpoint. Качество на наших снимках и значение каждого из 1254 выходов не установлены.

Решение: не назначать этот checkpoint детектором Th12/L1–L4. Возможность переноса
признаков потребует отдельного эксперимента с новой выходной головой и разметкой.

## Границы задач в нашем продукте

Основной путь находится в `competition/dxaqc/`, исследовательский total-body
адаптер в `backend/app/model_adapters.py` не является точкой интеграции основного продукта.
Сейчас `competition/dxaqc/anatomy.py` выделяет ненумерованные кандидаты и явно
оставляет Th12 без координат. Ограничения описаны в
[анатомических проверках](../competition/docs/ANATOMICAL_CHECKS.md).

| Задача | Предлагаемая ответственность |
|---|---|
| Область и проекция | Маршрутизация с возможностью отказа при неизвестном входе |
| Th12, L1–L4 | Специализированный локализатор с анатомической нумерацией |
| Подвздошные края | Анатомическая голова для проверки нижнего охвата |
| Бедро | Отдельная модель ориентиров бедра |
| Геометрия ROI и охват | Проверяемые вычисления по локализации и исходной ROI |
| Артефакты и прочие визуальные нарушения | Специализированная QC-модель |
| 3D-форма | Отдельный исследовательский модуль; кандидат DXA-to-3D |

Специализация относится к задаче и проверяемому выходу: отдельная нейросеть для
каждого геометрического правила не нужна. Возможность общего backbone определяется
измерением качества и стоимости инференса.

## Что требуется от локализатора

1. Вход: целевая фронтальная DXA позвоночника с сохранённой геометрией кадра.
   VFA, обычный рентген и КТ не считаются эквивалентной проверочной выборкой.
2. Выход: номер каждого позвонка, контур либо маска тела, уверенность и видимость
   (`visible`, `partial`, `absent`, `uncertain`). Координаты возвращаются в исходный
   кадр с учётом всех преобразований. Th12 и T12 — один анатомический уровень.
3. Номер нельзя назначать только по порядку объектов сверху вниз. При недостатке
   анатомического контекста нужен отказ от нумерации. Отсутствующий или обрезанный
   позвонок не заменяется выдуманной областью.
4. Для проверки половины Th12 одной центральной точки недостаточно: необходима
   экспертная разметка границ и отдельная оценка частичной видимости.
5. Веса, версия кода, preprocessing, классы и контрольная сумма фиксируются вместе.
   Запуск поставки проверяется без сети. Ошибка модели не превращается в успешную
   анатомическую проверку и не переписывает экспертные правки.

## Последовательность внедрения

Сначала инвентаризировать доступные экспертные аннотации и подготовить независимую
разметку номеров, границ и видимости на целевых снимках. Разделить пациентов между
обучением и проверкой до выбора порогов. Проверить кандидата на совместимость
архитектуры и весов, затем провести обучение или адаптацию при необходимости.

Отдельно измерить правильность нумерации каждого уровня, пропуски, ложные детекции,
качество границ, долю отказов и ошибки на обрезанном Th12. Ошибку в миллиметрах
считать только при подтверждённом масштабе. Проверить разные аппараты и полный
офлайн-инференс на целевом оборудовании. Численные пороги приёмки зафиксировать
до итогового теста с владельцем требований; результаты DXA-to-3D не подменяют эти метрики.

После этого подключать модель в анатомическую ветвь основного pipeline, проверяя
координаты overlay, экспорт и зависимые QC-критерии. До такой оценки нельзя объявлять
закрытой локализацию Th12/L1–L4 или полную анатомическую проверку.
