# Автоматические проверки анатомии — 1.12.0

Версия добавляет вычисления по требованиям исходного ТЗ к проверенной GPU-модели
качества. Головы классификатора и его пороги сохранены: новые приближённые
геометрические оценки не подменяют обученное решение жёсткими правилами.
Итоговая приёмка всего ТЗ пока не объявляется.

## Что добавлено

Для позвоночника рассчитывается оценка видимой доли центральной области Th12
относительно соседних поясничных позвонков и локализуются оба гребня подвздошных
костей. У порога половины тела учитывается разброс размеров соседних позвонков;
неуверенный результат сохраняется как `uncertain`. Это морфологическая оценка
области тела по предсказанной маске, а не отдельная обученная сегментация тела Th12.
При отсутствии области числовая доля не выдумывается.

Для бедра измеряется ориентация собственной ROI относительно оси шейки,
пересечение с модельной областью большого вертела, наличие предсказанных мышц
с двух поперечных сторон ROI и пересечение с тазовой костью. Область большого
вертела получается разбиением предсказанной бедренной кости по расстояниям до
ориентиров. Это приближение; оно не выдаётся за точный контур всего вертела.
Попадание или непопадание одной точки не заменяет проверку области.
Допустимый небольшой заход на седалищную кость не превращается в произвольный
числовой порог ошибки. Пространство вне кости не объявляется мягкой тканью;
отсутствие предсказанной мышцы не доказывает отсутствие мягкой ткани.

Маски берутся из уже выполненных вызовов сегментации. Дополнительных загрузок
моделей или сетевого инференса не требуется. При выборе отражённого входа маски
возвращаются в исходные координаты.

## Отчётность

Обязательные восемь полей CSV/XLSX и согласованное `quality_prob` сохранены.
Расширенная таблица дополнена полями:

| Поле | Значение |
|---|---|
| `automatic_requirement_checks` | Исходы каждой выполненной функции, основание и необходимость проверки |
| `automatic_check_execution_complete` | Все предусмотренные автоматические функции выполнены и выдали явный исход |
| `automatic_findings_resolved` | Все находки разрешены; отсутствие измерения или неопределённость не считается положительным ответом |

В `requirements.json` версии 2 отдельно агрегируются выполнение функций и
прежнее строгое покрытие анатомическими свидетельствами. Значение
`automatic_workflow_complete=true` обозначает выполнение автоматического
процесса с таблицами, типизацией и допустимым временем. Оно **не означает**
`requirements_complete=true`, правильность каждой находки или приёмку организатором.
Для входа без исходной ROI её проверка помечается `not_applicable`, как требует
работа с неразмеченным DICOM. Исходы и приближения доступны для проверки.

обучающем архиве; она не измеряет качество обобщения финальных весов.

используются для настройки правил по ответам качества.

Пакетный GPU-инференс занял 146,016 с; консервативная верхняя граница на одно
исследование со всеми общими расходами — 31,861 с. Измерение выполнено локально
на RTX 4070; это не результат на H200 организатора. Первый параллельный
хостовый прогон сохранён отдельно: 348,990 с на пакет и 133,945 с на исследование

Холодная граница готового CLI с инициализацией моделей — 42,663 с на исследование.

отладочных DICOM за 1,479 с; readiness осталась положительной. В обоих пакетах
проверены CSV/XLSX, PNG, SC/SR, неизменность исходного ZIP и совпадение ответов
с CLI. Доступная сеть контейнера — только `lo`.

Проверки исходного кода: 486 passed, 5 skipped. Проверки готового CPU-образа
через поставляемый скрипт: 469 passed, 8 skipped; дополнительно выполнен
пакетный запуск синтетического DICOM ZIP. Идентификаторы образов и подробная
приёмка сохранены в [машинном отчёте](competition/anatomy_upgrade_2026_10_15.json).

## Итерации качества и оставшиеся задачи

После первых трёх итераций выполнено ещё 67 конфигураций; они содержат
контрольные варианты и совпадающие предсказания. Это не 61 независимая выборка.
Последние четыре варианта калибровки вероятности, шесть конфигураций с новыми
геометрическими признаками и шесть конфигураций оси по центральным областям
тел позвонков не превзошли выбранную модель по основным метрикам.
Поэтому они не заменяют текущие головы. Лучший выбранный компромисс:
F1 = 0,619048, ROC-AUC = 0,811877, AP = 0,693250, macro-F1 пяти типов = 0,536340.
Метрики получены на ранее исследованной выборке из 249 размеченных изображений
с пятью внешними и четырьмя внутренними разбиениями по исследованиям. Независимость
пациентов не установлена. Рост относительно исходного F1 0,592105 и AUC 0,790318
не доказывает превосходство на закрытом тесте или глобальный максимум.

Три определения оси по центральным областям L1–L4 — общая регрессия,
направление между крайними уровнями и регрессия с весами по площади — проверены
при неизменном пороге 5°. Общая и взвешенная регрессии сохранили 2 TP / 8 FN / 3 FP
по критерию оси на 99 снимках; крайние точки дали 1 TP / 9 FN / 5 FP. Подмена
общего наклона максимальным локальным искривлением не выполнялась. Дополнительные
три геометрических теста прошли, включая физический масштаб и отражение.
На уровне всего QC новая общая ось сохранила F1/AUC, повысила macro-F1 типов
с 0,536340 до 0,540969, но снизила F1 артефактов позвоночника с 0,619048 до
0,590909. Это отдельный компромисс, поэтому поставляемый вариант сохранён.

Открыты точное выделение всей анатомической области большого вертела и тела
Th12, надёжная оценка обеих сторон мягких тканей и отдельное устойчивое
распознавание недостаточной и избыточной ротации. Текущий классификатор
оценивает объединённый официальный критерий укладки/ротации бедра.
Неопределённый случай локализации бедра также сохраняется явно.
Это конкретные ограничения алгоритмов, а не дополнительные требования к
пользователю о врачебной проверке или клинической сертификации.

Архив CPU- и GPU-образов:

Размер 7 278 757 318 байт; SHA-256:
`dabd83c1c2d89fb6aaf803d4e52d6f783a4487d858c9315edaa5646089652e43`.
Проверены gzip CRC, 102 блока SHA-256 и наличие двух ожидаемых тегов.
Также успешно выполнен `docker load`; оба image ID совпали с паспортом.
Загрузка проверена на том же частном движке проекта, а не на новом компьютере.
Подробный результат хранится в машинном отчёте.

Скрипт `competition/experiments/package_offline_delivery.py` собирает папку
передачи из проверенного архива, снимка закоммиченных исходников, скриптов запуска,
паспорта, отчёта и презентации. Он требует успешной загрузки архива и совпадения
image ID с паспортом, проверяет SHA-256 и создаёт контрольные суммы всего комплекта.
Папки датасетов, сырые медицинские форматы и лист просмотра обучающих снимков
исключаются из снимка исходников. Обучающие веса входят в Docker-образы.

```sh
python competition/experiments/package_offline_delivery.py \
  --archive-audit data/build-artifacts/2026-10-15/archive-verification-1.12.0.json \
  --output data/build-artifacts/2026-10-15/delivery-1.12.0
```

Команда выполняется из чистого Git-дерева. На принимающем компьютере сначала
проверяются `SHA256SUMS` и загружается Docker-архив, затем запускается
`./competition/local_run.sh serve 8091`; GPU требует совместимый драйвер NVIDIA.
Отдельный CPU-запуск: `./competition/run.sh serve 8090`.

Комплект создан в `data/build-artifacts/2026-10-15/delivery-1.12.0` по снимку
Git `8e241b2bd851c3eb16ca3f132275ff4473dec026`. Проверены контрольные суммы,
исполняемые скрипты и исключение обучающих изображений из снимка исходников.
Из скопированного скрипта реально запущен GPU-сервис на отдельном порту:
readiness и собранный интерфейс доступны. Затем проверочный сервис остановлен;
основной сервис на 8091 продолжает работать.
