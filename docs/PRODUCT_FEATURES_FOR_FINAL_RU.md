# Продукт вокруг готовой модели: план к финалу

20.09.2026. Модель считаем пригодным готовым ядром; её улучшение не входит в этот план. Горизонт — месяц, PACS исключён, эксперта пока нет. Документ описывает предлагаемые возможности, а не выполненную реализацию. Фактическое состояние: [IMPLEMENTATION_STATUS_RU.md](IMPLEMENTATION_STATUS_RU.md). Для продуктовых приоритетов до финала использовать этот документ; долгосрочную архитектуру дополняет [LONG_TERM_STRATEGY_RU.md](LONG_TERM_STRATEGY_RU.md).

Основание: предоставленный файл «4. ДепЗдрав.pdf», разделы 2–8. В нём оцениваются техническая проработка, соответствие задаче, воспроизводимость и защита; приоритет метрик модели сохраняется. Баллы отдельных продуктовых функций не опубликованы, поэтому приведённая приоритизация — наше проектное решение, а не официальный рейтинг.

## Продуктовое обещание

«Загрузите исследования, проверьте найденные нарушения на изображении, сохраните своё решение и получите проверяемый отчёт — локально, в одном приложении».

Главная единица работы — исследование с изображениями. Пакет загрузки нужен для импорта и технического контроля, но не заменяет исследование. Завершение работы означает проверенные результаты и доступный отчёт; завершение вычисления модели — отдельное событие.

Три основных раздела: **Исследования**, **Контроль качества**, **Система**. Просмотр снимка и редактор открываются внутри исследования. Библиотека примеров доступна через справку. Отдельный экран на каждую функцию не нужен.

## 1. Приём исследований без потери данных — P0

Уже есть: загрузка, обработка архивов, ошибки отдельных файлов, история пакетов, отмена и частичный отчёт.

Доработать:

- Результат приёма: сколько файлов принято, сколько исследований распознано, какие файлы повторяются, какие отклонены и почему.
- Прогресс по реальным стадиям: приём, чтение, анализ, формирование отчёта. Счётчики готовых/ошибочных файлов; оценка оставшегося времени только по наблюдаемой скорости.
- Повтор только неуспешных файлов при доступном исходнике; иначе точный список для повторной загрузки.
- Сохранение исходников с понятным сроком и лимитом; предварительная оценка свободного места.
- Возобновление незавершённого пакета после перезапуска с сохранением готовых результатов.

Приёмка: смешанный пакет с повреждённым файлом сохраняет все успешные результаты; перезапуск не дублирует готовые строки; отменённые и ошибочные файлы не считаются качественными исследованиями.

## 2. Рабочий список исследований — P0

Уже есть: список заданий, поиск и фильтры результатов. Нужна группировка по исследованиям.

- Карточка исследования: область, число изображений, результат ИИ, состояние проверки, дата при наличии, последнее действие.
- Отдельные состояния обработки и проверки: «Обрабатывается», «Ошибка обработки»; «Не проверено», «Черновик», «Подтверждено», «Невозможно оценить».
- Представления «Требуют проверки», «С нарушениями», «Есть технические ошибки», «Завершены». Приоритет очереди объясним; любое изображение остаётся доступным.
- Переход к следующему непроверенному снимку, сохранение фильтра, масштаба и позиции очереди.
- Миниатюры всех снимков исследования; итог исследования показывает и нарушения, и неполноту обработки без потери решений по отдельным изображениям.

Приёмка: после обновления страницы пользователь продолжает с прежнего места; несколько снимков одного исследования доступны вместе; повтор загрузки не создаёт вторую независимую историю правок. Группировать по надёжным идентификаторам DICOM, а при их отсутствии показывать неопределённость. Автоматически объединять людей по похожим именам нельзя.

## 3. Интерактивная карта нарушений — P0, ключевой демонстрационный элемент

Уже есть: исходник, геометрические слои, увеличение, численные признаки и пороги.

- Список критериев рядом со снимком. Выбор критерия выделяет относящиеся к нему доступные линии/области и показывает пояснение.
- Для каждого критерия: результат, фактическое основание, измерение и единицы при наличии, источник масштаба, ограничение оценки.
- Видимое различие «нарушение найдено», «нарушение не найдено» и «критерий не оценён». Последнее не превращается в зелёную отметку.
- Исходник/наложения одним действием; масштабирование, перемещение, сброс вида, яркость/контраст только отображения.
- Нельзя рисовать точную локализацию для классификатора, который её не выдаёт. В этом случае отображать результат для всего изображения. Score не называть вероятностью без соответствующего основания.
- Краткая справка по критерию с указанием раздела предоставленной методики. Тексты справки отделены от объяснения конкретного предсказания.

Приёмка: у каждого отображаемого основания есть поле результата или ссылка на методику; изменение отображения не меняет анализ; преобразования координат корректны при зеркальном бедре и разном масштабе пикселей.

## 4. Редактор ROI и ориентиров с версиями — P0, ключевой демонстрационный элемент

Уже есть: ввод координат, добавление геометрии, undo/redo, черновики, подтверждение и история.

- Перемещение точек мышью, доступное управление клавиатурой и точный числовой ввод.
- Выбор объекта на снимке и в списке; блокировка случайного перемещения; понятные названия объектов.
- Живое обновление поддерживаемых геометрических измерений с единицами и источником масштаба.
- Режим «Исходная разметка / Моя версия» с общей позицией и масштабом.
- Панель изменений: какие точки/линии изменены, автор, комментарий, время. Сохранение новой версии вместо перезаписи исходной.
- Локальный черновик либо серверное автосохранение с явным статусом и защитой от конфликта вкладок; подтверждение остаётся отдельным действием.

Граница: перемещение ROI само по себе не пересчитывает BMD и не доказывает устранение дефекта укладки. Предсказание ИИ не изменяется от правки рисунка. «Предложить ROI» допустимо только при наличии соответствующего работающего алгоритма; существующий редактор не выдавать за автоматическую коррекцию.

Приёмка: правки переживают перезагрузку, undo/redo предсказуемы, два открытых окна не теряют чужую версию; экспорт позволяет восстановить исходную и выбранную пользовательскую геометрию.

## 5. Протокол результата, пригодный для передачи — P0

Уже есть: машинные CSV/XLSX/SC/SR, отдельный экспертный CSV, JSON версий и HTML для печати.

- Читаемый отчёт исследования: изображения с выбранными наложениями, критерии, доступные измерения, решение ИИ, решение проверяющего и ограничения.
- Формирование отчёта из конкретной сохранённой версии, чтобы последующая правка не меняла ранее выданный документ.
- ZIP исследования: официальный результат, визуальные материалы, протокол проверки, паспорт версии. Экспорт всего пакета и выбранных исследований.
- HTML с проверенной печатью в PDF; отдельный генератор PDF нужен только если печать не обеспечивает воспроизводимую компоновку.
- Итоги пакета с отдельными знаменателями: принято, обработано, технические ошибки, найденные нарушения, проверено пользователем.
- Обязательный конкурсный CSV остаётся совместимым с заданием; дополнительные поля идут в дополнительные артефакты.

Приёмка: отчёт читается без приложения, соответствует сохранённой версии, открывается с русскими названиями, не теряет многостраничные таблицы. Автор, введённый текстом, не называется электронной подписью.

## 6. Сравнение изображений — P1

Два сценария: исходная и исправленная разметка одного снимка; два выбранных исследования.

- Два окна с синхронизацией перемещения/масштаба, независимыми слоями и явной стороной/областью.
- Перечень изменений геометрии и решений рядом с изображениями.
- Для разных исследований — проверка доступных метаданных, явные различия аппарата/масштаба/области; пользователь подтверждает выбор пары при недостаточных идентификаторах.
- Первый релиз показывает сравнение качества и разметки. Медицинскую динамику плотности не выводить из неподдерживаемых данных; совмещение разных снимков не трактовать как измерение изменений заболевания.

Приёмка: не связанная автоматически пара не представляется как история одного пациента; отсутствующая дата не выдумывается; синхронизацию можно отключить.

## 7. Панель контроля качества — P1

- Доли нарушений по области и типу, число обработанных/неоценимых изображений, полнота проверки.
- Расхождения ИИ и пользовательских решений; переход из каждого показателя к исходным случаям.
- Фильтры по пакету, периоду и аппарату при наличии достоверных метаданных. Различать дату исследования и дату загрузки.
- Явный знаменатель и размер группы. Повторные загрузки не удваивают показатели по исследованиям.
- CSV сводки для локального анализа.

Это наблюдение за потоком. Расхождения с пользовательскими правками не называть точностью модели; частоту нарушений без учёта состава потока не превращать в рейтинг сотрудников или учреждений.

Приёмка: любой счётчик проверяется по списку входящих в него исследований; сумма состояний сходится; отсутствие данных отличается от нулевой частоты.

## 8. Самостоятельный запуск и обслуживание — P0

- Экран готовности: модель, очередь, обработчик, свободное место, каталог данных, версия приложения и последняя успешная обработка.
- Понятная диагностика запуска с конкретным способом устранить ошибку.
- Резервное копирование и восстановление через существующий механизм, с отображением последней копии и проверкой сценария восстановления.
- Управление сроком хранения и удаление с предварительным перечнем затрагиваемых данных.
- Диагностический пакет с версиями/настройками/обезличенными техническими ошибками, без исходных снимков и персональных полей; просмотр состава перед экспортом.
- Готовый офлайн-образ, контрольные суммы, инструкции и команда проверки. Заявление об офлайн-работе проверяется без сети, включая первый запуск модели.

Авторство сейчас вводится пользователем. Для одиночной локальной конкурсной поставки это обозначается прямо. Если появится совместная работа через сеть, отдельная обязательная задача — вход, права доступа и проверяемый аудит; выбора имени из списка для этого недостаточно.

## 9. Встроенная библиотека кейсов — P1

- Несколько доступных обезличенных примеров: качественное исследование, позвоночник с нарушением, бедро, сочетание нарушений, техническая ошибка.
- Для примера: что проверять, исходная метка и её происхождение, фактический результат текущего приложения, доступное объяснение.
- Примеры запускаются тем же обработчиком. Технически синтетические случаи явно обозначены.
- Учебные данные изолированы от рабочего списка и аналитики, можно сбросить учебную сессию.

Без эксперта библиотека опирается на метки организатора и явно цитируемую методику. Новые медицинские эталоны не создаются.

## 10. Комплект доказательств для жюри — P0

Матрица «пункт задания → экран/файл/API → проверка → ограничение». Отдельно отметить обязательные функции и дополнительные возможности; не приписывать последним неизвестные конкурсные баллы.

Пакет сдачи: образ, запуск, инструкция на один экран, полная документация, примеры входа/выхода, отчёт проверок с условиями замера, презентация, сценарий демонстрации и резервная запись. Внешний проверяющий должен пройти путь на новом пакете без участия команды.

Сценарий защиты на 5 минут:

1. 0:00–0:40 — задача, локальная загрузка небольшого пакета, число исследований.
2. 0:40–1:30 — результаты и переход от нарушения к его доступному основанию на снимке.
3. 1:30–2:30 — редактирование ROI, измерение, сохранение версии, сравнение с исходной.
4. 2:30–3:10 — отчёт исследования и официальный CSV.
5. 3:10–3:50 — заранее подготовленный случай частичного сбоя: успешные строки сохранены, ошибка объяснена.
6. 3:50–5:00 — доказательства воспроизводимости, замеры, соответствие заданию и ограничения.

Записанная демонстрация обозначается как запись. Проверенные примеры помогают уложиться во время, но не заменяют возможность загрузки нового пакета. Не обещать устранение ошибки позиционирования перемещением ROI.

## Очерёдность на месяц

Это целевой объём при текущем готовом ядре; сроки оценочные. Каждый блок заканчивается работающим сценарием. P0 — приоритет этого плана, не новая официальная обязательная функция конкурса.

| Период | Основной результат | Критерий выхода |
|---|---|---|
| Неделя 1 | Исследования, состояния, сохранение исходников и связей, рабочая очередь | Повтор загрузки, обновление страницы и частичный сбой не теряют историю |
| Неделя 2 | Карта нарушений, drag-редактор, сравнение версий | Один снимок проходит от результата ИИ до сохранённой проверенной версии |
| Неделя 3 | Отчёт с изображениями, ZIP, готовность и восстановление; затем компактная аналитика | Отчёт воспроизводим, данные восстановлены в чистом окружении |
| Неделя 4 | Заморозка, проверка нового входа без сети, документация, защита | Полный путь выполняется по инструкции без автора проекта |

Если времени не хватает, сокращать сравнение разных исследований, расширенную аналитику и библиотеку примеров. Сохранять приоритет завершённого просмотра/редактирования/отчёта и надёжной поставки. Продолжение после сбоя реализовать до заморозки либо честно оставить работающий повтор с сохранённым входом.

## Общие критерии готовности

- Любое число в интерфейсе проверяемо по данным; нет демонстрационных процентов в рабочем режиме.
- Выбранная версия результата одинакова в просмотре, печати и экспорте.
- Действия пользователя не изменяют исходное машинное решение задним числом.
- Клавиатурой доступны основные сценарии, состояния различимы не только цветом, редактор имеет числовую альтернативу мыши.
- Экспорт и ошибки понятны человеку, который не знает внутреннюю архитектуру.
- Никакая новая функция не ломает официальный формат и автономный пакетный запуск.
- Успешность, время прохождения и число действий измеряются на фиксированных пользовательских сценариях; до замера экономию времени не заявлять.

## Что оставить за пределами этого месяца

PACS; универсальная МИС; чат с генеративными медицинскими советами; мобильное приложение; облачная многопользовательская платформа; автоматическое переобучение по любым правкам; декоративные 3D-сцены. Возвращаться к ним при конкретной потребности. Главная демонстрационная ценность сейчас — понятный результат на настоящем снимке, управляемое исправление, полноценный отчёт и самостоятельная работа поставки.
