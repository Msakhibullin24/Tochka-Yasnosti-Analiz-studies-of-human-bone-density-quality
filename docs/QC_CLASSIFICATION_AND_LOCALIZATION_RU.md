# Бинарный QC, типы нарушений и локализация

Дата: 2026-09-22. План ниже частично реализован: обучены три кандидата с замороженными
encoder, доступен дополнительный вывод в продукте, экспорт и Grad-CAM через CLI.
18 таблиц NHANES скачаны и проверены. Целевые анатомическая модель и детектор дефектов
пока не обучены. [Команды и фактические результаты](../competition/docs/SPECIALISTS.md).
Дополняет [решение по моделям и данным](MODEL_AND_DATA_DECISION_RU.md) и
[план анатомической локализации](SPECIALIZED_SPINE_MODEL_RU.md).

## Проверка исходных предположений

### NHANES

Официальные публикации [whole-body 2017–2018](https://wwwn.cdc.gov/Nchs/Data/Nhanes/Public/2017/DataFiles/DXX_J.htm)
и [spine 2017–2018](https://wwwn.cdc.gov/Nchs/Data/Nhanes/Public/2017/DataFiles/DXXSPN_J.htm)
описывают таблицы измерений и статусов. Открытый корпус DICOM/PNG с привязанными
QC-метками в проверенных публикациях не найден. Наличие таблиц не обеспечивает
обучение классификатора изображений; доступность пикселей требует отдельного подтверждения.
Не считать NHANES готовым эталонным image-QC датасетом для нашего продукта.

Периоды сбора различаются: whole-body — 1999–2006 и 2011–2018;
позвоночник — 2005–2010, 2013–2014 и 2017–2018 по указанному spine codebook.
Нет единого непрерывного набора всех протоколов за 1999–2018.

[Ранние файлы](https://wwwn.cdc.gov/Nchs/Nhanes/Dxa/Dxa.aspx) содержат по пять
записей на участника из-за множественной импутации. Это не пять сканов.
Объём в «сотни тысяч изображений» не подтверждён; считать строки таблиц снимками нельзя.
Импутированное измерение не означает наличие изображения или исправленный дефект.

Коды следует читать отдельно для каждого протокола, цикла и анатомической области:

- В [whole-body 2005–2006](https://wwwn.cdc.gov/nchs/data/nhanes/public/2005/datafiles/dxx_d.htm)
  есть отдельные коды для удаляемых объектов, неудаляемых объектов, шума при ожирении,
  перекрытия конечностей, выхода из кадра, позиционирования и прочего.
  Движение включено в `Other`, отдельной метки `Motion` здесь нет.
- В whole-body 2017–2018 удаляемые и неудаляемые объекты объединены в коде `1`.
  Восстановить их разделение из этого кода нельзя.
- Региональные статусы bone/soft tissue не являются исчерпывающим multilabel-эталоном
  всех дефектов кадра. Пропуск кода не равен отрицательной метке.

Панникулит не является синонимом жирового фартука или шума при ожирении;
объединять эти понятия в обучающую метку нельзя. Кальциноз также не следует
автоматически размечать как имплант.

Роль NHANES сейчас: справочник QC-категорий и источник табличной статистики с учётом
дизайна обследования. Использование как image training source возможно только после
подтверждения изображений, условий доступа и связи с конкретными QC-записями.

### Библиотеки и предобучение

[timm](https://github.com/huggingface/pytorch-image-models) предоставляет архитектуры
и предобученные веса общего назначения; сам по себе он не предоставляет обученный
DXA-QC классификатор. ConvNeXt-V2, EfficientNet-B4 и Swin — кандидаты для сравнения.

[ASL](https://github.com/Alibaba-MIIL/ASL) разработан для дисбаланса multilabel-задач.
Публикация не устанавливает его как стандарт или лучшую функцию потерь для нашего DXA QC.
Сравнивать с masked BCEWithLogitsLoss при одинаковых данных и вычислительном бюджете.

[TorchCAM](https://github.com/frgfm/torch-cam) поддерживает Grad-CAM и другие CAM-методы.
Для явно заявленного HiResCAM есть [pytorch-grad-cam](https://github.com/jacobgil/pytorch-grad-cam).
Нужна одна выбранная библиотека с проверкой совместимости конкретной модели.

[YOLO26x](https://docs.ultralytics.com/models/yolo26/) поддерживает детекцию и сегментацию,
но стандартные веса не являются DXA-детектором имплантов. Ссылка на главную Roboflow Universe
не определяет датасет: до использования нужны точный проект и версия, список классов,
тип изображений, вид аннотаций, происхождение и условия использования.
Классификационные метки имплантов нельзя автоматически превратить в bbox/mask-эталон.

## Предлагаемая схема продукта

`DICOM → область/проекция → анатомия + визуальный QC + детекция объектов → общее решение`

| Ветка | Выход | Проверяемая ответственность |
|---|---|---|
| Анатомия | Номера, контуры, ориентиры, видимость | Охват, ось, признаки ротации и отношение ROI к анатомии |
| Визуальный QC | Бинарный score и вероятности отдельных нарушений | Артефакты, движение и другие классы, для которых есть разметка |
| Детектор объектов | Класс, bbox; mask при необходимости | Где расположен объект и пересекается ли он с нужной областью |
| Правила | Итог, причины, неопределённость | Применимость признака к конкретному протоколу и критерию |
| CAM | Карта вклада для выбранного выхода | Дополнительная информация для просмотра, не доказательство дефекта |

Для визуального QC предлагается общий encoder и две головы: бинарная и multilabel
с независимыми sigmoid. Отдельные модели позвоночника и бедра сравнивать с общим
encoder, а не заранее удваивать все веса. Total-body оценивается отдельно.

Разметка каждого класса: `present / absent / unknown / not_applicable`.
Неизвестные и неприменимые метки исключаются из loss; пустое поле не становится нулём.
На первом этапе использовать имеющиеся классы ТЗ; motion и другие новые категории
добавлять только после определения критериев и получения положительных/отрицательных примеров.
Не обещать их обучение по текущей бинарной разметке.

Бинарная непригодность, присутствие объекта и тип нарушения — разные целевые переменные.
Имплант вне оцениваемой ROI не должен автоматически браковать нужную область.
Правило зависит от протокола и разметочного стандарта; одного факта пересечения тоже
недостаточно для всех видов артефактов. Кальциноз — отдельная анатомическая находка.

Общий вердикт нельзя строить как OR всех визуальных находок. Он учитывает только
нарушения, которые делают выбранное измерение непригодным по принятому критерию.
Если бинарная голова обнаружила проблему, но тип не подтверждён, сохранять
«тип не определён». Для непроверяемого критерия — `undetermined`, а не `pass`.
Технический отказ чтения файла не является отрицательным QC-примером.

## Изображения и локализация

Сохранять полный кадр и пропорции: random crop способен удалить дефект охвата,
поворот — изменить целевую метку оси. Изменяющие критерий аугментации допустимы
только с согласованным пересчётом разметки. Разделять реальные и синтетические дефекты.

Для мелких объектов проверить глобальный кадр плюс локальные фрагменты достаточного
разрешения. Выигрыш измерять на реальных мелких артефактах, не по размеру входного tensor.
Преобразования bbox/mask и CAM должны возвращаться в исходные координаты DICOM.

CAM строится отдельно для каждого класса и подписывается как вклад в предсказание.
Пороговая обработка CAM не создаёт проверенную маску или bbox. Для детектора требуется
экспертная объектная разметка, включая отрицательные кадры и неоднозначные объекты.
Маски нужны, когда bbox недостаточен для отношения объекта к ROI; движение может
проявляться глобально и не обязано иметь отдельную рамку.

## Связь с текущим кодом и эксперименты

Сейчас `competition/dxaqc/model.py` использует геометрию, RF/LR и замороженные
ResNet18-признаки из `embedding.py`. Это обязательный контрольный baseline.
`decision.py` уже отделяет бинарный флаг от известного типа нарушения.
Новый classifier должен отдавать score/вероятности в этот общий слой, сохраняя
словарь экспортируемых нарушений и версионируя новые правила.

Текущий ансамбль содержит недифференцируемые компоненты: CAM только для encoder
не объясняет его итоговый вердикт. Для новой дифференцируемой головы CAM может объяснять
именно эту голову; связь с финальным правилом должна быть показана отдельно.

Порядок ограниченных экспериментов:

1. Проверить привязку снимок–метки–пациент; зафиксировать определения классов,
   неизвестные метки, источники и независимую тестовую часть. Проверить дубликаты.
2. На тех же группах сравнить текущий baseline с ConvNeXt-V2 Tiny: сначала
   замороженные признаки, затем частичное дообучение. EfficientNet-B4 — следующий
   кандидат при обоснованной пользе; Swin не включать одновременно без причины.
3. На выбранной архитектуре сравнить masked BCE и masked ASL. Веса классов,
   sampler, калибровку и пороги выбирать только внутри training/validation.
   Не применять одновременно несколько способов компенсации дисбаланса без абляции.
4. Отдельно обучить детектор на размеченных целевых DXA. Внешний рентгеновский
   датасет проверить как источник переноса, сравнив с обучением без него.
5. Добавить анатомические проверки и оценить изменение итогового QC на тех же
   отложенных пациентах. После выбора — полный офлайн-прогон и проверка экспортов.

Основные метрики: бинарные F1, ROC-AUC, PR-AUC, чувствительность/специфичность;
для multilabel — по каждому классу и macro/micro, с количеством положительных случаев.
Отдельно показывать калибровку, долю отказов и качество на всей выборке, включая отказы.
Доверительные интервалы считать по пациентам. Для детектора — recall и ложные находки
на снимок, AP/IoU; для масок — Dice/IoU. Проверять перенос между аппаратами и областями.
CAM оценивать на независимой разметке локализации и проверках зависимости от весов
модели; визуально убедительная карта сама по себе не является метрикой качества.

Порог приёмки и допустимый бюджет ошибок фиксируются до итогового теста.
В поставке закрепляются версии весов, preprocessing и словаря, контрольные суммы,
CPU-время и память полного pipeline. Реализованное подключение сохраняет основной
вердикт и отдельно возвращает экспериментальную оценку; замена рабочей модели не выполнена.
