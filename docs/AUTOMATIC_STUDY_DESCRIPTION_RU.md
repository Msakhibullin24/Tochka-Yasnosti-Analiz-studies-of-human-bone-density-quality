# Автоматическое описание исследования и динамики

В Dataset Workbench после выбора исследования показывается блок
«Автоматическое описание исследования». Текст собирается из уже сохранённых
данных и обновляется после экспертной разметки, подтверждённого измерения
МПК и расчёта динамики. Кнопка «Скачать описание» сохраняет UTF-8 TXT.

Описание перечисляет технические флаги и ограничения baseline, каждое
экспертное чтение с отмеченными дефектами, ориентирами и ROI, источник и
значения подтверждённой МПК, а также результат сравнения с предыдущим
исследованием по каждой общей области измерения. Разные экспертные чтения
остаются раздельными; при расхождении выводов текст прямо сообщает об этом.

Динамика берётся из существующего `osseo-longitudinal/2.0.0`: пользователь
выбирает предыдущее исследование и профиль LSC учреждения, после чего backend
проверяет пациента, даты, протокол, аппарат, качество, укладку, ROI и
cross-calibration. Если статус `review` или `not-comparable`, проценты
изменения показываются **без интерпретации значимости**. При смене исходного
исследования, профиля, подтверждённой МПК или экспертной разметки прежнее
сравнение скрывается до повторного расчёта.

Текст не вычисляет МПК из пикселей, не выставляет диагноз и не называет
непроверенный технический baseline клинической оценкой. Если данных нет,
раздел содержит явное «не внесено» или «не рассчитана». Реализация:
`src/services/study-description.ts`, `src/DatasetLongitudinal.tsx`.

Проверки: три сценария генерации текста, включая заблокированную динамику;
интерфейсный сценарий обновления после сравнения и скрытия устаревшего
результата; `pnpm run build`, `pnpm run lint`.

## Основное рабочее место DXA QC

В рабочем месте, которое открывается по умолчанию, у каждой группы снимков
есть «Описание находок»: оно перечисляет результат и статус проверки каждого
файла, ошибки обработки, обнаруженные критерии, непроверенные анатомические
пункты, проекцию и наличие исходной ROI. Последняя сохранённая экспертная
версия добавляет решение, подтверждённые нарушения, комментарий, разметку и
последующие действия отдельным блоком от вывода модели. Описание можно скачать в TXT.
Повторные экспорты не скрываются, поскольку их исходные ROI могут различаться.

Раздел «Анализ в динамике двух DXA» принимает два явно выбранных DICOM и
использует существующий локальный API `POST /api/v1/compare`. Перед расчётом
пользователь подтверждает по документам, что это один пациент и второй
снимок сделан позже: API не устанавливает это по обезличенным UID. Значения
МПК и LSC вводятся отдельно. Все проверки сопоставимости попадают в
автоматическое описание. При статусе `review` или `not_comparable` API и клиент
показывают численное изменение, но не выдают вывод о его значимости.
