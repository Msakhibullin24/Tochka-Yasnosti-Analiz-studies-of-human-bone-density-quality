# Исправления аудита — 1.7.0, решение версии 3

## Реализовано

1. **Единый итог критериев.** Положительный критерий больше не подавляется общим классом.
   Итог положительный при положительном бинарном детекторе или хотя бы одном сработавшем
   критерии. Для каждого критерия сохраняются состояние и основание (`criterion_states`).
2. **Ось и 5°.** При конечном измеренном угле критерий оси определяется условием >5°;
   ровно 5° допустимо. Недоступное измерение даёт `undetermined`, не подтверждённый тип.
   Расхождение с классификатором явно помечено для проверки. Локализация оси не становится
   клинически валидированной от введения этого правила.
3. **Неопределённый тип.** Удалён выбор максимального критерия ниже его порога.
   При положительном бинарном результате без установленного типа: класс 1, пустой
   `violation_type`, `violation_type_status=undetermined`, явное замечание. В UI это
   не отображается как отсутствие нарушений. Можно сохранить черновик; подтверждение
   требует выбора типа или решения «Невозможно оценить» с причиной.
4. **Предполагаемый металл.** Насыщенные пиксели больше не превращаются автоматически
   в имплант, ошибку ROI и score 0,99. Создаётся замечание для проверки. Старые записи
   и экспертные решения с кодом импланта сохраняют совместимость.
5. **Точная принадлежность растровой ROI.** Сохраняются компактные интервалы исходных
   включённых пикселей. Попадание точки проверяется по ним, а контуры служат отображению.
   Покрыты отверстия, их границы, тонкие участки, одиночные пиксели, смещение origin.
   Для дробных точек используется ближайший центр пикселя с полуоткрытой внешней границей.
6. **Отказ при неоднозначном большом вертеле.** Компонент, выходящий на верхнюю границу,
   не даёт кандидата большого вертела. Правило также действует на запасной контур при
   отсутствии оси диафиза. Это отказ от неподтверждённой точки, не завершение локализатора.
7. **Согласованные ориентиры.** UI и SC используют один текущий набор кандидатов бедра.
   Отброшенные точки не возвращаются через старый слой. Числовые признаки обученной
   модели сохраняются отдельно и подписаны как признаки модели.
8. **Ограничения при экспорте.** SC явно показывает незавершённость анатомической проверки,
   отсутствие Th12, состояние проекции/исходной ROI. SR и HTML передают ограничения и
   основания проверки. Формулировка «Качественное исследование» не используется для
   ограниченного модельного класса. Некалиброванный score не называется вероятностью.
9. **Идентичность DICOM-объектов.** SOPInstanceUID производного SC/SR учитывает источник
   и содержимое отчёта; изменившееся решение получает новый UID. Только время обработки
   не меняет UID SR. Это предотвращает отождествление разных результатов в получателе.

## Изменение выходного контракта

Первые восемь колонок и quality_prob сохранены. В расширенном выводе добавлены
`criterion_states`, `violation_type_status`, `review_reasons`; `decision_version=3`.

Пустой тип при классе 1 — явный незавершённый результат типизации, **не выполнение
требования определить тип**. Валидатор допускает его как корректно представленную
неопределённость и выдаёт предупреждение о неполной типизации. В расширенной таблице
требуется статус `undetermined`; в строгой таблице дополнительные поля отсутствуют,
поэтому предупреждение формируется из сочетания класса и пустого типа.
Новые официальные категории нарушений не придуманы. Потребители, ранее предполагавшие,
что каждый класс 1 обязательно имеет тип, должны обрабатывать этот случай отдельно.

Исходные машинные результаты и экспертные версии старых заданий не переписаны.
Для получения новой оценки нужно новое задание с исходными DICOM.

исследованиям, внутренний подбор порогов, 249 отложенных изображений. Рабочие веса
не заменены. Новые правила не подбирались перебором по этим внешним результатам.

подтверждённого превосходства или переносимости на новую клинику не заявляется.

Порог не снижался по внешним фолдам ради исправления этой цифры. Требуется работа
с обучающей выборкой и последующая независимая оценка критерия артефактов.

`decision_v3_comparison.json` с парным сравнением, конкретными матрицами ошибок и SHA правил.

## Что остаётся незавершённым

- Полноценные Th12 и проверенная нумерация позвонков.
- Валидация ориентиров и распознавания альтернативных проекций по пикселям.
- Анатомический вердикт исходной ROI и анатомическая автокоррекция.
- Надёжная типизация всех положительных случаев, особенно критерий артефактов.
- Независимая клиническая и полная DICOM-проверка, закрытая выборка организатора.

Ни отсутствие противоречий в коде, ни успешное чтение всех файлов не закрывают эти пункты.

## Воспроизведение технического аудита

```sh
./competition/run.sh build
./competition/run.sh test
./competition/run.sh batch /absolute/input.zip /absolute/fresh-output
python competition/audit_consistency.py --results /absolute/fresh-output/results.csv \
  --output /absolute/consistency.json
```

Проверка согласованности отдельно считает неопределённые типы; они не исчезают из отчёта
при нулевых счётчиках программных противоречий. Это проверка вывода, не клиническая оценка.
