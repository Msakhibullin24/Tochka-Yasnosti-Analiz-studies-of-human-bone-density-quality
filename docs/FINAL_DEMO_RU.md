# Проверка и демонстрация конкурсной поставки

Версия 1.5.0. Документ — исполнимый сценарий и структура защиты, а не свидетельство независимой клинической приёмки.

## Запуск проверяющим

Из корня репозитория:

```sh
./competition/run.sh build
./competition/run.sh test
./competition/run.sh batch /absolute/path/input.zip /absolute/path/results-a
./competition/run.sh batch /absolute/path/input.zip /absolute/path/results-b
```

Проверка таблицы и повторяемости в поставленном контейнере:

```sh
docker run --rm --network none \
  -v /absolute/path/results-a:/a:ro -v /absolute/path/results-b:/b:ro \
  osseo-dxaqc:1.5.0 python -m dxaqc.validate_results \
  --results /a/results.csv --repeat /b/results.csv --series /a/additional_series.zip
```

Для проверки комплектности добавьте `--manifest /a/expected-paths.json`: JSON-массив путей входных изображений относительно корня обработки. Манифест собирается независимо до запуска, не из выходного CSV. Для архивных ошибок учитываются также ожидаемые строки отказов; отсутствие манифеста явно отмечено в протоколе.

Валидатор проверяет поля таблицы, словарь результатов, согласованность класса и типов, диапазоны чисел, время по исследованию, при наличии — комплектность и повторяемость. Код выхода 0 означает успех выполненных проверок; код 1 — ошибку. Опция `--series` проверяет читаемость SC/SR, ссылки на исходные изображения и наличие обоих объектов для каждого UID. Это не полная проверка соответствия DICOM. Валидатор не подтверждает клиническую правильность, соответствие всех SC/SR стандарту или скорость на оборудовании организатора.

## Демонстрация за 5 минут

1. Загрузить небольшой доступный обезличенный пакет. Показать несколько изображений одного исследования, итог модели и ошибки отдельно.
2. Открыть позвоночник: карточка оси, реальный измеренный угол, соответствующие машинные ориентиры. Показать границу возможностей: локализация Th12 отдельно не выполнена.
3. Открыть бедро. Добавить ROI, явно выбрать левый или правый край изображения. Показать расчёт отступов и источник масштаба.
4. Если масштаб известен и перенос возможен, раскрыть предложение, проверить координаты, принять и отменить. Если доступен только масштаб аппарата, показать честный отказ от предложения. Демонстрационный геометрический пример не обозначать экспертной анатомической разметкой.
5. Добавить замечание, сохранить версию и скачать её отчёт. В отчёте присутствуют изображение, комментарии и геометрическая оценка ROI.
6. Скачать «Проверка формата ТЗ»; показать отдельно прогон валидатора с независимым манифестом и повторным запуском.

Не редактировать рабочие медицинские решения ради демонстрации: использовать отдельную учебную загрузку. Не заявлять прирост качества модели от интерфейсных изменений.

## Структура презентации

1. Задача: контроль качества DXA; позвоночник и бедро; локальный поток DICOM → результат.
2. Критерии ТЗ и используемая таксономия; несколько нарушений в одном изображении.
3. Данные и предотвращение утечек: группировка, дедупликация, разбиения, ограничения независимости пациентов.
4. Модель и правила итогового решения; результаты из актуального отчёта CV с доверительными интервалами. Показать `pipeline_audit_1_5.json`: общий внешний фолд роутера и моделей качества, внутренний подбор порогов, отложенные исходные DICOM.
5. Рабочее место: основания результата, правки, версии, второе мнение и отчёт.
6. Надёжность: проверенные отказы DICOM, ZIP, отмена, контракт таблицы, повторяемость.
7. Замеры на явно указанной машине: CPU, память, время и размер входа; исторические замеры не подписывать новой версией.
8. Ограничения и пилот: неоднозначность входной разметки, неподтверждённые ориентиры, отсутствие экспертной проверки геометрической коррекции.

## Открытые пункты перед окончательной сдачей

- Письменное разъяснение формата входной ROI: основной PDF одновременно описывает вход без разметки и проверку разметки.
- Независимая проверка ориентиров и предложений ROI. Сквозная оценка DICOM → Analyzer выполнена; формат и повторяемость CSV проверяются отдельно.
- Самостоятельное распознавание проекции по изображению: текущий код только отклоняет явно заявленную боковую проекцию.
- Проверка дополнительных DICOM-серий независимым валидатором; PACS не входит в объём.
- Независимый запуск другой командой и запись репетиции. Замеры релиза и готовые слайды: `FINAL_TZ_AUDIT_2026_09_20_RU.md`, `FINAL_PRESENTATION_RU.html`.
