# Пакет для врача: проверка конкурсного DXA-набора

Версия 1, 17.09.2026. Цель первого этапа — получить достоверную связь изображения с анатомической областью и экспертной оценкой. Это разметка для исследовательской разработки, а не заключения пациентам.

## Что открыть

Рабочая папка: `data/competition-v1/`.

- `image_review.csv` — 252 строки, одна на уникальное изображение; редактируется копия с именем/кодом эксперта.
- `images/` — PNG в исходном разрешении, без изменения пропорций или обрезки.
- `sheets/` — 100 листов по исследованиям; помогают сравнить изображения одного исследования.
- `priority_review.csv` — пять обнаруженных проблем разметки, которые нужно разобрать отдельно.
- `near_duplicate_review.csv` и `near_sheets/` — 36 пар кандидатов на похожие снимки с листами попарного просмотра; близость автоматически не доказывает одного пациента. Решения записывать в CSV.
- `study_labels.jsonl` — исходные оценки Excel, открывать после независимого первого чтения качества, чтобы уменьшить влияние прежних меток.

CSV открывать в UTF-8, разделитель — запятая. Не менять `image_id`, `image_path`, `sheet_path`, `excel_row`. Пустая метка означает «нет оценки», а не норму. Исходный Excel остаётся неизменным.

## Первый проход: область и сторона

Заполнить `anatomical_region`: `spine`, `hip_right`, `hip_left`, `unsupported` либо `uncertain`. Если сторону нельзя достоверно определить, выбрать `uncertain` и объяснить причину. Не угадывать сторону только для завершения таблицы.

В поле `reviewer` — стабильный код врача. `review_status`: `mapped` после определения области, `reviewed` после полной оценки применимых критериев, `unassessable` если оценить нельзя. Исходное значение — `pending`.

Можно сначала закончить только область/сторону всех изображений и передать таблицу инженеру; это уже позволит создать привязку исходных меток и обнаружить оставшиеся несоответствия.

## Второй проход: качество

Используется проектная кодировка: 0 — нарушение не выявлено, 1 — нарушение выявлено; требует подтверждения организатором для соответствия исходной таблице. Заполнить `quality_class` и только применимые критерии. Не применимые поля оставить пустыми.

| Поле | Применимо | Что оцениваем |
|---|---|---|
| spine_coverage | Позвоночник | Требуемый анатомический охват по ТЗ |
| spine_axis | Позвоночник | Отклонение оси согласно критерию до 5°; при сомнении в геометрии пометка в notes |
| spine_artifact | Позвоночник | Посторонние предметы, выраженные артефакты/наложения |
| hip_position_rotation | Бедро | Позиционирование и ротация по совокупности анатомических признаков |
| hip_roi_coverage | Бедро | Область/охват в смысле исходной конкурсной колонки; не считать проверкой отсутствующего vendor ROI |

Если criterion невозможно оценить, оставить пустым и записать причину в `notes`. Отсутствие масштаба не позволяет подтвердить конкретное расстояние в сантиметрах; визуальная оценка охвата должна быть отделена от измерения 2/3 см. Итоговый класс не обязан автоматически равняться OR критериев, пока правила не согласованы; любое расхождение пояснить.

Для проверки ROI оператора нужны сами ROI. На текущих изображениях нельзя подтверждать правильность границ, которые не представлены. Допустимо отдельно нарисовать предлагаемую ROI, но это другой тип аннотации.

## Обязательные разборы

| Строка исходного Excel | Причина |
|---|---|
| 8 | Все три критерия позвоночника 0, итог 1; комментарий «сколиоз» |
| 13 | Все три критерия позвоночника 0, итог 1; упоминается неверная разметка |
| 37 | Критерий оси 1, итог 0; комментарий «перелом» |
| 68 | Три уникальных изображения, две итоговые оценки |
| 72 | Три уникальных изображения, одна итоговая оценка |

В `priority_review.csv` записать решение: `keep_original`, `propose_correction`, `needs_organizer` или `unassessable`, код врача и основание. При предложении исправления указать старое и новое значение, поле, изображение и причину. Исходная и предложенная метки сохраняются обе; инженер не исправляет клинический класс по своему усмотрению.

Для 36 похожих пар определить: точный/близкий повтор одного исследования, вероятно связанный случай, разные исследования либо недостаточно информации. Похожие нормальные позвоночники часто не являются дублями. Подтверждённые связанные случаи должны находиться в одной группе валидации; сомнения фиксируются отдельно.

## Дальнейшая координатная разметка

После первых baseline-ошибок выбрать полезные ориентиры: центры/границы L1–L4, видимость Th12 и таза; для бедра — шейка, малый/большой вертел, седалищная кость и края охвата. Для невидимой структуры ставить `visible=false`, а не придумывать координату. Не смешивать недовключённую в кадр структуру с неопределённой из-за качества.

Использовать существующий формат координатной разметки проекта только после адаптации импорта этих GE-изображений: текущий Workbench ожидает иной manifest. PNG и CSV уже доступны; автоматическое подключение нового пакета к Workbench пока не реализовано.

При одном враче можно провести повторное слепое чтение спорных случаев. Межэкспертное согласие измеряется только при наличии второго независимого эксперта. Подтверждение кодов и критериев организатором сохраняется как отдельный документ.

Результат этапа: заполненный CSV, решения по пяти проблемам, решения по похожим парам, версия правил и список случаев без достоверной оценки. Отправка врачу выполняется владельцем данных; автоматическая рассылка не производилась.

## Проверка заполненной таблицы инженером

```bash
PYTHONPATH=backend backend/.venv/bin/python -m app.competition_review \
  --data data/competition-v1 \
  --review data/competition-v1/image_review_doctor.csv \
  --output data/review-doctor-v1
```

Путь `image_review_doctor.csv` — будущая заполненная копия. Выходной каталог должен быть новым. Проверка создаёт `summary.json`, `issues.jsonl` и `candidate_image_labels.jsonl`; исходные данные не изменяются. Проверяются все image_id, неизменяемые пути/строки Excel, применимость критериев, бинарные значения и код эксперта.

`mapped` означает только подтверждение области: клинические поля CSV остаются пустыми, в кандидаты переносятся исходные оценки Excel с явным происхождением. `reviewed` использует только оценки врача; его пустые поля не заполняются автоматически прежними значениями. Изменения, неполные оценки и расхождения итогового класса с критериями требуют пояснения. `unassessable` требует причины и пустых клинических меток; `uncertain`/`unsupported` оформляются этим статусом.

Если два разных изображения одного исследования привязаны к одной области, оба попадают в очередь разбора, а не получают одну оценку Excel автоматически. Противоречивые исходные оценки при одном лишь `mapped` также не переносятся до разбора. `pending` никогда не становится обучающим примером.

Это кандидаты меток, ещё не замороженная обучающая выборка: отдельно нужны подтверждение правил, разбор связанных исследований и фиксированное групповое разбиение. На исходной незаполненной таблице проверка дала 252 pending и 0 кандидатов; отчёт находится в `data/review-audit-v1/`.

Критерии конкурса берутся из предоставленного ТЗ и методических рекомендаций 2022 года. Дополнительный клинический контекст — [официальные позиции ISCD](https://iscd.org/official-positions-2023/); они не заменяют контракт конкурсной разметки.
