## Что реализовано

- В версии **1.9.2** решение класса качества теперь формируется только при наличии хотя бы одного определённого официального типа нарушения. Сильный бинарный сигнал без типа сохраняется в расширенном отчёте как `binary_only_review` для экспертной проверки. Решение имеет `decision_version=4` в диагностическом выводе; бинарная модель и её сохранённые веса не переобучались.
- Очередь экспертной сверки теперь принимает и прежние положительные строки без типа, и новые сигналы `binary_only_review`; коды и метки разметки она не меняет.
- Очередь формирует отдельный **слепой пакет** из уникальных изображений, двух пустых бланков и масштаба пикселя. Прогнозы, старые метки и соответствие DICOM-путям остаются вне папки `blind/`; после двух независимых чтений существующий `reconcile_reviews.py` отмечает согласие и расхождения, не меняя исходную разметку.
- Три компактных DAX энкодера измерены на одинаковых внешних фолдах по исследованиям. Все уступили текущему решению и остаются исследовательскими активами, без включения в контейнер и конкурсный вердикт.

## Что остаётся для роста точности

1. Получить экспертное решение по 11 уникальным случаям бинарного сигнала без типа. В первую очередь сверить `spine_axis`: в исходных положительных метках девять из десяти случаев не подтверждаются текущим правилом измеренного угла >5°. Нельзя повышать чувствительность снижением порога без проверки анатомической оси и определения метки.
2. Разметить независимым экспертом ось L1–L4, границы ROI, ориентиры бедра и артефакты на отдельных исследованиях. Измерить ошибку ориентиров в мм при анизотропном масштабе X/Y и качество масок. До этого LiteMedSAM остаётся инструментом предварительной разметки, без измеренной Dice и без автоматического вердикта.
3. После согласования меток повторить study-held-out сравнение по всем официальным типам, с парными доверительными интервалами и проверкой строгого CSV. Кандидат попадает в поставку только при воспроизводимом улучшении и подтверждённой клинической трактовке критерия.
4. Повторить полный демонстрационный сценарий с SC/SR и визуализациями на целевой машине. Измерения ноутбука нельзя переносить на RTX 5090 без фактического прогона.

После независимого заполнения `reviewer-A.csv` и `reviewer-B.csv` из папки `blind/` выполнить:

```bash
competition/.venv/bin/python competition/reconcile_reviews.py \
  --packet data/specialists/review/typed-v4-targeted-final-2026-09-24/blind \
  --review-a data/specialists/review/typed-v4-targeted-final-2026-09-24/blind/reviewer-A.csv \
  --review-b data/specialists/review/typed-v4-targeted-final-2026-09-24/blind/reviewer-B.csv \
  --output data/specialists/review/typed-v4-targeted-final-2026-09-24/agreement.json
```

Проверенные открытые источники не дают готового классификатора конкурсных ошибок: [DXA-to-3D](https://github.com/EmmanuelleB985/DXA-to-3D) предсказывает геометрию позвоночника, но имеющийся checkpoint пока не сопоставлен с именованными ориентирами нашего набора; [Vertebra-Landmark-Detection](https://github.com/yijingru/Vertebra-Landmark-Detection) обучен для оценки сколиоза на рентгенограммах, а не на AP DXA. Автоматически присваивать на их основе официальный тип нарушения без DXA-валидации нельзя.

Техническая валидность сдачи достигнута для проверенного локального пути. Точность по отдельным нарушениям, независимая клиническая оценка и результаты закрытого теста пока не подтверждены.
