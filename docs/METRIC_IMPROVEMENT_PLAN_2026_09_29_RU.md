DXA организатора: `[TN, FP, FN, TP] = [142, 34, 28, 45]`, F1 **0,592**,
чувствительность **0,616**, специфичность **0,807**. Из 170 автоматически

Этот показатель не заменяет клиническую долю критических пропусков:
критичность в наборе не размечена.
По 2000 групповых bootstrap-повторов 95% интервалы текущего постфактум
OOF: F1 **0,494–0,679**, чувствительность **0,514–0,721**,
специфичность **0,733–0,868**, доля ложных норм среди автоматических норм
**10,8–22,5%**. Они описывают вариацию на той же изученной выборке.

## Что проверено и отвергнуто

Дополнительно проверен CatBoost 1.2.10 с фиксированными параметрами на 11
геометрических признаках бедра. Пять внешних фолдов разделены по
исследованиям; в каждом внешний порог F1 выбирался только по четырём
внутренним фолдам. На тех же 150 снимках и тех же внешних фолдах текущий
ансамбль получил `[TN, FP, FN, TP] = [87, 27, 14, 22]`, F1 **0,518**,
чувствительность **0,611**; CatBoost — `[89, 25, 14, 22]`, F1 **0,530**,
чувствительность **0,611**. Парный групповой интервал 95% для ΔF1:
**−0,103…+0,136**. Подтверждённого прироста нет, рабочая модель не изменена.
Построчные прогнозы и хеши входов сохранены в
[`dxa_hip_catboost_probe_2026_09_29.json`](competition/dxa_hip_catboost_probe_2026_09_29.json)
и соседнем OOF CSV. Исследование относится только к совмещённой метке
укладки/ротации, не измеряет подтипы ротации и общий итоговый QC.

Проверено фиксированное постфактум правило: тревогу
`criterion_failure` оставлять только при согласии общей оценки качества
с её порогом; обязательный измеренный тип оси `>5°` сохранять.
Результат `[153, 23, 32, 41]`, F1 **0,599** вместо 0,592, но
чувствительность **0,562** вместо 0,616, а число ложных норм выросло
с 28 до 32. Групповой bootstrap по исследованиям для ΔF1:
**−0,045…+0,054**; для Δчувствительности: **−0,109…−0,012**.
Правило снижает безопасность при ничтожном и неопределённом приросте F1.
Оно не включено в поставку. Это постфактум исследование на уже изученной
выборке, не независимая проверка.

## Последовательность дальнейшей разработки

| Приоритет | Работа | Метрика и критерий продвижения |
|---|---|---|
| 1 | Улучшить обнаружение нарушений укладки **левого бедра** на фронтальных DXA: анализ ошибок 10 FN, признаки малого вертела, диафиза и анатомии шейки; сравнение с текущим ансамблем на одинаковых исследованиях. | Общий QC и совмещённая метка бедра: F1, чувствительность, FP, число ложных норм, парные доверительные интервалы. Сохранять только кандидата без роста пропусков; не трактовать общую метку как подтипы ротации. |
| 2 | Исправить измерение **оси позвоночника** через проверенные границы L1–L4 и отдельные углы позвонков. | Сначала ошибка углов в градусах на независимых DXA ориентирах; затем чувствительность/F1 общей метки оси при строгом пороге `>5°`. Нельзя подменять физический порог классификатором бинарной метки. |
| 3 | Снизить ложные тревоги в правилах укладки без роста FN: разбирать 28 FP `criterion_failure` по признакам и изображениям. | Парная оценка F1, чувствительности и доли ложных норм; постфактум подбор порога на тех же OOF не считать подтверждением. |
| 4 | Измерить отсутствующие анатомические критерии Th12, гребней, нумерации и границ, шейки, отступов ROI и подтипов ротации. | Нужны отдельные DXA метки полного контура/ориентиров и варианты нарушений. Отчитываться по Dice/MAE/ошибке угла/чувствительности каждого критерия; без эталона писать `не измерено`. |
| 5 | Проверить проекцию бедра на AP, lateral и oblique DXA разных производителей. | Строгие метки проекции, доля безопасных отказов, FN неподдерживаемой проекции, разрезы по производителю. |

Для каждого обучаемого кандидата сохранять разделение по исследованиям,
внутренний подбор порогов только на обучающей части, хеши пикселей и
построчные прогнозы. Улучшение F1 на старых OOF само по себе не является
основанием для медицинского выпуска. Нужен ранее не просмотренный DXA
набор с проверенной независимостью пациентов и подтверждёнными метками.

Добавлен автоматический [экран сравнения кандидатов](../competition/experiments/verify_metric_candidate.py).
Он требует совпадения всех 249 изображений, исследований, фолдов и истинных
меток, проверяет согласованность класса и официального типа, а также
физическое правило оси `>5°`. Отчёт содержит общие и региональные матрицы,
парный групповой интервал ΔF1. Внутренний кандидат проходит экран только
при росте F1 с положительной нижней границей интервала, без снижения
чувствительности, дополнительных ложных норм и ухудшения F1 в любой из
трёх областей. Экран проверен на совпадающей с собой базе
([отчёт](competition/metric_screen_selfcheck_2026_09_29.json)) и на
контрфактическом правиле выше: последнее отклонено за четыре добавленных
пропуска. Даже успешное прохождение экрана не является клинической
валидацией или разрешением на выпуск.

Проверка полей DICOM показала: `PatientID`, `PatientName`, дата рождения и
номер направления имеют по одному значению на всех 249 размеченных
изображениях из 100 исследований. `StudyInstanceUID` различает 100
исследований. Эти поля **не доказывают** независимость пациентов.
Одинаковое значение поля пациента не следует интерпретировать как одного
реального пациента: экспорт обезличен и непригоден для такого вывода.

[ISCD DXA Atlas](https://iscd.org/iscd-dxa-atlas/) даёт полезные экспертные
примеры критериев, но доступ к его изображениям и их использование
ограничены условиями ISCD для членов организации. Изображения атласа не
включены в данные проекта и не подменяют независимый тест.
