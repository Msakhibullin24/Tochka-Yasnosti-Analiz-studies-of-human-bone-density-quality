## Официальные типы нарушений

Тип считается обнаруженным только если он **присутствует в итоговом `violation_type`**
положительной строки. Таким образом таблица оценивает результат для сдачи, включая
пропуски типизации. AUC по отдельным типам не рассчитывается: в сохранённом OOF нет
вероятности каждого официального типа. Macro-F1 по пяти критериям — **0,488**.

## Диагностика поставляемой модели на обучающих снимках

Полный контейнерный прогон 1.9.1 обработал 499/499 DICOM. Для сопоставления с
разметкой взяты 249 исходных путей с известным классом, по одному на запись метки.
Получилось F1 **0,967**, ROC-AUC **1,000**, матрица `[171, 5, 0, 73]`.
Это результат **на снимках, участвовавших в обучении**; он не оценивает качество
на новых исследованиях и не заменяет OOF. Несмотря на высокий бинарный результат,
официальный тип оси позвоночника здесь найден лишь в 1 из 10 случаев; 11 из 249
положительных строк не имеют типа. На всех 499 физических DICOM таких строк 19,
поэтому строгая проверка полной сдачи не проходит.

## Внешние модели и следующие действия

DXA-to-3D: checkpoint проверен; на 12 поясничных DICOM все выходы конечные,
медиана CPU-времени 4,03 с. Это модель формы позвоночника с нерасшифрованным для
конкурсных меток выходом; F1/AUC по QC отсутствуют. Остальные предложенные
репозитории не дают применимого готового checkpoint для этой задачи.

1. Сначала получить экспертную сверку 19 релизных строк без типа (11 уникальных изображений)
   и согласовать трактовку спорной разметки оси позвоночника с куратором.
2. Исправить общий путь решения и повторить полный строгий прогон 499 DICOM.
3. Для улучшений ориентироваться на OOF по официальному выходу: ось позвоночника,
   ротация бедра, ROI бедра. После изменений пересчитывать study-held-out оценку
   без подбора порога на тех же тестовых предсказаниях.
