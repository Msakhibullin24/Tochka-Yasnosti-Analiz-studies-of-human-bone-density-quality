# Сверка проекта с материалами Минздрава — 25.09.2026

## Вывод

Текущий кандидат **1.9.4 технически принимает доступные DICOM и формирует валидную конкурсную таблицу**. Полное соответствие клинической части ТЗ пока не подтверждено: определение проекции и анатомических ориентиров остаётся предварительным, а исходной ROI в предоставленных снимках нет. Закрытый набор и заключения экспертов недоступны, поэтому первое место или клиническую точность обещать нельзя.

Это актуальная точка отсчёта. [Аудит 24.09](HACKATHON_READINESS_AUDIT_2026_09_24_RU.md) фиксирует исторический дефект версии 1.9.1: 19 положительных строк без типа. В 1.9.4 этих невалидных строк уже нет, но **19 бинарных сигналов без определённого типа** остаются в расширенном отчёте с `decision_reason=binary_only_review` и классом 0 в конкурсном CSV. Их клинический смысл требует проверки.

## Что сверено

- Исходное ТЗ `4. ДепЗдрав.pdf`: разделы 2–8, в том числе формат выхода, критерии укладки, требования к финальной сдаче и рекомендуемые метрики.
- Методические рекомендации по ДРА из той же папки: разделы 2.6, 2.7 и приложение Д. Они раскрывают ориентиры позвоночника и бедра, ротацию, анатомическую ROI. Описание «шейка отсканирована в боковой проекции» в разделе 2.7 относится к виду шейки при правильной ротации бедра; это не разрешение считать весь латеральный VFA-снимок эквивалентом целевого AP DXA.
- `Разъяснения по вопросам ЛЦТ_V2.docx`: масштаб Y=1,05 мм/X=0,6 мм, закрытые строки областей и нарушений, несколько типов через `;`, пустой тип при норме, дополнительный `quality_prob` от 0 до 1.
- `Датасет/НД_для_обучения`, `Датасет/Для теста`, код `competition/dxaqc/`, [сквозные метрики](../competition/reports/typed_v4_metrics.json), [протокол релиза 1.9.4](../competition/reports/release_1_9_4_router_2026_09_25.json), локальный полный `results_extended.csv` из `data/specialists/router-group-full-sc-sr-20260925/`.

Для этой сверки повторно выполнен `validate_results`: `submission.csv` принят профилем `competition_v2` (**499/499**, 0 ошибок); расширенная таблица проверена против **независимого списка 499 `.dcm`**, собранного из исходной папки `Исследования`, и `additional_series.zip` (**valid=true**, 0 ошибок, 0 предупреждений). Строгая таблица содержит только согласованные поля, поэтому сама по себе не проверяет комплектность входа и ссылки на серии. Некорректные исходные DICOM UID сохраняются как в файлах; проверка ссылок не равна полной DICOM-конформности.

## Точность и границы доказательства

[Текущий OOF-протокол](../competition/reports/typed_v4_metrics.json): один повтор, пять внешних фолдов по исследованию, 249 размеченных уникальных изображений из 100 исследований, 73 положительных. F1 **0,577** (95% кластерный ДИ 0,472–0,662), ROC-AUC **0,801** (0,729–0,867), чувствительность **0,562**, специфичность **0,841**; macro-F1 пяти критериев **0,488**. Позвоночник: F1 0,613 на 99 изображениях; бедро: F1 0,550 на 150. Особенно слабая ось позвоночника: F1 0,167, 1 TP и 9 FN. Эти числа отражают внутреннюю оценку с уже изученными командой данными; независимость пациентов между фолдами не доказана. Сохранённые поставляемые веса обучались на этих данных, поэтому их результат на полном учебном пакете не является оценкой обобщения.

Раздельные специалисты и внешние открытые модели не изменили основной конкурсный ответ в релизе 1.9.4. По [парному отчёту релиза](../competition/reports/release_1_9_4_router_2026_09_25.json) 249 OOF предсказаний побайтно совпали с предыдущим `typed_v4`; прирост F1 **0**. На внешних 20 бедренных снимках маршрутизация дала 18 определённых сторон против 14 прежде, но два случая явно отвергнуты как неуверенные; на этом наборе нет совместимых меток качества, поэтому это не прирост DXA QC F1.

## Исправленные и оставшиеся расхождения

1. **Исправлено в проекте:** инструкция переноса образа в корневом README теперь использует тег 1.9.4; ссылка на эту сверку ведёт к текущему статусу. План отдельно различает официальный H200-стенд и ПК команды с RTX 5090.
2. **Не закрыто клинически:** Th12, гребни подвздошных костей и бедренные ориентиры требуют координат/масок с экспертным эталоном; `anatomical_checks_complete=false` для всех 499 строк. Включать неподтверждённый ориентир в автоматический вердикт как установленный факт нельзя.
3. **Не закрыто по данным:** исходная ROI отсутствует во всех 499 DICOM; нужны поддерживаемые контуры или независимая анатомическая разметка. Датасет «Для теста» содержит 3 DICOM без ответов, он проверяет только работоспособность.
4. **Не закрыто по договорённости:** как кодировать Failure в восьми обязательных полях, из материалов не следует. Сейчас строгий валидатор проекта допускает такой случай; это локальное решение, а не подтверждение организатора.
5. **Не закрыто по валидации:** нет запечатанного независимого набора, доказанного разделения пациентов, повторной слепой врачебной разметки спорных случаев и замера на H200. Для оси позвоночника и ротации бедра менять официальное правило по текущим OOF без этой проверки рискованно.

## Следующий проверяемый цикл

1. Два специалиста независимо заполняют [слепые бланки](../competition/docs/SPECIALISTS.md) для 11 спорных уникальных изображений; затем сводятся расхождения и фиксируется происхождение каждой метки. До этого `binary_only_review` остаётся запросом на проверку, а не новым официальным типом.
2. Создаётся экспертный эталон Th12/L1–L4, краёв таза, бедренных ориентиров, проекции и ROI с видимостью и причиной «не определить». Сначала считается ошибка локализации и доступность критерия, затем влияние на итоговый F1.
3. Кандидаты сравниваются на одинаковых групповых разбиениях с порогами из внутренних фолдов; сохраняются парные предсказания, TP/FP/FN, поддержка каждого типа и ДИ. Закрытый новый набор используется один раз после выбора.
4. Перед сдачей повторяется полный офлайн-пакет и проверка manifest, strict CSV, отказов, SC/SR, повторяемости и времени **с включёнными сериями** на финальной машине. Если появится доступ к H200, время на официальном стенде измеряется отдельно.
