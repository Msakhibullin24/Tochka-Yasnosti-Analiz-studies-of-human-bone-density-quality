# Стратегия решения уровня первого места

## 1. Что на самом деле определит место

Побеждает не самый сложный нейросетевой backbone, а система без утечки данных, с согласованной экспертной таксономией, сильной out-of-fold валидацией и контролем редких нарушений. До получения датасета любые числа качества были бы выдуманными, поэтому этот документ задаёт воспроизводимый путь к лучшим метрикам.

Приоритеты:

1. нулевая утечка пациента, исследования, серии, клиники и модели денситометра между train/validation/test;
2. отдельное моделирование анатомии, ROI и артефактов вместо одной непрозрачной классификации;
3. оптимизация под точную официальную метрику конкурса на OOF-предсказаниях;
4. высокая чувствительность к критическим дефектам при контролируемой доле ложных тревог;
5. демонстрация работающего DICOM-контура, объяснений и отказа от ответа при высокой неопределённости.

## 2. Таксономия разметки

До обучения эксперт и ML-команда фиксируют `labelbook-v1` с визуальными примерами, пограничными случаями и правилом разрешения конфликтов. Каждый кейс получает независимую разметку двух экспертов; расхождения разбирает третий эксперт. Для каждого класса считаются Cohen’s kappa или Krippendorff’s alpha. Классы с низкой воспроизводимостью сначала уточняются, а не передаются модели как «истина».

### Поясничный отдел

- неверный протокол или проекция;
- позвоночник не по средней линии;
- наклон или аксиальная ротация;
- неполный охват L1–L4;
- ошибка нумерации позвонков;
- линия ROI пересекает межпозвонковое пространство;
- неверная глобальная ROI или граница мягких тканей;
- ошибочное включение/исключение позвонка;
- гиперденсный или гиподенсный артефакт над костью;
- внешний предмет, металл, кальцинат, двигательный артефакт;
- ошибка edge detection.

### Проксимальный отдел бедра

- наружная или недостаточная внутренняя ротация;
- выраженная абдукция/аддукция;
- ось бедренной кости не выпрямлена;
- неполный охват головки, шейки, большого/малого вертела или диафиза;
- перекрытие шейки седалищной костью;
- неверная femoral-neck ROI;
- ROI не привязана к большому вертелу;
- неверная нижняя граница total-hip ROI;
- неверная граница кости/мягких тканей;
- артефакт над костью или в мягких тканях.

Для каждого дефекта хранятся: `present`, `severity`, `action` (`accept`, `review`, `repeat`), polygon/mask или keypoints, экспертная уверенность и причина невозможности оценки.

Критерии опираются на [ISCD Official Adult Positions](https://iscd.org/official-positions-2023/), [ISCD DXA Atlas: normal hip scan](https://staging.iscd.org/dxaatlas/normal-hologic-hip-scan/), [normal GE hip scan](https://staging.iscd.org/dxaatlas/normal-left-proximal-femur-scan-from-a-ge-idxa-densitometer/) и [spine positioning and rotation](https://iscd.org/dxaatlas/spine-positioning-and-rotation/). Порог конкретного производителя не переносится на другой аппарат без отдельной проверки.

## 3. Защита от утечки

Единица разбиения — пациент, а не картинка. Если доступны повторные исследования, они целиком остаются в одном fold. Дополнительно группируются Study/Series UID, клиника, оператор и аппарат.

Рекомендуемая схема:

- закрытый holdout: 15–20% пациентов, по возможности отдельные клиники и модели аппаратов;
- разработка: 5-fold stratified group cross-validation;
- внешний стресс-тест: производитель/модель аппарата, не встречавшиеся в train;
- temporal holdout: последние по времени исследования, если даты доступны;
- все пороги и ансамбли выбираются только по OOF, holdout открывается после заморозки решения.

Проверки утечки перед первым обучением:

- perceptual hash и near-duplicate search;
- совпадения UIDs и псевдонима пациента;
- серии одного исследования в разных folds;
- текстовые/графические подписи, вшитые в пиксели;
- характерные рамки, таблицы и UI конкретного экспортёра;
- распределение класса по клинике/аппарату: модель не должна «угадывать» ответ по источнику.

## 4. Препроцессинг DICOM

1. Валидировать SOP Class, transfer syntax, Number of Frames, Rows/Columns, Bits Stored, Pixel Representation, Photometric Interpretation, rescale/windowing.
2. Декодировать исходные 12/16-битные значения без промежуточного JPEG.
3. Приводить MONOCHROME1/2 к единой полярности.
4. Сохранять физический масштаб по Pixel Spacing; не растягивать изображение с изменением пропорций.
5. Формировать три канала из разных percentile windows: кость, мягкие ткани, глобальный диапазон.
6. Обрезать только пустые поля, сохраняя контекст анатомического охвата.
7. Производитель, модель и режим сканирования используются для domain-aware нормализации и анализа срезов, но не как короткий путь к целевой метке.
8. Проверять de-identification по DICOM PS3.15; отдельно обрабатывать burned-in annotations и private tags.

Браузерный прототип уже реализует пункты 1–4 для несжатых 8/16-битных grayscale-кадров и явно сообщает, когда pixel stream не поддерживается.

## 5. Архитектура модели

### Каскад

`DICOM validator → protocol router → anatomy segmentation/keypoints → geometry features → multi-label defect classifier → calibrated decision → explanation`

### Модель 1: protocol router

Маленькая модель определяет `spine`, `hip`, `unsupported`. Цель — почти нулевая ошибка маршрутизации. Неизвестный протокол отправляется на ручную проверку.

### Модель 2: анатомия

Один сильный encoder с двумя decoder/head-вариантами:

- segmentation: позвонки L1–L4, межпозвонковые пространства, таз, головка/шейка/диафиз бедра, мягкие ткани и ROI;
- keypoints: центры позвонков, ось позвоночника, ось диафиза, границы вертелов, точки привязки ROI.

Практичный старт: ConvNeXt V2 или EfficientNetV2 encoder + U-Net/FPN decoder. Сравнить с SegFormer. Выбор делается по OOF, latency и устойчивости по аппаратам, а не по ImageNet-рейтингу.

### Модель 3: дефекты

Multi-label head получает encoder features, predicted masks/keypoints и вычисленные геометрические признаки. Это позволяет отличить «наружную ротацию» от общего плохого качества и сформировать измеримое объяснение: угол оси, видимость малого вертела, полнота охвата, отклонение ROI.

### Ансамбль

- 5 fold-моделей одного лучшего семейства;
- максимум одна архитектурно отличная модель, если она даёт некоррелированные ошибки;
- усреднение calibrated logits;
- TTA только безопасные преобразования: небольшой scale/translation и мягкое изменение окна;
- горизонтальный flip запрещён, если он ломает laterality или геометрию разметки.

## 6. Loss и дисбаланс

- multi-label classification: asymmetric focal loss или class-balanced BCE;
- segmentation: Dice + BCE, для малых артефактов Tversky/Focal-Tversky;
- keypoints: heatmap focal loss + smooth L1 для координат;
- uncertainty weighting между задачами либо веса, подобранные по OOF;
- oversampling редких дефектов на уровне пациента;
- hard-negative mining после первого полного OOF;
- label smoothing только после проверки: он может ухудшить редкие классы и калибровку.

Аугментации не должны создавать анатомически невозможные примеры. Разрешены небольшие rotation/translation, экспозиция, шум, blur и симуляция экспортного сжатия. Elastic deformation, сильный perspective warp и случайное удаление ключевой анатомии запрещены.

## 7. Метрики

Официальная метрика конкурса имеет приоритет. Если она не опубликована, внутренний dashboard включает:

| Задача | Основная метрика | Дополнительные |
| --- | --- | --- |
| Итог `quality / review / violation` | macro F1 | balanced accuracy, confusion matrix |
| Типы нарушений | macro F1 по классам | per-class PR-AUC, sensitivity, specificity |
| Критические нарушения | sensitivity при заданной specificity | NPV, false negatives на 100 исследований |
| Сегментация | macro Dice | IoU, HD95, surface Dice |
| Keypoints | normalized mean error | PCK по физическому порогу |
| Калибровка | ECE и Brier score | reliability diagram |
| Отказ от ответа | risk–coverage curve | selective accuracy |

Нельзя писать «accuracy 98%» без prevalence, confidence interval и независимого holdout. Для каждой метрики публикуются bootstrap 95% CI на уровне пациента и срезы по протоколу, производителю, модели аппарата, клинике и классу нарушения.

### Подбор порогов

Пороги подбираются по OOF отдельно для каждого класса. Для критических ошибок вводится ограничение на минимальную sensitivity; внутри допустимой области максимизируется официальная метрика. После выбора применяется temperature scaling или isotonic calibration, затем пороги замораживаются.

Итоговое решение:

- `passed`: все обязательные классы ниже порога и uncertainty мала;
- `review`: пограничная вероятность, неизвестный domain, несогласие ансамбля или нераспознанный протокол;
- `rejected`: хотя бы одно критическое нарушение выше рабочего порога.

## 8. Цикл улучшения метрик

После каждого OOF строится единый error ledger:

1. false negative критических классов;
2. false positive, ведущие к ненужному повтору сканирования;
3. ошибки разметки экспертов;
4. domain shift по аппаратам/клиникам;
5. маленькая анатомия и артефакты;
6. низкое качество DICOM/экспорта;
7. случаи, где модели ансамбля не согласны.

Следующий эксперимент допускается только с одной проверяемой гипотезой и записью: commit, config, seed, folds, dataset version, OOF predictions, метрики и длительность. Публичный leaderboard не используется как validation set; отправки ограничиваются заранее выбранными кандидатами.

## 9. Конкурсная демонстрация

Сценарий на 90 секунд:

1. загрузить реальный обезличенный DICOM;
2. показать декодированное исходное 16-битное изображение и метаданные;
3. переключить AI overlay/original;
4. выбрать найденное нарушение и показать локализацию плюс измеримый признак;
5. показать `passed / review / rejected` и конкретное действие оператору;
6. открыть provenance: версия модели, критериев, uncertainty и privacy status;
7. открыть «Динамику»: показать baseline/current, LSC и автоматическую блокировку несопоставимого исследования;
8. выгрузить JSON-протокол;
9. показать dashboard независимой валидации с CI и срезами по аппаратам.

Сильный тезис продукта: модель не диагностирует остеопороз и не заменяет врача; она предотвращает технически некорректное исследование до того, как ошибка попадёт в заключение.

## 9.1. Анализ в динамике как конкурентное преимущество

Follow-up должен быть отдельным каскадом, а не вычитанием двух чисел:

`patient/region matching → quality gate каждого исследования → device/cross-calibration gate → ROI/positioning registration → ΔBMD → LSC decision → human confirmation`

Согласно [ISCD Official Adult Positions](https://iscd.org/official-positions-2023/), отчёт о динамике должен указывать предыдущее исследование и ROI, facility-specific LSC, абсолютное изменение в g/cm² и процент; изменение не следует сообщать как значимое, если оно не превышает LSC. Исследования разных аппаратов нельзя сравнивать количественно без cross-calibration.

Целевые метрики longitudinal-модуля:

| Подзадача | Метрика | Критерий готовности к пилоту |
| --- | --- | --- |
| Pair matching | patient/region pair accuracy | 100% на интеграционных тестах, иначе отказ |
| Сопоставимость | sensitivity критической несопоставимости | ≥ 0,98 с patient-level 95% CI |
| Registration ROI | landmark error / surface Dice | пороги задаются по экспертной воспроизводимости |
| Извлечение BMD | MAE и доля точного парсинга | отдельно по производителю/модели |
| Решение относительно LSC | agreement с экспертом | weighted kappa и confusion matrix |
| Итоговое действие | macro F1 + false-safe rate | приоритет минимизации ошибочного `comparable` |

Главная защита от красивой, но опасной функции: если аппарат изменился без доказанной cross-calibration, ROI расходятся или текущее исследование отклонено по качеству, продукт показывает `not-comparable`, а не «ухудшение».

## 10. Definition of done

### Для конкурсной подачи

- официальный labelbook подписан экспертами;
- 5-fold patient-grouped OOF воспроизводится одной командой;
- нет дублей между folds;
- зафиксированы per-class thresholds и calibration;
- есть независимый holdout и device-shift stress-test;
- UI принимает реальные DICOM, показывает реальный overlay и не выдумывает unsupported results;
- отчёт содержит model/data/criteria version и request ID;
- демонстрационный кейс воспроизводится без интернета;
- есть model card, data card, error analysis и latency benchmark.

### Для пилота в клинике

- server-side decoder поддерживает фактические transfer syntaxes заказчика;
- DICOM de-identification соответствует выбранному профилю PS3.15, проверены private tags и Pixel Data;
- PACS/RIS-интеграция протестирована на копии контура;
- врач подтверждает или исправляет результат, изменения аудируются;
- проведена независимая клиническая валидация;
- выполнены применимые регуляторные и ИБ-требования.

## 11. Критический путь после получения данных

| Срок | Результат |
| --- | --- |
| День 1 | schema audit, label prevalence, duplicate/UID audit, baseline split |
| День 2 | DICOM normalization, simple classifier baseline, OOF harness |
| День 3–4 | segmentation/keypoints baseline, labelbook corrections |
| День 5 | multi-task classifier, class imbalance, threshold optimization |
| День 6 | hard-negative mining, domain slices, calibration |
| День 7 | fold ensemble, safe TTA, frozen holdout evaluation |
| День 8 | inference packaging, real overlays in UI, JSON protocol |
| День 9 | ablation report, model/data cards, failure demo |
| День 10 | rehearsal, offline build, final reproducibility run |

Если конкурсная метрика, формат submission или датасет отличаются от предположений, первым изменяется evaluation harness и mapping labels, а не архитектура вслепую.
