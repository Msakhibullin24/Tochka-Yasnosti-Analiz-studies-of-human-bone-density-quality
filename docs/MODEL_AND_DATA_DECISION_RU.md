# Решение по модели и данным для хакатона

Дата: 17.09.2026. Это план экспериментов, а не заявление о достигнутом качестве. Фактический аудит файлов и первый CPU-результат: [проверенные данные](EXTERNAL_DATASETS_VERIFIED_RU.md). Общий протокол сдачи и оценки: [стратегия](COMPETITION_STRATEGY.md).

## Что выбираем

Основной путь — дообучение готового визуального encoder на целевых DXA с отдельными выходами для качества и конкретных нарушений. Анатомические ориентиры добавляем как проверяемое улучшение. Большой универсальный медицинский корпус и обучение foundation model с нуля сейчас не оправданы имеющейся разметкой.

Главное ограничение — не 14 МБ и не мощность ноутбука. Есть 100 исследований, 252 уникальных изображения, 249 итоговых оценок областей, но нет подтверждённой таблицы «изображение → область/сторона → строка Excel». Для отдельных критериев всего 3–6 положительных примеров. Дополнительного файла разметки от врача нет. Нельзя автоматически размножить оценку исследования на все его изображения.

Ramathibodi не даёт готового расширения бинарных конкурсных меток: часть значений 1 означает допустимые отклонения; порог наклона отличается от наших 5°. Есть нанесённые ROI, которых нет на просмотренных конкурсных GE-кадрах. Сначала проверяем геометрию масок и согласуем определения; затем отдельный эксперимент. Между Annotation/Verification есть повторы.

HipRay и MTDDH в FleXray — переупакованные исходные наборы, а не новые независимые исследования. Например, там заявлено 905 MTDDH-примеров: это не полный оригинальный MTDDH. Нельзя сложить оригинал и копию или поместить их по разные стороны train/test.

Для прямого улучшения QC наиболее ценное расширение — разрешённый экспорт взрослых DXA через клинику: реальные ошибки укладки, охвата, ротации, ROI и артефакты, плюс корректные случаи. Предложенный первый ориентир 500–1 500 исследований не является расчётом необходимого размера выборки. До получения такого экспорта работаем с текущими файлами; наличие врача не означает наличие нового корпуса.

## Готовые веса вместо обучения с нуля

1. **Основная компактная модель:** ImageNet ResNet18 как контроль, затем один кандидат ConvNeXt-Tiny. Начать с замороженных признаков, затем размораживать последний блок. Две семьи достаточно для первого сравнения.
2. **Альтернатива признакам:** [DINOv2 ViT-S/14](https://github.com/facebookresearch/dinov2), опубликованные веса Apache 2.0. Проверить замороженные признаки и небольшую обучаемую голову; не предполагать заранее преимущество над CNN. Это универсальные, а не медицинские DXA-веса.
3. **Анатомический эксперимент:** [FleXray](https://flexray.csail.mit.edu/index.html), модель сегментации обычного рентгена. Публичный API Hugging Face подтвердил safetensors, ONNX, схемы меток и preprocessing в `VictorButoi/flexray`, revision `b3d892015a51848f675739107f697c8e7ea709f4`. Лицензия весов — CC BY-NC 4.0. GitHub-ссылка авторов при прямой проверке API вернула 404. Веса здесь не загружены и не запускались. Пригодность для DXA не проверена; проверить условия конкурсного использования перед включением в поставку.
4. **Не делать зависимостью:** [LeDXA](https://arxiv.org/abs/2608.02208) — интересная работа по представлениям whole-body DXA, но в этой проверке доступный checkpoint не установлен. XRay-DINO также требует отдельного доступа к весам и имеет специальную некоммерческую лицензию, отличную от обычного DINOv2.

Метрики FleXray на рентгене и LeDXA на рисках заболеваний не являются ожидаемой точностью нашего контроля качества. Их роль — проверяемая гипотеза переноса.

## Предлагаемая схема модели

```text
DICOM → декодирование и сохранение исходной геометрии
      → область: позвоночник / бедро / неподдерживаемое
      → общий encoder + головы по области
           ├─ вероятность общего нарушения
           ├─ вероятности отдельных нарушений, с маской неизвестных меток
           └─ опционально: ориентиры / анатомические маски
      → калибровка и пороги → обязательный CSV + обоснование результата
```

Сторону бедра сохраняем отдельно от общего класса hip. Если исходные метаданные/маркеры не позволяют установить сторону, модель не должна выдавать её как доказанный факт. Нужны подтверждённые примеры или явная неопределённость.

Общий класс обучаем по итоговой оценке области; нарушения — по отдельным полям Excel. Пропуски не превращаем в нули. Из-за найденных противоречий общий выход не следует жёстко определять как OR необработанных меток нарушений. Для спорных строк сохраняем исходную оценку и причину исключения из соответствующей функции потерь.

Анатомическая ветвь должна объяснять измеримое: ось относительно вертикали, присутствие нужных ориентиров, положение границ. Cobb angle и наклон оси укладки — разные величины. Из отсутствующей метки малого вертела нельзя безусловно заключать неправильную ротацию. Размеры в сантиметрах не выдаём из пикселей без достоверного масштаба: PixelSpacing в текущем наборе отсутствует.

На входе сохраняем весь кадр и пропорции. Эксперимент с увеличенным размером входа возможен, но увеличение PNG не создаёт новые анатомические детали. Не применять случайные обрезки, выравнивание позвоночника или повороты с прежними QC-метками: они могут создать или устранить целевую ошибку. Зеркальное отражение требует корректного преобразования стороны и аннотаций. Синтетические нарушения — отдельный обучающий эксперимент, не независимый тест; артефакты генерации могут стать ложной подсказкой.

## Минимум аннотаций, который даст пользу

Полные маски для всех кадров на первом шаге не обязательны. Первый проход — область и сторона 252 кадров с явным `unknown`, где доказательств нет; затем связь с исходной оценкой Excel. Второй — пять уже найденных спорных строк и кандидаты близких исследований. Третий — ориентиры только для выбранного анатомического эксперимента и пересмотр ошибок на обучающей части.

Если дополнительной экспертной разметки совсем не будет, доступны frozen-feature и слабоконтролируемые модели уровня исследования. Выполненный CPU-baseline именно такой: ROC-AUC 0,5944, F1 0,5294. Он не решает требуемую классификацию каждого изображения. Автоматические предположения о привязке допустимы как черновик, но не как подтверждённая разметка для оценки качества.

## Порядок экспериментов и критерии решения

| Шаг | Сравнение | Что должно решить продолжение |
|---|---|---|
| A | Проверенная привязка + frozen ResNet18 против константы | Есть ли сигнал на уровне изображения; показатели по областям |
| B | Частичное дообучение CNN против A | Прирост на тех же группах; отсутствие провала редких областей |
| C | DINOv2-признаки против лучшего CNN | Даёт ли другая предобученная модель полезный независимый сигнал |
| D | Целевые данные против добавления каждого внешнего источника по отдельности | Парное изменение метрик на целевых GE DXA; внешний размер не является критерием успеха |
| E | Лучшая модель против неё же с анатомическими признаками | Улучшается ли QC, а не только красивый overlay |
| F | Одна модель против среднего двух дополняющих моделей | Повторяемый выигрыш без ухудшения времени и покрытия |

Порог и калибровку выбирать внутри обучающей части; внешние группы не использовать для ранней остановки. Текущие 36 похожих пар — кандидаты, а не доказанные повторы пациентов: их консервативное объединение уже дало очень неравномерные фолды. Проверка этих связей полезнее расширения поиска до десятков архитектур. Для редких меток адаптировать число фолдов; AUC без двух классов не определена.

Сначала ограниченный поиск параметров, затем проверка выбранных вариантов с несколькими seed. Хранить все OOF-вероятности, конфигурации, версии весов/данных и отрицательные эксперименты. Сравнивать F1 и ROC-AUC вместе, отдельно показывать sensitivity, specificity, число ошибок и интервалы по группам. Повторный выбор по CV не превращает её в независимую клиническую валидацию.

На ноутбуке: аудит, подготовка разметки, линейные головы, проверка инференса. На 5090: дообучение, маски, повторные эксперименты. До проверки самой GPU-машины не обещать время обучения.

## Как превратить модель в сильную конкурсную поставку

Обязательная ценность: все входные файлы обработаны; точный формат результата; явный Failure для технической ошибки; локальные веса; запуск без интернета; лимит 180 секунд на исследование; воспроизводимый контейнер. Интерфейс показывает конкретный обнаруженный признак и вероятность. Grad-CAM можно обозначить как карту внимания модели, но не как доказательство клинической причины.

Пакет защиты: одинаковые группы для сравнений, таблица абляций A–F, примеры ошибок, версии данных и весов, измерение полного времени и демонстрация на заранее отложенных случаях. Финальную модель выбираем по этим результатам. Сейчас данных, чтобы честно назвать какую-либо архитектуру лучшей, нет.

## Проверка новых источников

Метаданные прямого API и лицензии сохранены локально в `data/external/source-metadata/`. Для FleXray-data зафиксирован revision `6219d411cc3f10572182f37668d87c531f0974f5`; лицензии различаются по папкам. Большая синтетическая FluXray-часть не выбрана для массового скачивания: это обычный рентген с иной задачей, а польза на наших DXA пока не показана.

Дополнительно проверена [работа 2026 года об автоматическом QC рентгена позвоночника](https://pmc.ncbi.nlm.nih.gov/articles/PMC13361558/): данные предоставляются авторами по запросу, открытого скачиваемого корпуса статья не даёт. Письма и заявки от имени пользователя не отправлялись.
